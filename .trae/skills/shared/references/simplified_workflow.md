## 7. 简化执行流程（Skill 创建/修改轻量化模式）

> **适用场景**：日常新建或修改单一 Skill 时，作为完整六阶段流程的轻量化替代方案。不修改 Skill 本身的研发流程，而是为「Skill 这个产物本身的创建/修改」提供快速通道。

### 7.1 流程定位

完整六阶段流程（需求→架构→开发→测试→投产→归档）适用于正式软件项目交付。当目标产物是 Skill 本身（SKILL.md 文件）时，可使用本简化流程，将原 ~8h 全流程压缩至 ~50min。

### 7.2 五步流程

| 步骤 | 名称 | 耗时 | 目标 | 替代的完整流程环节 |
|------|------|------|------|-------------------|
| 1 | 需求定义 | ~10min | 1 段需求描述（3-5 句话）明确 Skill 要做什么、何时触发、边界在哪 | 需求收集→七维分析→IEEE 830 SRS→需求评审（原 4 环节，7 个 Excel） |
| 2 | SKILL.md 编写 | ~20min | frontmatter（name+description）+ 正文（适用场景、核心模块、使用流程、输出规范） | 架构设计 6 环节 + 开发编码 |
| 3 | 结构校验 | ~5min | 3 项检查：frontmatter 格式 / 内容完整性 / 无重复定义 | 315 单元测试 + 9 门禁 |
| 4 | 功能验证 | ~10min | 触发测试：匹配提问能加载 + 无关提问不误触发 | 203 用例 + 521 次执行 |
| 5 | 打包发布 | ~5min | 每个 Skill 单独 zip（内含 SKILL.md） | Go-Live 评审 + 金丝雀发布 |

### 7.3 可完全裁剪项

以下完整流程环节在简化模式下可完全裁剪：4+1视图、C4模型、ADR、ATAM、Go-Live评审、金丝雀发布、DORA指标、Excel台账、跨会话交接。

### 7.4 混合策略

推荐「简化流程快速迭代 → Skill 稳定后补充安全扫描等关键检查 → 无需从头走完整六阶段」。即：先用简化流程快速产出可用的 SKILL.md，在迭代稳定后按需补充安全扫描、质量门禁等关键检查项，但不强制走完整六阶段流程。

### 7.5 三项结构校验细则

| 校验项 | 检查内容 | 通过标准 |
|--------|---------|---------|
| frontmatter 格式 | `---` 包裹、含 name 和 description 字段 | 格式正确，字段无缺失 |
| 内容完整性 | 适用场景、核心模块、使用流程、输出规范四个部分 | 四部分均有内容 |
| 无重复定义 | 文件内无重复的章节或模块定义 | 无重复 |

### 7.6 功能验证方法

| 测试类型 | 方法 | 通过标准 |
|---------|------|---------|
| 正向触发 | 用与 Skill description 匹配的提问测试 | Skill 正确加载并响应 |
| 反向触发 | 用与 Skill 无关的提问测试 | Skill 不误触发 |
| 边界触发 | 用近似但不在范围内的提问测试 | Skill 不误触发 |
