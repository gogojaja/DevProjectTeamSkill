## 0. 铁律锚点（每轮回显三词）

```
铁律锚点：授权 → 备份 → 留痕
```

## 1. 系统/项目外文件铁律（最高优先，不可压缩忽略）

修改、删除**系统文件（%windir%\System32、hosts、注册表等）或项目外部文件（仓库之外路径）**必须三条件齐备，否则禁止执行：

1. **①先获用户明确授权**（`user_confirm=同意`）；
2. **②操作前强制备份**到项目内 `.backup/`（含时间戳）；
3. **③操作留痕**至 `13_安全审计台账.csv`。

> 必须经 `security_audit` 前置审计；未授权/未备份=违规高危操作，立即阻断。
> **操作前自问**：目标在仓库外吗？是系统路径吗？未授权则停，先问用户。

## 2. 项目内文件保护

- 无用户明确指令**禁止删除/移动/重命名**项目内文件；
- 高危操作（改入口脚本/删移文件/配置变更）转发总控安全审计。

## 3. 密钥/敏感信息

- **密钥、账号、Token 禁止入库**（仓库内只留占位符/别名，真实值经 `.secrets/` + 凭据管理器）；
- 历史中若发现已提交密钥，立即轮换并清理。

## 4. 输出与格式

- 禁止产生 `.xlsx`（全库 CSV UTF-8 with BOM，token_standard §3）；
- 大输出转 CSV，仅回显首 5 行 + 行数。

## 5. 源码单源 / 不覆盖

- `.trae/skills/` 是唯一事实来源；deploy/solidify 不覆盖源码；shared 单源不手工复制。

## 6. 上下文压缩流程（触发即执行）

1. 压缩（compaction）后，**第一步重新 Read 本文件**，作为新上下文的铁律锚点；
2. 压缩前将未固化的护栏产出先 `solidify.sh` 固化 + git commit；
3. 每轮对话末尾回显锚点 `授权→备份→留痕`。
