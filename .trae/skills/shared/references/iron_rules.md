## 0. 铁律锚点（每轮回显三词）

```
铁律锚点：授权 → 备份 → 留痕
```

## 1. 系统/项目外文件铁律（最高优先，不可压缩忽略）

修改、删除**系统文件（%windir%\System32、hosts、注册表等）或项目外部文件（仓库之外路径，含其他项目目录）**必须三条件齐备，否则禁止执行：

1. **①先获用户明确授权**（`user_confirm=同意`）；
2. **②操作前强制备份**到项目内 `.backup/`（含时间戳）；
3. **③操作留痕**至 `13_安全审计台账.csv`。

> 必须经 `security_audit` 前置审计；未授权/未备份=违规高危操作，立即阻断。
> **操作前自问**：目标在仓库外吗？是系统路径吗？是其他项目目录吗？未授权则停，先问用户。

## 1a. 目录访问边界铁律（项目初始化强制）

- **默认边界**：本项目可读写/删除范围 = **本项目所在目录（含子目录）**，项目启动时经 `declare_access_boundary` 声明写入 `台账/26_访问边界.csv`（role-project-init）；
- **本项目目录之外的任何访问**（其他项目目录、系统文件、仓库外路径）一律经 `register_auth` 授权登记（`台账/14_授权登记.csv`），**未填有效期默认仅本次对话有效**，会话结束自动失效；跨会话须用户显式指定到期时间并留痕；
- 操作目标在本项目目录外 → 先查 `26_访问边界.csv` + `14_授权登记.csv`，无授权禁止读写/删除；授权未登记视为未授权。

## 2. 项目内文件保护

- 无用户明确指令**禁止删除/移动/重命名**项目内文件；
- 高危操作（改入口脚本/删移文件/配置变更）转发总控安全审计。

## 3. 敏感信息分级处理矩阵（统一管理）

> **优先级声明**：§3.2「泄密文件禁令」为**最高级别要求**，**凌驾于下表 A/B/C 三级判定**，也**不因仓库私有而豁免**。命中即禁入库，无需再问“属哪级”。

敏感信息按「处置方式」分三级统一管理，**提交公共仓库前一律自问"这条数据属于哪级"**：

| 级别 | 保护对象 | 处置方式 | 代表场景 |
|------|---------|---------|---------|
| **A 级：禁止入库** | 密钥、凭据、Token、密码 | 仓库内只存别名/占位符，真实值经 `.secrets/` + 凭据管理器；历史泄露立即轮换 | 连接串密码、API Key、证书 |
| **B 级：脱敏入库** | 本机/环境专属信息（主机名/IP/用户名/绝对路径） | 提交前按 §3.1 强制脱敏后入库 | CMDB 快照、运维手册、连接串示例 |
| **C 级：可入库** | 脱敏后数据、非敏感配置、公共知识 | 正常提交 | 无真实值的模板、通用示例 |

### 3.1 B 级脱敏细则（提交公共仓库前强制）

**本机/环境专属信息（主机名、IP、用户名、环境路径等）在提交 GitHub 等公共仓库前必须脱敏**，否则禁止入库：

| 信息类型 | 脱敏规则 | 示例 |
|---------|---------|------|
| 主机名 | 可保留或匿名（按用户授权决定） | `Douglas` / `dev-host-01` |
| IP 地址 | **完全脱敏**或保留 C 段网段隐藏主机号（按用户授权决定） | `192.168.0.211` → `xxx.xxx.xxx.xxx` / `192.168.0.x` |
| 用户名 | 匿名化或保留（按用户授权决定） | `gogojaja` |
| 内网网段/域名 | 一律隐藏 | `10.x.x.x` → `xxx.xxx.xxx.xxx` |
| 环境变量路径 | 相对化或替换占位符 | `C:\Users\gogoj\...` → `%USERPROFILE%\...` |

**执行流程**：
1. 提交前识别文件中是否含本机/环境专属信息（主机名/IP/用户名/绝对路径）；
2. 按上表脱敏（**IP 完全脱敏为默认**，保留主机名须用户授权）；
3. 脱敏后复查全文确认无真实值残留；
4. 敏感度不确定时，先问用户授权再提交。

> 应用场景：CMDB 快照（`cmdb_export.csv`）、运维手册、连接串示例、日志、快照文件等一切会随仓库暴露的文件。
> 该脱敏不替代 A 级处理（§3），A 级真实值仍走 `.secrets/` + 凭据管理器。

### 3.2 泄密文件禁令（最高级别，凌驾于 A/B/C 分级）

**凡内容一旦入库即可能导致泄密的文件，一律禁止进入版本库。此为最高级别要求，不论仓库公开或私有、不论远端是否内网。**

#### 3.2.1 适用对象（含但不限于）

| 类别 | 典型形式 | 泄密机理 |
|------|---------|---------|
| **反向映射 / 对照表** | 脱敏执行记录、术语替换表、遗留清单、原名↔代号映射 | **可反向破解仓库内全部脱敏成果**，是风险最高的文件类型 |
| 未脱敏原件 | 甲方原始文档、真实客户/项目名称、生产数据导出 | 直接暴露真实主体与业务数据 |
| 凭据载体 | 私钥、令牌、含密码的配置/脚本、`.secrets/` 下任何文件 | 直接失窃 |
| 环境情报集 | 含真实 IP/主机名/账号的拓扑图、CMDB 全量导出、堡垒机清单 | 汇总后可定位并突破内网 |
| 人员隐私 | 含身份证号/手机号/家庭住址的名单、审批附件 | 个人信息保护义务 |

#### 3.2.2 强制动作

1. **硬约束而非口头不提交**：必须写入 `.gitignore` 并用 `git check-ignore -v <路径>` 实测命中。仅“没暂存”不算合规——下次 `git add -A` 会重新卷入。
2. **提交前拦截**：暂存后必须回看新增/变更集里是否存在 3.2.1 类文件；命中则整批退回，不得拆单“先提其他”。
3. **已入库必须抹历史**：若已随提交推送，**追加一个“删除提交”不算完成整改**——旧提交仍可用 `git show <sha>:<路径>` 原样取出。必须改写含该文件的提交并 `push --force` 到所有远端（强推前先经用户确认）。
4. **提示用户另存**：排除或从历史抹除前，**必须主动提示用户将该文件内容手动保存到仓库之外**（本地加密盘、密码管理器、离线介质等），并待用户确认后再执行排除，避免清理时连同唯一副本一起丢失。
5. **不得降级处理**：禁止以“脱敏后入库”“只放代号”等方式变通收录反向映射表——其价值就在映射关系本身，脱敏即失效。

#### 3.2.3 与私有仓库例外的关系

部分项目（如 TwinForge）在其 `AGENTS.md` 声明"私有仓库可直接管理本地 IP/凭据，无需脱敏"。该例外**仅适用于 B 级环境信息**，**不覆盖本节**：反向映射表、凭据、未脱敏原件、人员隐私在任何仓库中均禁止入库。

#### 3.2.7 脱敏映射安全存储（推荐实践）

> **脱敏映射文件必须存储在仓库之外，打包为 AES-256 加密 ZIP，会话时由用户临时提供密码解锁，会话结束后自动清除。**

**强制要求**：

1. **仓库外存储**：映射文件存放在 `D:\MyProjects\.secrets\` 或项目级 `.secrets\`，禁止写入仓库内任何位置
2. **加密保护**：打包为 AES-256 加密 ZIP，密码由用户单独管理（推荐密码管理器）
3. **会话加载**：会话开始时用户输入密码加载，禁止将密码写入任何文件
4. **自动清除**：会话结束时临时文件自动删除（`secure_mapping_loader.py --unload`）
5. **零入库**：禁止将映射文件（含解密后的临时文件）写入仓库内

**推荐实践**：

- 每季度执行 `--rotate` 轮换映射规则（生成新的随机替换值）
- 轮换后更新加密 ZIP 包以持久化新映射
- 密码使用密码管理器存储（Bitwarden/1Password 等）
- 定期备份加密 ZIP（密码丢失则映射永久丢失）

**工具支持**：

- `tools/desensitize/secure_mapping_loader.py`：安全映射加载器
- `D:\MyProjects\.secrets\README.md`：详细使用指南
- 命令：`--load`（加载）/ `--unload`（卸载）/ `--status`（状态）/ `--rotate`（轮换）

#### 3.2.8 AI 自动检测承诺（强制行为）

> **AI 在帮助用户创建、编辑、处理文件时，必须自动执行敏感信息检测，发现敏感信息时立即提示并阻止直接保存。**

**AI 强制行为**：

1. **创建/编辑前扫描**：每次帮用户创建或编辑文件前，先对内容执行敏感信息扫描
2. **发现即提示**：检测到敏感信息时，立即列出所有命中项，说明类型和敏感级别
3. **建议脱敏方案**：针对每个敏感项提供脱敏建议（替换/删除/外部存储）
4. **拒绝直接保存**：未经用户确认脱敏方案前，拒绝将含敏感信息的文件写入仓库
5. **提醒外部存储**：提示用户将敏感信息保存到仓库外（如 `.secrets/` 或密码管理器）

**检测范围**：

- **A 级（禁止入库）**：密钥、密码、Token、私钥、连接串密码
- **B 级（需脱敏）**：IP 地址、主机名、用户名、绝对路径、邮箱、手机号
- **C 级（可入库）**：已脱敏数据、通用配置
- **反向映射表**：任何包含「原始词→替换值」映射关系的文件

**工作流示例**：

```
用户：帮我创建配置文件，包含数据库连接信息

AI：⚠️ 检测到敏感信息：
  - 数据库密码: "MySecretPassword123" (A 级)
  - 内网 IP: "192.168.1.100" (B 级)

建议：
1. 密码应存储在 .secrets/ 或密码管理器，配置文件仅存引用
2. IP 应脱敏为 xxx.xxx.xxx.xxx

是否按建议脱敏后保存？[Y/N]
```

**与现有机制的关系**：

- 本条款补充 pre-commit hook（第二道防线），在文件创建阶段即拦截
- 与 §3.2.2「提交前拦截」形成双重保障
- 不替代人工复核（第三道防线），而是提前预警

## 6. 平台兼容铁律（双平台强制，不可压缩忽略）

本技能库所有启用项目**必须同时支持 Windows 与 macOS 双平台**：

1. **路径**：禁止硬编码单一平台绝对路径（`C:\...`、`D:\trae\...`、`/Users/...`、`/Volumes/...`）；脚本/配置统一用相对路径或平台自适应（Python `os.path`/`pathlib`、bash `$HOME`/`%USERPROFILE%`）；
2. **命令**：禁止依赖 Windows 专属命令（`py -3.11` 等）或 macOS 专属假设；Python 用 `sys.executable` 跨平台调用子脚本；
3. **行尾**：文本文件统一 LF（配 `.gitattributes`），防 Windows 检出 CRLF 导致反复 diff；
4. **文档**：涉及路径/命令时同时标注双平台写法（如 `~/.config/opencode/skills` vs `%USERPROFILE%\.config\opencode\skills`）。

> 细则见 `../references/token_standard.md` §6。

1. 压缩（compaction）后，**第一步重新 Read 本文件**，作为新上下文的铁律锚点；
2. 压缩前将未固化的护栏产出先 `solidify.sh` 固化 + git commit；
3. 每轮对话末尾回显锚点 `授权→备份→留痕`。

## 8. 语言铁律（全程中文，不可压缩忽略）

- **全程中文交流**：所有项目（含本技能库维护）的**对话、产出文档、台账、报告、提交说明、面向用户的回复一律使用中文**；
- 代码标识符可保留英文（行业惯例），但注释、提交信息、文档、说明性文字必须用中文；
- 不主动切换其他语言，除非用户明确要求。

## 9. 产物落盘铁律（禁入系统盘 / C 盘，不可压缩忽略）

- **产物必落项目目录**：所有任务生成的产物（文档/报告/台账/脚本/导出文件/快照/构建物等）必须写入**本项目目录内**（含其新建子目录），不得落于项目目录之外；
- **禁止写入系统盘 / C 盘**：生成的文件**严禁写入系统盘或 C 盘**等非项目路径（如 `C:\Users\...`、`C:\Windows\...`、桌面、下载目录、其他项目目录等）；
- **新建目录限制**：确需新建目录存放产物时，只能建在**本项目目录内**；禁止在项目目录外（尤其系统盘/C 盘）新建任何目录；新建前须用户明确确认；
- **与访问边界同源**：本律与 §1a 目录访问边界铁律一致——项目外路径一律经 `register_auth` 授权，未授权禁止写入；违反即阻断；
- **例外（元操作）**：本技能库本体生产发布（`publish_production` 写全局库 `~/.config/opencode/skills`）属维护元操作，按 AGENTS.md 固化/发布门禁执行，不受本律限制；项目初始化时须将本律写入目标项目的「项目铁律」。

## 10. 角色加载铁律（不可压缩忽略）

> **核心原则：每一个任务都必须在角色上下文中执行。没有“无角色”工作状态。**

- 接收到任何任务时，系统自动判断任务性质，加载对应角色包，按角色规范执行；
- **角色加载是系统的责任，不是用户的责任**——用户只描述任务，不需要说触发词；
- 禁止在未加载角色的情况下执行任何专业领域工作；
- 角色包内的铁律仅对该角色生效，不跨角色强制；
- 多角色任务：按子任务独立路由，分别加载对应角色。

**角色分配映射（任务性质 → 角色）：**

| 任务性质 | 角色 |
