# Skill Maintenance SOP（技能维护标准操作程序）

> 适用范围：所有新建、扩展、修订 SKILL.md 的维护活动。
> 目标：将维护产出从“描述型流程”提升为“闭环执行型技能”，并强制通过门禁后才允许打包、部署和固化。

## 1. 维护目标

维护产出的技能必须满足以下条件：
- 具备明确任务入口；
- 具备执行状态和动作层；
- 具备验收门禁；
- 具备失败恢复机制；
- 具备交接与审计链；
- 能证明该技能可执行、可验证、可恢复与可交接。

> 任何只包含角色职责、流程建议、经验总结的技能，不视为合格维护产出。

## 2. 强制输入清单

维护工作前，必须确认：
- 需求背景；
- 触发场景；
- 前置条件；
- 输出目标；
- 关键依赖；
- 本地工具/脚本；
- 交接对象。

## 3. 强制模板

所有维护产出必须引入并遵循：
- `../shared/closure_execution_template.md`

正文中必须存在：
- `## 闭环执行系统`
- `### 1. 任务入口`
- `### 2. 执行状态`
- `### 3. 执行动作层`
- `### 4. 验收门禁`
- `### 5. 失败处理`
- `### 6. 产出与交接`
- `### 7. 审计记录`

## 4. 维护流程

### Step 1：需求定义
- 明确触发词与场景；
- 明确输入与输出；
- 明确不适用场景；
- 明确前置条件与角色状态。

### Step 2：能力建模
- 建立状态机；
- 确认关键动作；
- 定义失败恢复方式；
- 确认验收门禁与审计证据。

### Step 3：SKILL.md 编写
- 保持 frontmatter 合法；
- description 中含 `Load when`；
- 保留 `技能版本`、`**文档版本**`、`**最后更新**`；
- 统一插入闭环执行系统章节。

### Step 4：结构校验
- 检查目录与名称一致；
- 检查输出是否符合 token 标准；
- 检查引用路径是否有效；
- 检查 `闭环执行系统` 是否完整。

### Step 5：功能验证
- 执行 `tools/check_skill_closure.py`；
- 执行 `tools/check_skill_release_gate.py`；
- 执行 `tools/check_version_consistency.py`；
- 若失败，必须修正后再继续。

### Step 6：发布前门禁
- 通过全部门禁后，才允许：
  - `tools/package_skills.sh`
  - `tools/deploy_skills.py`
  - `tools/solidify.sh`

## 5. 门禁规则

以下门禁必须强制通过：
1. `tools/check_skill_release_gate.py`
2. `tools/check_skill_closure.py`
3. `tools/check_version_consistency.py`

任何一个失败都阻止发布和固化。

## 6. 产出物要求

维护完成后的产出物必须落盘于：
- `.trae/skills/<包名>/`

临时物必须归档到：
- `backup/tmp_migrations/`
- `_pkg_tmp/`
- `dist/`

严禁将临时草稿直接留在系统或项目外目录。

## 7. 归档与交接

维护结束后：
- 更新交接文档断点区；
- 固化快照；
- 保留审计证据；
- 交接给下一阶段负责人或维护人。

## 8. 禁止事项

- 跳过结构校验直接发布；
- 仅写最优实践、不写闭环系统；
- 只写角色职责、不写执行状态与门禁；
- 把中间草稿留在系统目录或项目外路径；
- 绕过 publish/release gate 直接打包部署。
