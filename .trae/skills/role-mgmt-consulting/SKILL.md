## 2. 触发规则

用户表达「项目管理咨询/PMO 咨询/成熟度评估/差距分析/方法论定制/变革管理/咨询建议书/PMO 蓝图/教练辅导」时加载本包。单角色场景直接 Read 本文件；需要台账时调用 `../shared/governance.md`；明细按需 Read `domain/consulting-lifecycle.md` 与 `domain/consulting-lifecycle__resources/`。

## 3. 流程（路由到 domain/）

| 环节 | 动作 | 明细 |
|------|------|------|
| 商机评估与投标 | assess_opportunity（机会评估/竞标建议/投标策略）＋ draft_proposal（建议书/SOW/交付物/里程碑/报价） | `domain/consulting-lifecycle.md` |
| 现状诊断 | diagnose_as_is（现状采集/痛点识别）＋ assess_maturity（成熟度评估：CMMI/P3M3/OPM3 裁剪模型）＋ analyze_gap（差距分析/对标/根因） | `domain/consulting-lifecycle.md` |
| 方案设计 | design_solution（To-Be 蓝图/PMO 设计/治理模型/方法论定制/绩效体系） | `domain/consulting-lifecycle.md` |
| 实施与变革 | drive_change（Kotter 8 步/ADKAR/干系人管理/试点推广/教练辅导）＋ coach_org（能力建设/培训/辅导） | `domain/consulting-lifecycle.md` |
| 成效评估 | measure_value（价值实现测量/结项评估）＋ asset_knowledge（知识资产沉淀/案例库/IP 复用） | `domain/consulting-lifecycle.md` |

> **定位铁律**：本包为「二级方法工程/诊断」能力，独立于 SDLC 一级执行路由；诊断与方案设计只提供建议，落地执行由客户组织或本库执行角色承接，咨询师不代行客户方决策。
> **保密铁律**：咨询接触的客户组织信息（组织名/人名/财务数据/流程细节）一律按 `../references/iron_rules.md` §3 A/B 级处理，台账只存脱敏别名，真实信息走 `.secrets/`+凭据管理器，未经授权禁止入库。
> **成熟度模型**：自建 5 维评估框架（治理/流程/组织/度量/工具，0~5 级）对齐 P3M3/CMMI 裁剪，评分细则见 `domain/consulting-lifecycle.md` §2 与 `domain/consulting-lifecycle__resources/maturity_model.md`。

## 4. 输出规范与边界

- 台账经 `../shared/governance.md` 路由写入（33~37 CSV，禁止 .xlsx）；
- 输出表格按 token_standard §3 阈值（Markdown/CSV）；
- 评估报告/建议书/蓝图等文档类交付物落 `咨询资产/` 目录（`../references/directory_structure.md`）；
- 边界：仅负责「评估/诊断/方案/变革/成效」咨询侧；不替代客户方项目/项目群/组合治理决策；不承载投资决策；组合治理投资判断不属本包。

## 闭环执行系统

### 1. 任务入口
- 输入：用户要求开展项目管理咨询（商机评估/投标、现状诊断、成熟度评估、差距分析、方案设计、变革实施、成效评估）；
- 前置：需确认咨询对象（客户组织背景）、维护范围（`maintenance_scope`）、客户数据授权与脱敏等级；
- 不适用：仅讨论咨询概念未绑定具体咨询对象、或咨询对象信息不足时不应直接执行。

### 2. 执行状态
| 状态 | 进入条件 | 退出条件 | 处理方式 |
|------|---------|---------|---------|
| 待启动 | 咨询需求明确且授权已登记 | 用户确认/系统启动 | 读取商机/客户台账与授权记录 |
| 执行中 | 咨询环节已加载 | 环节产出形成或失败 | 按 5 环节流程推进 |
| 校验中 | 关键产出完成 | 验收通过/失败 | 检查评估报告/门禁/脱敏复核 |
| 阻塞 | 客户数据缺失/授权不足/信息不足 | 补充信息/人工处理 | 暂停推进并记录阻塞原因 |
| 完成 | 验收通过 | 进入知识资产沉淀 | 归档证据并更新商机/客户台账 |
| 回退 | 执行失败/门禁未过/保密违规 | 回到最近稳定状态 | 触发回滚、恢复上下文、保留审计 |

### 3. 执行动作层
- 执行步骤 1：读取商机/客户台账（33/34）与授权登记，确认咨询对象与脱敏等级；
- 执行步骤 2：按 5 环节顺序执行（评估→诊断→方案→变革→成效），每环节产出经用户确认后进入下一环节；
- 执行步骤 3：成效评估 + 知识资产沉淀，更新 33~37 台账，脱敏复核后固化；
- 所需工具/脚本：总控台账、`../references/consulting_standards.md`、`../shared/governance.md`；
- 输入输出约束：输出必须落盘到 `台账/`（33~37 CSV）与 `咨询资产/`（文档交付物），不能跳过授权登记与保密门禁。

### 4. 验收门禁
- 必须产出物：商机评估、建议书、成熟度评估报告、差距矩阵、方案设计蓝图、变革计划、成效评估、知识资产记录；
- 通过条件：每环节产出经用户确认、脱敏复核通过（B 级脱敏/A 级禁止入库）、台账更新完整；
- 失败条件：客户数据未脱敏、授权缺失、评估无证据支撑、方案未定稿、变革计划缺责任人；
- 审核对象：咨询负责人（Consulting Lead）+ 客户方联系人（变更/变革涉及）+ 用户确认。

### 5. 失败处理
- 失败类型：客户数据缺失、授权不足、评估证据不足、方案被拒、变革受阻、保密违规；
- 恢复策略：回到对应环节补充信息后重审，不需从头重跑；
- 回滚方案：撤销受影响草稿，保留上一可用咨询状态；
- 重试策略：在数据/授权/证据补充后再重试；
- 是否需要人工确认：涉及客户数据使用、变革决策、外部信息访问必须人工确认。

### 6. 产出与交接
- 产出物列表：成熟度评估报告、差距矩阵、咨询建议书、PMO 蓝图、变革路线图、成效评估报告、知识资产记录；
- 保存路径：`台账/33_商机管道.csv`、`34_客户登记.csv`、`35_建议书版本.csv`、`36_成熟度基线.csv`、`37_变革计划.csv`、`咨询资产/`；
- 交接对象：客户组织执行团队、role-governance 总控（如承接落地项目）；
- 下一步动作：根据评估结果选择进入落地项目（交接 role-project-init/role-governance）或知识资产沉淀；
- 归档条件：成效评估通过、知识资产记录完成、脱敏复核通过。

### 7. 审计记录
- 执行时间：咨询动作开始/结束时间；
- 关键参数：咨询对象、环节、版本、脱敏等级；
- 关键决策：成熟度评分、方案采纳/拒绝、变革范围调整；
- 结果证据：33~37 CSV、咨询资产文档、评审记录、脱敏复核记录；
- 失败原因：在 `台账/13_安全审计台账.csv` 或交接文档中留痕。
