# 公共标准规范（Common Standards）

> 全技能体系共享的标准规范，各依赖技能直接引用本文件，避免重复定义（Token 优化方案 B）。
> 本文件承载**版本管理规范**与**技能库版本快照规范**两大通用标准；各技能的标准化输出结构、action 清单等特有内容保留在各技能内。

---

## 1. 技能版本管理规范

### 1.1 技能版本与项目版本分离

- **技能版本号**：独立于项目基线版本，采用语义化版本 `主版本号.次版本号.修订号`（如 v1.0.0）；
- **项目基线版本号**：项目各阶段固化后的版本号，如 v1.0（需求基线）、v2.0（架构基线）、v3.0（开发基线）；
- 两者完全独立，技能升级不影响项目数据，项目变更不触发技能版本变化。

### 1.2 技能版本升级触发条件

| 升级类型 | 触发条件 | 版本号变化 |
|----------|----------|------------|
| 主版本升级 | 新增核心子模块、架构级重构、新增独立技能 | vX.0.0 |
| 次版本升级 | 新增 action、新增台账 Sheet、优化核心流程 | vX.Y.0 |
| 修订升级 | Bug 修复、规则微调、文档完善 | vX.Y.Z |

### 1.3 技能升级评审机制

每次技能修改/升级后，必须执行技能评审流程，评审角色自动匹配规则与 DevProjectTeamSkill §2.4 一致：

1. **评审内容**：功能完整性、规则一致性、边界清晰度、与其他技能协同性、知识产权合规性；
2. **评审输出**：技能评审报告 Excel（评审摘要、问题清单、整改建议、评审结论）；
3. **评审通过后**：更新技能版本号、更新《技能说明文档》和《技能操作手册》、写入技能版本变更记录；
4. **评审角色自动匹配**：按 DevProjectTeamSkill §2.4 角色匹配规则自动判断（涉及流程变更→对应角色+文档管理员联合评审；全技能重构/主版本升级→全部角色联合评审）。

### 1.4 版本变更记录格式与单源同步（防版本漂移）

每个 SKILL.md 文件顶部（基础元数据）统一包含：

- 技能唯一标识
- 技能版本号
- 版本发布日期
- 版本变更记录（倒序排列，最新版本在前）

**版本单源铁律（防漂移）**：
- **「技能版本」行为唯一事实源**（package/get_version 据此命名产物），以下三处**必须保持一致**：①元数据「技能版本」行；②文档页脚「文档版本」行；③变更记录最新一条版本号；
- **变更记录必须严格倒序**（最新版本在首，与 2026-08-07 实测漂移一致），禁止乱序混排；
- **硬门禁**：`tools/solidify.py` 每次固化前强制执行 `tools/check_version_consistency.py`，任一包元数据/页脚不一致即中止固化；
- 任何版本升级后，需**同一批次**同步 8 包涉及改动的 SKILL.md 三处与 `SKILL_INDEX.md` 版本行。

### 2.1 引用规范

- 所有跨技能引用使用相对路径 `../references/`，禁止裸 `references/` 路径；
- 本文件作为版本管理规范的唯一事实来源，各技能仅保留简短的引用声明；
- 多项目隔离方案引用：`references/multi_project_isolation.md`（Git/运行时/数据库/Docker 四层隔离 + 第 5 层全局环境资产注册与冲突仲裁，`台账/25_环境资源清单.csv`）；

## 3. 技能库版本快照与回滚规范

### 3.1 快照时机（强制）

以下任一场景发生**前**，必须先创建技能库完整快照：

| 场景 | 快照要求 |
|------|----------|
| 技能主版本升级（vX.0.0） | 升级前完整快照 + 升级后完整快照 |
| 结构性重构（拆分/合并/删除技能） | 重构前完整快照（含全部 SKILL.md 与 references/） |
| 跨技能批量修改（≥3 技能） | 修改前完整快照 |
| 单技能修订（vX.Y.Z） | 修改前备份该技能 SKILL.md 即可 |

### 3.2 快照规范

- **快照目录**：`skills_backup_<版本号>/`（项目根目录，与 `.opencode/skills/` 同级）；
- **快照内容**：全部技能目录（SKILL.md）+ `references/` 全部文档，目录结构与 `.opencode/skills/` 一致；
- **快照命名**：`skills_backup_v<版本号>/`（如 `skills_backup_v9.0.0/`）；
- **历史快照保留**：不得覆盖/删除历史快照，保留完整版本演进链；
- **快照校验**：创建后执行与当前工作目录的一致性比对（filecmp），确认无缺失/差异；
- **版本控制纳入**：快照目录须随技能库一并纳入 git 版本控制（git add 后提交），禁止写入 `.gitignore`，确保快照可随仓库历史回溯与恢复。

### 3.3 回滚机制

1. **回滚触发**：技能升级/重构后发现严重缺陷、与台账基线冲突、或用户要求恢复旧版时；
2. **回滚来源**：最近的 `skills_backup_<版本号>/` 快照或 `dist/` 中对应版本 zip；
3. **回滚流程**：从快照恢复全部 SKILL.md 与 references → 更新主技能版本变更记录（标注回滚）→ 重新打包发布 → 更新台账范围变更；
4. **回滚保护**：回滚前先对当前损坏版本做快照归档（命名 `skills_backup_<版本号>_回滚前/`），确保可再次恢复。

### 3.4 与既有机制的关系

- **项目台账备份**：由 ProjectMonitorSkill `stage_close` 负责（`项目总台账_v<版本号>_backup.xlsx`），与本规范互补——本规范覆盖技能文件本体，ProjectMonitor 覆盖项目数据；
- **完整性校验**：由 self-improve 子技能 `evolve_check_log`（SHA256 哈希链）负责验证快照/基线未被篡改（`dev-project-team-skill/skills/self-improve/domain/self-diagnosis.md` §4）；
- **跨工具部署**：技能库目录结构与多工具（TRAE/VSCode/Claude Code）同步规范详见 `cross_tool_standard.md`；快照/发布与部署脚本相互配合，部署不改变源库结构。
- **发布包**：`dist/` zip 作为轻量级可分发快照（仅含 SKILL.md），完整快照以 `skills_backup_<版本号>/` 为准。

### 3.5 存储与异地备份（多副本要求）

为降低单机故障/误删导致备份丢失的风险，快照与关键工作产物必须满足多副本要求：

1. **本地副本（强制）**：`skills_backup_<版本号>/` 快照 + git 版本控制，作为本机第一道防线；
2. **异地副本（推荐）**：定期（至少每次主版本升级后）将 git 仓库推送至远程仓库（GitHub/GitLab 等）或同步至外部存储（网盘/移动硬盘/Time Machine）；
3. **临时文件约束**：禁止将重要工作产物（拆分数据源、评审前版本等）存放于 `/tmp` 等易失目录；如需暂存，应立即迁移至项目内 `backup/tmp_migrations/` 并纳入 git；
4. **备份验证**：每次异地同步后抽查 1 个快照目录与本地一致（filecmp 比对），确保异地副本可用。
