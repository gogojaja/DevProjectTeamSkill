# Token 优化标准（Token Standard）

> 全技能体系 Token 消费的公共标准，源自 `Token优化与CSV化改造方案_v21.0.1.md` 评审修订。
> 各依赖技能直接引用本文件，避免重复定义（Token 优化方案 B 延续）。

---

## 1. 角色包模型

### 1.1 定义

- **角色包** = 一个自包含技能：`<role-name>/SKILL.md`（根入口）+ 本角色域子技能 + `shared/` 辅助能力（打包时内嵌副本）；
- **源码单源**：源码库只保留一份 `shared/`，各角色包通过相对路径 `../shared/<name>.md` 引用；副本仅在 `tools/package_skills.sh` 打包时自动内嵌，禁止源码手工复制；
- **注册口径**：工具只注册 8 个根技能（7 角色包 + 1 编排器），不注册子技能。

### 1.2 加载模式

| 模式 | 触发 | 说明 |
|------|------|------|
| 角色组合加载 | 「启用需求分析师」/「启用需求分析师+测试工程师」/业务人员「需求+测试」 | 按指令加载组合包：单角色=1 包，多角色=多包，双角色=业务人员预设（需求+测试） |
| 全生命周期 | 编排器 | 按阶段渐进加载，阶段切换强制上下文压缩 |
| 敏捷迭代 | 编排器（「用敏捷/迭代/快速上线」） | 1~2 周迭代循环，迭代切换强制压缩 + 发布级强门禁 |
| 技能维护 | 技能库自身修改（skill-authoring） | authoring 五步流程，仅维护 Skill 非执行项目 |

### 1.3 上下文压缩铁律

工具上下文为**追加式**，已读文件无法手动弃置，只能靠压缩（compaction）回收。因此：

1. 阶段门禁处必须执行上下文压缩（ContextHealthMonitor / 工具原生 compaction）；敏捷模式**迭代切换**同样强制压缩；
2. 全生命周期峰值 = 阶段内累计未压缩包量级，禁止「读后用后即弃」假设；
3. **压缩后防遗忘**：每完成一次 compaction，**重新 Read `../references/iron_rules.md`**，把铁律卡作为新上下文锚点，避免压缩丢关键约束（授权/备份/留痕）。

## 2. description 规范

- **长度**：150~250 字符（**不得低于 150**，压至 ~70 会因触发词缺失导致技能召回失败）；
- **结构**：`<做什么>。<触发词，前置>。用户说…时加载。`；
- **原则**：description 是模型从多技能中选择该包的唯一依据，必须同时含「做什么 + 何时触发」。

### 2.1 弱模型适配（能力弱模型下技能可被识别）

能力弱模型（本地 4B/7B、免费 Flash 档，见 `model_selection.md` §3/§7）对 description 的语义抓取能力弱，必须按以下规则优化，否则弱模型下技能几乎无法被选中：

- **单语言原则**：description 统一项目主导语言（简体中文），**禁止中英混排**；「Load when」句转中文「用户说/请求…时加载」或删除，保留时置于末尾；
- **触发词前置**：用户实际会说的触发词（如「启动项目/立项/章程」）放**首句**，行为描述在后；触发词缺失=弱模型永远选不中；
- **高区分度**：与其他技能 description 避免语义重叠，触发词要能唯一区分本技能；
- **弱模型铁律**：description 无触发词、中英混排、低于 150 字符 → 维护门禁拦截（`tools/check_skill_descriptions.py`），禁止发布；多技能并列时弱模型只会按首句触发词匹配。

## 3. 表格输出规则（CSV / Markdown）

### 3.1 阈值（以体积/Token 估算为准，非行数）

| 估算输出体积 | 输出格式 |
|--------------|----------|
| 估算 < 4K token（或 <100KB） | **Markdown 表格** |
| 估算 ≥ 4K token（或 ≥100KB） | **CSV 文件**（UTF-8 with BOM） |

- **快速判定**：`行数 × 列数 × 平均字段长度` ≥ 约 4K token 即转 CSV；大列数（>20 列）即使 ~200 行也建议转 CSV；
- 各技能 DoD 可按数据密度调整阈值；
- 导出 CSV 仅回显首 5 行预览 + 行数，禁止回显全文。

### 3.2 CSV 规范

1. **编码**：UTF-8 with BOM；分隔符 `,`；含逗号字段双引号包裹；多行字段 `\n`；
2. **结构**：首行表头，固定列顺序；
3. **命名**：语义化，目录内 `NN_` 序号前缀保持排序；
4. **列数上限**：单 CSV >30 列必须按域拆分；
5. **访问**：`head -5` 预览 / `grep` 定位，禁止全量 cat；
6. **审计**：CSV 纳入 git 版本控制；SHA256 校验链对 CSV 文本计算。

### 3.3 弃用 Excel

- 全库禁止产出新 `.xlsx`；存量经 `tools/excel_to_csv.py` 一次性迁移；
- 目录规划见 `../references/directory_structure.md`。

## 4. 通用 Token 减耗规则

1. **正文四段式**：技能/角色包正文仅保留「触发规则 + 流程 + 输出规范 + 边界」，明细外置 `domain/*.md` 与 `shared/`；
2. **读文件规则**：先读根 SKILL.md 路由表 → 命中后只读目标文件，禁止一次性 Read 全部文件；
3. **脚本经 bash 执行**：不载入脚本源码，只算输出；
4. **Proxy/Prompt Caching 友好排序**：稳定内容（规则/流程/铁律）前置，动态内容（当前阶段/项目数据/任务上下文）后置，最大化缓存前缀命中；
5. **命令/日志输出**：仅回显变更与错误，禁止回显完整大文件。

---

## 5. 交接文档优先

- 新模型/新会话启动第一步必须读取项目根 `交接文档.md` 的「工作断点」区，未读前禁止读取其他项目文档；
- 打包/归档/交接 zip 必须包含 `交接文档.md` 且置于包内第一项（命名 `00_交接文档.md`）；
- 所有原子任务完成 / 切换模型前执行 `tools/solidify.sh` 固化并刷新断点区。

## 6. 双平台兼容规则（Windows + macOS 强制）

本技能库所有启用项目**必须同时支持 Windows 与 macOS 双平台**（编排器 §2.2-6 / iron_rules §6）。

### 6.1 路径规则

1. 禁止硬编码单一平台绝对路径（`C:\...`、`D:\trae\...`、`/Users/...`、`/Volumes/...`）；
2. 脚本/配置统一用**相对路径**（脚本自定位：`os.path.dirname(os.path.dirname(__file__))` / `$(dirname "$0")/..`）或**平台自适应**；
3. Python 用 `os.path`/`pathlib` 拼接路径；bash 用 `$HOME`（macOS/Linux）与 `%USERPROFILE%`（Windows）分支；
4. 全局配置路径双平台对照：`~/.config/opencode/skills` ↔ `%USERPROFILE%\.config\opencode\skills`。

### 6.2 命令规则

1. 禁止依赖 Windows 专属命令（`py -3.11`、`curl.exe` 等）或 macOS/Linux 专属假设（`bash` 缺失场景需说明）；
2. 跨平台调用子脚本统一用 `sys.executable`（Python）或平台自适应 shell；
3. 可执行脚本（`.sh`/`.py`）行尾必须 LF（shebang 才可执行），配 `.gitattributes` 强制。

### 6.3 交付物规则

1. 技术方案、文档、命令说明中涉及路径/命令时，**同时标注双平台写法**；
2. 打包/部署目标路径平台自适应（Windows→`%USERPROFILE%\.config\opencode\skills`；macOS/Linux→`~/.config/opencode/skills`）；
3. 项目脚本若无法双平台通用，须显式标注运行平台并给出替代方案，不得默认单平台。

## 7. 交接预算与 Handoff 策略（P1 核心交接重构）

> 解决小模型/受限上下文窗口下频繁压缩导致交接信息丢失。三层交接文档（L1/L2/L3）配合显式预算分配与三模式 Handoff，确保小模型亦能在有限上下文完成关键决策。

### 7.1 交接预算显式分配

将上下文窗口显式切分为三个预算项，**L1 必读核心永不压缩、始终置于上下文首部**：

| 预算项 | 占比 | 硬上限（以 20k 窗口为例） | 保护策略 |
|--------|------|---------------------------|----------|
| **交接必读预算** | 10% | 2,000 token | L1 必读核心**永不压缩**，始终保留在上下文首部；压缩算法跳过 L1 区域 |
| **工作执行预算** | 75% | 15,000 token | 常规压缩策略（滚动窗口/语义去重/工具输出剪枝/边界对齐） |
| **压缩缓冲/系统预留** | 15% | 3,000 token | 系统提示词、iron_rules.md、工具调用开销、压缩元数据 |

> **适配性**：不同模型窗口按比例缩放（如 8k 窗口则 800/6000/1200），最小窗口保底 L1≤1000 token。

### 7.2 三层交接文档结构（配合预算）

| 层级 | 名称 | 目标模型 | 加载触发 | 核心内容 | 预估 Token | 预算归属 |
|------|------|----------|----------|----------|------------|----------|
| **L1 必读核心** | 关键决策摘要 | 所有模型（含小模型） | 新会话/新模型**必读** | 当前阶段/角色/任务边界、关键风险/阻塞、下一步唯一动作、铁律锚点、Iron Rules #15 | **~800 token** | 交接必读预算（10%） |
| **L2 标准上下文** | 标准工作集 | 中/大模型 | L1 判定"需要更多上下文"时按需加载 | 详细工作断点、台账指针、关键文件索引、进行中/待办列表、跨会话交接记录 | ~2,500 token | 工作执行预算（75%） |
| **L3 完整归档** | 全量归档 | 大模型/归档审计 | 显式要求/回溯分析 | 历史固化记录、完整变更日志、废弃资产清理记录、历史评审报告 | ~8,000+ token | 工作执行预算（按需） |

> **加载策略**：小模型仅加载 L1；中模型加载 L1+L2；大模型/审计加载 L1+L2+L3。工具原生 compaction 仅作用于 L2/L3，**L1 永不参与压缩**。

### 7.3 Handoff 三模式策略（可配置）

在压缩/交接时按模型能力选择策略，**默认 `handoff-struct`（小模型优先）**：

| 策略 | 适用场景 | 核心机制 | 小模型友好度 |
|------|----------|----------|--------------|
| **handoff-struct** (默认) | 小模型/受限上下文 | 结构化摘要保留：仅保留 L1 核心 + 关键实体索引(阶段/角色/风险/阻塞/下一步) + Iron Rules 锚点，其余折叠为 `{{folded:N sections}}` 占位符 | ⭐⭐⭐⭐⭐ |
| **handoff-full** | 中/大模型 | 完整 L1+L2 保留，L3 折叠，工具输出剪枝+语义去重 | ⭐⭐⭐ |
| **handoff-snap** | 极度受限/离线 | Snapcompact 思路：折叠段落渲染为极简文本索引（无图像依赖），仅保留实体指针，恢复时按需展开 | ⭐⭐⭐⭐ |

> **选择规则**：
> - 自动检测：读取模型上下文窗口/能力档位（`model_selection.md §3/§7`），小模型→`handoff-struct`，中模型→`handoff-full`，极限→`handoff-snap`
> - 显式覆盖：用户/工具可通过环境变量 `HANDOFF_STRATEGY` 或 `solidify.sh --handoff-strategy` 强制指定
> - **默认**：`handoff-struct`（小模型优先，保证关键信息不丢）

### 7.4 结构化摘要生成器（`tools/handoff_summarizer.py`）

- **触发点**：`solidify.sh` §2 刷新断点区前自动运行
- **输入**：完整交接文档 + 当前阶段/角色/任务上下文
- **输出**：L1 核心摘要（结构化 Markdown，含实体索引），写入交接文档头部 `## 🔴 L1 必读核心`
- **模型**：可配置辅助模型（默认 `qwen2.5-coder:7b` 本地小模型，满足 Hermes"辅助模型上下文≥主模型"要求）
- **保护**：L1 摘要受 §7.1 交接必读预算保护（永不压缩、首部固定）
- **Fallback**：模型不可用时退化为纯规则摘要（正则/关键词提取关键字段）

### 7.5 预压缩优化管道（零额外 LLM 调用）

在工具调用/对话轮次内嵌预压缩步骤，**零额外 LLM 调用**：

| 步骤 | 触发时机 | 操作 | Token 节省 |
|------|----------|------|------------|
| **工具输出剪枝** | 每次工具调用返回 | 仅保留 `stdout` 关键行/错误/结果摘要，丢弃冗长日志/进度条 | 20-40% |
| **敏感数据脱敏** | 语义去重前 | 强制运行 `desensitize.py --dictionary tools/desensitize/desensitize_dictionary.csv` 对文本脱敏，**仅脱敏后文本进入 embedding**，向量**仅内存计算、不落盘、用后即丢** | — |
| **语义去重** | 脱敏后/每轮对话结束 | 复用 `qwen2.5-coder:7b` mean-pooling embedding（最后一层隐藏状态平均池化），计算消息相似度(阈值 0.85)，仅保留最信息密集版本 | 15-25% |
| **边界对齐保护** | 压缩前 | 识别 tool_call/tool_result 组，保持组完整不拆分（参考 Hermes `_align_boundary_backward`） | 防信息丢失 |

> **Embedding 模型选型（CR-004）**：复用本地 `qwen2.5-coder:7b` mean-pooling（最后一层隐藏状态平均池化），零额外模型部署；向量维度 3584，内存峰值 ≤1.2 GB，CPU <30% 单核，延迟 <200 ms/32 条，**向量仅内存计算、不落盘、用后即丢**。
