# 进度成本挣值管理标准（Schedule & Cost Earned Value Management）

> 版权声明：`../COPYRIGHT.md`
> 适用：所有启用本技能库的软件项目（对齐 PMBOK 7th 进度/成本绩效域 · PMBOK 6 控制进度/控制成本过程 · EVM 挣值管理 ANSI/EIA-748 · ISO 21500 · PRINCE2 阶段边界评审 · 关键路径法 CPM）
> 调用：阶段流转门禁 `stage_review` / 项目经理日常管控调用 `tools/evm_ops.py` 自动计算 EVM 绩效
> 权威实现：可独立部署技能 `schedule-cost`（`tools/evm_ops.py` v1.0.0，内化自 dev-project-mgmt `evm_calculator.py`）——进度成本/EVM 逻辑单一信源，角色包/MCP 一律引用或委派

---

## 1. 问题定义

软件项目进度与成本反复出现两类失控：

- **进度滞后（schedule slip）**：里程碑延期未被及时量化，直到阶段边界才暴露；「感觉快完成了」的主观百分比掩盖真实进度。
- **成本超支（cost overrun）**：实际消耗与已挣价值脱钩，只看「花了多少」不看「挣了多少」，超支发现过晚无从纠偏。

根因：**进度与成本未作为受控绩效持续测量**——既缺「计划投多少」（进度/成本基准 PV/BAC），也缺「实际挣了多少、花了多少」（EV/AC + CPI/SPI 双维绩效）。

本标准在 PMBOK EVM 挣值管理框架上，补齐**里程碑级进度成本绩效**能力：进度基准、成本基准、里程碑状态机、EVM 核心指标（PV/EV/AC/CPI/SPI/CV/SV/准点率）、健康判定与预警、AC 缺失回退估算。

## 2. 行业最佳实践（依据）

| 来源 | 核心主张 | 本标准落点 |
|------|----------|-----------|
| PMBOK 7th 进度/成本绩效域 | 以绩效测量基准（PMB）比对实际，量化偏差并驱动纠偏 | §4 基准；§6 EVM 指标；§7 健康判定 |
| PMBOK 6 控制进度/控制成本 | 挣值分析（EVM）为核心工具：PV/EV/AC → CPI/SPI/CV/SV | §6 核心指标公式 |
| EVM（ANSI/EIA-748） | 挣值管理 32 项准则；里程碑/工作包级测量，客观挣值优先 | §5 里程碑 0/100 规则；§6 |
| 里程碑 0/100 规则 | 工作包/里程碑未完成计 0、完成计全额，避免主观百分比挣值 | §5 EV 计法 |
| ISO 21500 | 进度/成本控制须基于基准的绩效测量与偏差管理 | §4；§7；§9 |
| PRINCE2 阶段边界评审 | 每阶段末以绩效数据支撑继续/终止决策 | §7 健康判定；§9 流程嵌入 |
| 关键路径法 CPM | 里程碑依赖链最长路径决定总工期，延期直接传导 | §4.1 进度基准依赖 |
| 完工预算 BAC | Budget at Completion 作为 PV 的价值总量来源 | §4.2 成本基准 |

结论：**进度成本必须作为受控绩效基准 + 客观里程碑挣值（0/100）+ CPI/SPI 双维健康判定 + 偏差预警前置**，而非主观「完成度感觉」。

## 3. 标识符与台账数据源规范

### 3.1 里程碑标识符（ID Scheme）

| 产物 | 前缀 | 示例 | 台账 |
|------|------|------|------|
| 里程碑 | `M<n>` | M1 / M2 | `09_进度跟踪台账.csv` |

**规则**：里程碑编号唯一、稳定、不复用；重复 ID 的 `add-milestone` 被拒（rc1），防止重复登记污染 PV 总量。

### 3.2 台账数据源（directory_structure.md §6 权威 schema）

EVM 计算读写目标项目 `台账/`，四个数据源各司其职。各项目历史列名存在差异，工具读取时**防御式别名**兼容（下表「别名」列为工具实际回退顺序）：

| 台账 | 角色 | 关键列（规范名 → 别名） |
|------|------|------------------------|
| `03_进度基准.csv` | 进度计划侧 | 阶段 / 里程碑编号·名称 / 计划开始 / 计划日期 / 依赖关系 |
| `04_成本基准.csv` | BAC 来源 | 成本阈值 → 预算 / BAC / 总预算 / 成本基准；人力工时预估 / 超支标准 |
| `09_进度跟踪台账.csv` | **PV/EV 主源** | 里程碑编号 → 编号/ID/milestone_id/里程碑；计划值 → 计划值(PV)/PV/预算/planned_value；任务完成率 → 完成率/completion；状态 → status；计划日期 → 计划完成日期/计划结束/planned_end；实际日期 → 实际完成日期/actual_end |
| `10_成本消耗台账.csv` | **AC 主源** | 累计消耗 → 累计成本/cumulative；资源成本 → resource_cost；工具成本 → tool_cost |

> 向后兼容：既有台账若为差异 schema，`add-milestone`/`update-milestone` 沿用既有表头追加（非破坏式），读取一律走别名回退。

## 4. 进度基准与成本基准（PMB 计划侧）

### 4.1 进度基准（03_进度基准.csv）

进度基准是 EVM 的计划侧锚点，项目初始化时建立，任务分解至可跟踪粒度：

- **阶段划分**：启动/需求/架构/开发/测试/投产 阶段序列。
- **里程碑清单**：每阶段可验证的交付节点，编号 `M<n>` 唯一不复用。
- **计划日期**：计划开始·完成日期（YYYY-MM-DD），是准点率判定与时间进度比 AC 估算的锚点，必填。
- **依赖关系（CPM）**：里程碑间 FS/SS 依赖，关键路径（依赖链最长）里程碑优先保障，其延期直接传导总工期。

### 4.2 成本基准（04_成本基准.csv）与 BAC

成本基准提供 **BAC（Budget at Completion，完工预算）**，是 PV 的价值来源。BAC 取 `成本阈值`（别名回退 预算/BAC/总预算/成本基准）首个正值。

**PV 三级回退规则**（工具 `_load_milestones`）：
1. 里程碑显式声明 `计划值`（PV）→ `PV = Σ 各里程碑计划值`（推荐，精确到里程碑）。
2. 里程碑未声明计划值 → 按 BAC 均摊：`pv_i = BAC / 里程碑数`。
3. BAC 亦缺失 → 回退默认 `pv_i = 1.0`（保证 CPI/SPI 比值仍可计算，绝对值仅供参考）。

## 5. 里程碑状态机与 0/100 挣值规则

### 5.1 里程碑状态（09_进度跟踪台账 `状态` 列）

```
未开始 → 进行中 → 已完成（终态，计全额 EV）
              │
              └─→ 延期（记偏差，责任到人）
```

- 「已完成」判定（工具 `_is_done`）：状态含 `已完成/完成/已交付/done/closed/complete` 任一 token（大小写不敏感）。
- 置为已完成且未填实际完成日时，`update-milestone` 自动补当天日期（准点判定输入）。

### 5.2 EV 里程碑 0/100 规则（权威计法，与 dev-project-mgmt 一致）

**EV = Σ（已完成里程碑的计划值）**；未完成里程碑计 0。

```
EV = Σ pv_i  , 对所有 done=True 的里程碑 i
```

> **为何 0/100 而非百分比挣值**：主观完成百分比（「已完成 80%」）缺乏客观证据，易被乐观粉饰；里程碑 0/100 规则以「里程碑达成」为客观挣值事件，符合 ANSI/EIA-748 对客观挣值的要求，且与 dev-project-mgmt `evm_calculator.py` 公式一致（AC6 内化一致性）。

## 6. EVM 核心指标（权威公式，`evm_ops.py _compute_evm`）

| 指标 | 全称 | 公式 | 判读 |
|------|------|------|------|
| **PV** | Planned Value 计划值 | `Σ pv_i`（全部里程碑） | 计划应完成的价值总量 |
| **EV** | Earned Value 挣值 | `Σ pv_i`（仅已完成里程碑，0/100） | 实际已挣得的价值 |
| **AC** | Actual Cost 实际成本 | 台账 `10` 累计消耗；缺失回退 §6.1 | 实际已花费的成本 |
| **CPI** | Cost Performance Index 成本绩效指数 | `EV / AC` | >1 成本节约；<1 成本超支 |
| **SPI** | Schedule Performance Index 进度绩效指数 | `EV / PV` | >1 进度超前；<1 进度滞后 |
| **CV** | Cost Variance 成本偏差 | `EV − AC` | >0 节约；<0 超支 |
| **SV** | Schedule Variance 进度偏差 | `EV − PV` | >0 超前；<0 滞后 |
| **准点率** | On-Time Rate | `准点完成里程碑数 / 里程碑总数` | 准点=实际完成日 ≤ 计划完成日 |

- 分母保护：`AC ≤ 0` 时 `CPI = 0`；`PV ≤ 0` 时 `SPI = 0`（避免除零）。
- 精度：PV/EV/AC/CV/SV 保留 2 位小数；CPI/SPI/准点率 保留 4 位小数。

### 6.1 AC 缺失回退估算（时间进度比，与 dev-project-mgmt 一致）

`10_成本消耗台账` 无数据时，AC 按**时间进度比**估算（工具 `_estimate_ac_by_time`），并标注 `ac_source="时间进度比估算"`：

```
ac_i = pv_i × clamp((today − planned_start) / (planned_end − planned_start), 0, 1)
AC   = Σ ac_i
```

- 里程碑缺计划开始/结束日期时，回退 `ac_i = pv_i × 完成度`（完成度为 0 时取 0.5 保守估算）。
- 有台账实际成本时，AC 优先取 `累计消耗` 最大值，否则 `Σ(资源成本 + 工具成本)`，标注 `ac_source="台账10_成本消耗"`。

## 7. 健康判定与偏差预警

### 7.1 CPI/SPI 双维健康判定（权威阈值，`evm_ops.py`）

| 判定 | 条件 | 含义 |
|------|------|------|
| ✅ 健康 | `CPI ≥ 1.0` 且 `SPI ≥ 1.0` | 成本节约 + 进度超前 |
| ⚠️ 轻度偏差 | `CPI ≥ 0.9` 且 `SPI ≥ 0.9`（未达健康） | 需关注，尚在容忍带 |
| ❗ 严重偏差 | `CPI < 0.9` 或 `SPI < 0.9` | 成本超支/进度滞后，须纠偏 |

### 7.2 偏差预警（calc 自动输出）

- `CPI < 1.0` → `[WARN] 成本超支：每投入 1 元仅产出 CPI 元挣值`。
- `SPI < 1.0` → `[WARN] 进度滞后：仅完成计划进度的 SPI×100%`。
- 预警必须留痕（`calc --json` 结构化输出供 MCP `evm_analyze`/PMO 仪表盘消费）。

### 7.3 人工决策门槛

- **连续 2 次延期/超支** → 停止 AI 自动调整计划，强制推送人工决策（PRINCE2 阶段边界升级）。
- 基准调整（改 PV/BAC/里程碑计划日期）→ 须走变更审批，委派 `scope-tracking` 变更生命周期，禁止以「实际发生」逆向修正基准。

## 8. 退出码与 CLI 契约（`evm_ops.py`）

```bash
python3 tools/evm_ops.py add-milestone --id M1 --name "需求基线" [--start 2026-09-01] [--end 2026-09-30] [--value 1000]
python3 tools/evm_ops.py update-milestone --id M1 [--status 已完成] [--actual-end 2026-09-28] [--completion 100]
python3 tools/evm_ops.py calc [--milestone M1] [--json]
python3 tools/evm_ops.py status
```

| 退出码 | 含义 |
|--------|------|
| `0` | 成功；或无数据时的友好提示（09 台账为空 → calc 提示先 add-milestone） |
| `1` | 参数非法：重复里程碑 ID（add）/ 里程碑不存在（update）/ 09 台账为空（update） |

- 工具经 `PROJECT_ROOT` 环境变量解析目标项目根，无论脚本副本位于何处，读写的都是目标项目的 `台账/`（03/04/09/10）。

## 9. 流程嵌入（何时做）

- **启动/规划阶段**：建进度基准（03，阶段+里程碑+计划日期+依赖）与成本基准（04，BAC）；`add-milestone` 登记里程碑到 09，明确 PV。
- **执行阶段**：`update-milestone` 更新里程碑状态/实际完成日/完成率（已完成自动补实际日期）；成本消耗记入 10 台账（AC 主源）。
- **每阶段 `stage_review`**：自动跑 `evm_ops.py calc`（PV/EV/AC/CPI/SPI/CV/SV/准点率 + 健康判定），严重偏差（<0.9）无纠偏方案不得流转。
- **周期复盘**：`calc --json` 出结构化绩效，偏差分析 + 纠偏方案；连续 2 次延期/超支推送人工决策。
- **监控/汇报**：`status` 出全里程碑状态 + EVM 概览；`calc --json` 供 MCP `evm_analyze`/PMO 仪表盘消费；跨项目 CPI/SPI/准点率统一度量口径归 `role-program-mgmt`。
