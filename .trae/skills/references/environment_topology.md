# environment_topology.md — 双套环境拓扑规划标准（单源共享）

> 环境管理整体规划：**每个项目采用「开发测试一套 + 生产一套」双套环境拓扑**，两套之间文件隔离、端口隔离，基础软硬件可共用。
> 被 role-development / role-testing / role-deployment / role-project-init（register_env_asset）引用。
> 配套台账：`台账/20_环境配置.csv`（含环境组/隔离方式/端口区间/共用边界/权限角色列）。
> 配套机制：`environment_standard.md`（配置列标准）、`multi_project_isolation.md`（四层隔离 + CMDB 第 5 层）、`tools/cmdb/` 资源仲裁。

## 1. 设计原则（行业最佳实践）

对齐行业实践：AWS 1+N 架构（Hybrid / Consolidated Non-Production 模型）、CSA 环境隔离指南、环境隔离三层次（数据/进程/网络）。

| # | 原则 | 落地 |
|---|------|------|
| 1 | **非生产合并，生产独立**：dev+test 共享一套基础软硬件；prod 独立严格隔离，变更须 CAB/回滚预案 | 双套环境组（§2） |
| 2 | **文件隔离**：两套环境文件系统/数据目录/配置互不交叉，防止配置漂移与数据污染 | §3 |
| 3 | **端口隔离**：两套环境端口区间分离，同端口段内按项目错位规划；冲突经 CMDB 仲裁 | §4 |
| 4 | **基础软硬件共用**：Docker 引擎/基础镜像/GPU/编译工具链/网络出口等平台层共用；服务实例层隔离 | §5 |
| 5 | **权限最小化（RBAC）**：开发者非生产全权+生产只读；QA 测试执行权；生产变更走 CAB/ECAB 审批 | §6 |
| 6 | **单一真实数据源**：环境拓扑统一登记 `20_环境配置.csv`，构建/部署仅从该台账取参数，禁止各自维护 | §7 |

## 2. 双套环境组拓扑

按行业 1+N：**一个非生产环境组 + 一个生产环境组**，替代盲目 dev/test/prod 三套独立搭建（省资源且减少维护成本）。

| 环境组 | 组成 | 基础软硬件 | 文件 | 端口 | 数据 | 权限 |
|--------|------|-----------|------|------|------|------|
| **非生产组 nonprod** | dev + test（同一套平台实例，逻辑细分） | **共用**（Docker Engine/镜像/GPU/中间件模板/编译工具） | 项目内隔离目录，组内共享平台文件 | 非生产端口区间（§4） | 脱敏/造数，禁生产数据 | 开发全权，QA 执行权 |
| **生产组 prod** | prod（独立部署，与白云隔离） | 平台层只读共用（镜像只拉取），实例独占 | 独立文件系统/数据目录 | 生产端口区间（§4） | 真实数据 | 只读+变更走 CAB |

> **非生产组内 dev/test 逻辑细分**：同一平台实例上按环节独立数据库 schema、独立环境变量、独立命名空间/目录，避免测试数据污染开发。

### 2.1 环境命名规范

统一命名 `{project}-{envGroup[-slot]}`，如 `finapp-nonprod-dev` / `finapp-nonprod-test` / `finapp-prod`。

| 段 | 取值 | 说明 |
|----|------|------|
| project | 项目代号 | 小写连字符 |
| envGroup | `nonprod` / `prod` | 双套环境组 |
| slot | `dev` / `test`（仅 nonprod） | 非生产组内逻辑细分 |

## 3. 文件隔离（两套环境文件互不交叉）

- **目录规划**：两套环境工作目录分属独立目录树，禁止共享工作目录
  ```
  项目根/
  ├── environments/
  │   ├── nonprod/            # 非生产组（dev+test 共用平台文件）
  │   │   ├── dev/            # 开发 slot：源码/venv/环境变量/局部配置
  │   │   ├── test/           # 测试 slot：测试脚本/数据/报告
  │   │   └── shared/         # 组内共享：公共镜像引用/模板/工具链
  │   └── prod/               # 生产组独立目录树
  │       └── deploy/         # 生产部署产物/回滚包/审计
  └── 台账/20_环境配置.csv    # 单一真实源
  ```
- **数据目录**：数据库数据目录、日志、缓存卷拆分为 `nonprod` / `prod` 两套，卷名 `{project}-{envGroup}-{svc}`（衔接 `25_环境资源清单.csv`）；
- **配置隔离**：`.env.nonprod` / `.env.prod` 分离，密钥只存别名（A 级铁律），真实值经 `.secrets/` 注入；
- **代码库**：非生产/生产共用同一 Git 仓库，靠分支+tag 区分（`multi_project_isolation.md` §2），不拆两份代码。

## 4. 端口隔离（端口区间规划）

双套环境使用**互不重叠的端口区间**，区间内按服务类型错位规划；所有监听端口注册 CMDB（`25_环境资源清单.csv`），冲突先注册先得。

| 区间 | 用途 | 范围示例 | 说明 |
|------|------|----------|------|
| **非生产端口区间** | nonprod dev+test 全部服务 | `30000~39999`（示例，按实际调整） | 与生产区间硬隔离，区间内 dev→test 按 100 步进错位 |
| **生产端口区间** | prod 服务 | `8000~8999`（示例）或 `80/443` 经网关映射 | 独立区间，禁止与非生产区间重叠 |
| **共用平台层** | Docker 引擎/GPU/基础服务 | 固定少数端口（如 2376/凭据） | 属基础软硬件共用范畴，登记后全项目只读引用 |

> 端口分配规则：dev 占 `30000+svc_offset`，test 占 `30100+svc_offset`，prod 按云/网关规范单独规划。冲突检测脚本与 CMDB `cmdb-cli.py` 仲裁（见 `multi_project_isolation.md` §4.1/§10）。

### 4.1 端口分配示例

| 服务 | nonprod-dev | nonprod-test | prod | 共用平台层 |
|------|-------------|--------------|------|-----------|
| Web API | 30000 | 30100 | 8080（网关映射） | - |
| Admin API | 30001 | 30101 | 8081 | - |
| DB | 30002 | 30102 | 5432（集群） | - |
| 缓存 | 30003 | 30103 | 6379（集群） | - |
| Docker Engine | - | - | - | 2376 |

## 5. 基础软硬件共用边界（该共用则共用，该隔离必隔离）

| 层 | 是否共用 | 说明 |
|----|---------|------|
| Docker Engine / Podman | **共用** | 单一运行时托管所有项目容器，容器网络/名称空间隔离 |
| 基础镜像仓 | **共用** | 镜像多项目复用，实例层隔离；生产只读引用 |
| GPU / 高性能硬件 | **共用** | 经 CMDB 登记调度，先注册先得，独占任务排队 |
| 编译工具链 / 公共依赖 | **共用** | 多项目复用，减少重复安装 |
| 中间件模板（PG/Redis 镜像模板） | **共用** | 模板共用，运行实例按项目-环境命名分离 |
| 服务实例（容器/进程/数据库库实例） | **必须隔离** | 每项目每环境组独立，禁止跨项目共享运行实例 |
| 数据卷 / 日志 / 缓存 | **必须隔离** | 卷名 `{project}-{envGroup}-{svc}`，杜绝数据串写 |
| 网络出口 / 代理 | **共用**（按需） | 共用出网，访问控制按环境组分别策略 |

## 6. 权限模型（RBAC，CSA 建议）

| 角色 | nonprod dev | nonprod test | prod | 依据 |
|------|-------------|--------------|------|------|
| 开发者 | 读写 | 读写（测试协助） | 只读排查 | 防生产误改 |
| QA/测试 | 只读 | 读写（执行/造数） | 禁止 | 测试只需执行权 |
| 开发工程师（部署） | 读写 | 读写 | 只读+变更走 CAB | 生产变更受控 |
| PM/架构（评审） | 只读 | 只读 | 只读审计 | 需要可见性 |
| 运维（生产操作员） | 可控 | 可控 | 读写（生产专责） | 唯一生产写权限角色 |

## 7. 单一真实源与运维闭环

1. 环境拓扑一次性规划入 `20_环境配置.csv`（环境组/隔离方式/端口区间/共用边界/权限角色），后续配置/检查/部署**仅从该台账读取**；
2. 环境就绪检查（`check_gate` / `check_ready`）比对台账与实际运行（端口监听、数据目录、卷名），不一致即阻断；
3. 环境变更走 `register_change` + `change_audit`；生产组变更须 CAB/ECAB + 回滚预案（见 role-deployment planning）；
4. 冒烟测试在对应环境组通过后才允许推进；
5. 多项目共享平台资源冲突升阶 `change_audit` 留痕（`multi_project_isolation.md` §10 / CMDB）；
6. 审计台账：`13_安全审计台账.csv` 记录环境变更操作留痕。

## 8. 与现有文件的关系

| 文件 | 关系 |
|------|------|
| `environment_standard.md` | 配置项明细标准（dev/test/prod 列）——本文件定义拓扑，它定义各环境配置项 |
| `multi_project_isolation.md` | 四层隔离实现细则 + CMDB 第 5 层资源注册仲裁——本文件在其之上定义双套拓扑 |
| `role-project-init` register_env_asset | 项目启动时按本拓扑注册 25_环境资源清单，check_ready 门禁 |
| `role-deployment` planning | 生产环境变更 CAB/回滚预案对接生产组 |
