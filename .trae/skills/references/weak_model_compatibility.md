# weak_model_compatibility.md — 弱模型兼容指南（能力弱模型下技能发挥最佳作用）

> 定位：解决「能力弱的模型（本地 4B/7B、免费 Flash 档）加载技能库时，技能几乎无法被识别/执行」的问题。
> 适用：所有 SKILL.md、角色包、编排器、子技能。衔接 `token_standard.md` §2.1（description 弱模型适配）与 `model_selection.md` §4（模型路由）。

## 1. 问题本质

能力弱模型（S0/S1 档，见 `model_selection.md` §3）对长上下文、中英混排、深层隐式推理的语义抓取能力弱，导致：

1. **召回失败**：description 无触发词或中英混排 → 弱模型从多技能列表中选不中正确技能；
2. **指令丢失**：SKILL.md 正文过长/嵌套过深 → 弱模型只记住头部，细则被忽略；
3. **执行偏差**：依赖隐含上下文的流程 → 弱模型无法自行推导下一步。

## 2. 适配原则（三条铁律）

| 铁律 | 要求 | 依据 |
|------|------|------|
| **单语言** | SKILL.md 正文与 description 统一简体中文，禁止中英混排 | 弱模型跨语言匹配/推理弱 |
| **前置执行** | 头部 5 行内含「触发词 + 第一步动作」，细节外置 domain/__resources | 弱模型按顺序记忆，头重脚轻 |
| **显式命令** | 步骤写成显式动词指令（执行/输出/校验），避免「可考虑/建议」式软表述 | 弱模型不擅长推断软性意图 |

## 3. SKILL.md 结构适配清单

1. **frontmatter**：`name` + `description` 必备（opencode 只认这 5 字段：name/description/license/compatibility/metadata，其余忽略）；
2. **description**：触发词首句、单语言、150~250 字符（细则见 `token_standard.md` §2.1）；
3. **正文头部**（`## 1. 触发规则`）：用户说什么→加载本技能，直接列出动作名与第一步；
4. **流程表**：路由表「环节/动作/明细」用短句，明细文件路径显式给出；
5. **明细外置**：>50 行的细则放 `domain/*.md` 与 `*__resources/`，正文只留指针；
6. **刹车规则**：全局强制刹车（安全铁律）保留在正文，弱模型也必须遵守。

## 4. 路由与档位衔接（衔接 model_selection §4）

- S0 简单 / S1 常规 → 弱模型可执行（导航/查询/格式化/常规文档/单文件编码）；
- S2 复杂 / S3 高危 → **禁止降档给弱模型**，强制强模型（架构评审/需求分析/高危编码/安全相关）；
- 弱模型执行 S0/S1 任务时，技能正文按本指南优化后应可独立完成，不需强模型干预；
- 每阶段末复核 `21_模型选型.csv`：低成本模型能力不足导致返工 → 升档（`model_selection.md` §6）。

## 5. 弱模型执行失败降级路径

| 失败信号 | 判定 | 降级动作 |
|---------|------|---------|
| 技能未被选中 | description 触发词缺失/混排 | 按 §2/§3 重写 description，跑 `tools/check_skill_descriptions.py` |
| 流程半途迷失 | 正文过长/嵌套 | 拆细则到 domain/，正文头 5 行内给第一步 |
| 结论偏差 | 任务实际属 S2/S3 | 路由升档强模型，回写 `21_模型选型.csv` |
| 中英混排错乱 | 跨语言推理弱 | 统一简体中文重写正文 |

## 6. 校验门禁

- `tools/check_skill_descriptions.py`：description 触发词首句 / 无英文尾巴 / 150~250 字符 → 全库 SKILL.md 必过；
- `check_version_consistency.py`：版本一致性硬门禁；
- 新技能/改技能发布前必须跑两个校验，未过禁止 `solidify`。
