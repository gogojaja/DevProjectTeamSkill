# 测试策略分析详细内容参考（Test Strategy Details）

> 本文件为 `test-strategy-skill` 详细分析内容的参考文档，按需加载。
> SKILL.md 仅保留流程骨架与规则，详细表格与本文件对应章节为准。

---

## 一、需求可测性分析

对需求基线中的每条需求进行可测性评估：

| 可测性等级 | 定义 | 处理策略 |
|-----------|------|---------|
| **可直接测试** | 需求描述清晰、验收标准明确、输入输出可观测 | 正常设计用例 |
| **需澄清后测试** | 需求描述模糊或验收标准不明确 | 提出澄清问题，补充测试验收标准后设计用例 |
| **间接测试** | 无法直接验证，需通过关联功能间接验证 | 设计关联场景用例，标注间接验证关系 |
| **暂不可测试** | 依赖外部条件未满足（如第三方系统未就绪） | 标注阻塞条件，制定替代方案（Mock/延期） |

**分析输出**：《需求可测性分析清单》，包含每条需求的可测性等级、测试验收标准、依赖条件、风险标注。

## 二、风险评估与测试优先级

采用**风险驱动测试（Risk-Based Testing, RBT）**方法论，基于风险等级分配测试资源。

### 2.1 风险评估矩阵

| 影响\概率 | 极低(1) | 低(2) | 中(3) | 高(4) |
|----------|---------|-------|-------|-------|
| **致命(4)** | 中风险(4) | 高风险(6) | 极高风险(12) | 极高风险(16) |
| **严重(3)** | 低风险(3) | 中风险(6) | 高风险(9) | 极高风险(12) |
| **一般(2)** | 低风险(2) | 低风险(4) | 中风险(6) | 高风险(8) |
| **微小(1)** | 极低(1) | 低风险(2) | 低风险(3) | 中风险(4) |

- **风险值 = 影响程度 × 发生概率**（1-16）
- **极高风险(>10)**：P0用例，100%覆盖，优先执行，多方法交叉验证
- **高风险(7-10)**：P1用例，100%覆盖，优先执行
- **中风险(4-6)**：P2用例，>=80%覆盖，按计划执行
- **低风险(1-3)**：P3用例，选择性覆盖，资源允许时执行

### 2.2 风险维度评估

每个功能模块从以下维度评估风险：

| 维度 | 评估问题 | 高风险信号 |
|------|---------|-----------|
| **业务影响** | 功能故障对业务的影响程度 | 涉及核心业务流程、资金、用户数据 |
| **技术复杂度** | 实现的技术难度和依赖复杂度 | 新技术栈、复杂算法、多系统集成 |
| **变更频率** | 需求变更的频繁程度 | 需求频繁调整、需求不明确 |
| **历史缺陷** | 类似功能的历史缺陷密度 | 同类功能历史缺陷率高 |
| **接口依赖** | 对外部系统/接口的依赖程度 | 依赖多个第三方系统 |
| **数据敏感** | 涉及数据的敏感性 | 涉及用户隐私、财务数据 |

## 三、测试方法选型

根据需求特征和风险评估结果，选择合适的测试方法组合：

| 需求特征 | 推荐测试方法组合 | 适用测试类型 |
|---------|----------------|-------------|
| 输入范围明确 | 等价类划分 + 边界值分析 | 功能测试 |
| 多条件组合逻辑 | 决策表 + 因果图 | 功能测试 |
| 状态流转业务 | 状态迁移法 | 功能测试 |
| 参数组合爆炸 | 正交实验法 + 组合测试 | 功能/接口测试 |
| 用户业务流程 | 场景法（基本流+备选流） | 功能/SIT测试 |
| 接口契约验证 | 契约测试 + 数据驱动 | 接口自动化测试 |
| 跨系统数据流转 | 端到端场景法 + 数据一致性校验 | SIT联调测试 |
| 性能敏感功能 | 负载测试 + 压力测试 + 容量测试 | 非功能测试 |
| 安全敏感功能 | OWASP Top 10检查 + 渗透测试 | 安全测试 |
| 历史缺陷高发区 | 错误推测法 + 回归测试 | 全类型补充 |

## 四、五大测试类型定义

测试类型与测试级别（组件/集成/系统/验收）是正交维度，同一级别可包含多种测试类型。

### 4.1 功能测试（Functional Testing）

- **定义**：验证系统功能行为是否符合需求规格说明，关注"系统做什么"，采用黑盒方法
- **被测对象**：需求文档中定义的全部功能点
- **设计方法**：等价类划分 + 边界值分析 + 场景法 + 决策表 + 错误推测法
- **覆盖目标**：核心需求（P0/P1）100% 覆盖，非核心需求 >=80% 覆盖
- **准入条件**：需求基线已固化、待测版本已交付、测试策略已分析
- **准出条件**：功能用例执行率 100%，严重/主要缺陷 100% 闭环
- **质量模型映射**：ISO 25010 功能性（功能完备性、功能正确性、功能适合性）

### 4.2 系统联调测试（SIT, System Integration Testing）

- **定义**：验证被测系统与外部系统/第三方组件之间的交互与集成，关注跨系统接口、数据交换、端到端业务链路
- **被测对象**：系统间接口、数据流转、业务链路
- **设计方法**：接口契约验证 + 业务链路场景法 + 数据一致性校验
- **执行顺序**：单接口验证 → 组合接口验证 → 端到端业务链路验证
- **联调模式**：前置联调（开发阶段接口契约对齐，Mock验证）/ 并行联调（各方同步开发，沙箱环境验证）/ 正式联调（各方接口就绪，联调环境端到端验证）
- **关键要点**：明确联调边界与 RACI 矩阵；准备接口契约/Mock/沙箱；失败时定位己方 vs 第三方（日志+抓包+对比契约）；记录接口响应时间基线；数据一致性校验（完整性/时序性/幂等性）
- **准入条件**：接口契约文档已定稿、各方接口已就绪（或Mock可用）
- **准出条件**：全部接口链路验证通过，无严重/主要缺陷

### 4.3 接口自动化测试（API Automation Testing）

- **定义**：对 API/接口进行自动化验证，验证服务间数据交互与业务逻辑
- **定位**：测试金字塔中层，投入产出比最高
- **设计方法**：数据驱动 + 参数化 + 契约测试（如Pact）
- **工具建议**：Postman / RestAssured / pytest + requests / Karate DSL
- **用例分层**：契约层（请求/响应结构符合契约）/ 业务逻辑层（业务处理逻辑）/ 场景层（多接口组合业务场景）
- **关键要点**：纳入 CI 流水线；用例原子化/参数化/独立执行；覆盖正向/逆向/边界/异常四类；契约破坏自动检测（Consumer-Driven Contract Testing）；测试数据隔离；断言分层（状态码/业务码/数据结构/数据值）
- **准入条件**：接口文档已定稿、CI 环境已搭建
- **准出条件**：核心接口自动化覆盖率 >=80%，CI 流水线集成完成
- **CI/CD集成**：代码提交 → 单元测试 → 接口自动化测试 → 结果通知；失败用例阻断流水线；测试报告自动生成推送

### 4.4 非功能测试（Non-Functional Testing）

| 子类型 | 定义 | 关注指标 | 典型工具 | 准出标准 |
|--------|------|---------|---------|---------|
| **性能测试** | 评估系统在不同负载下的响应速度、稳定性、吞吐量 | 响应时间、TPS、并发数、CPU/内存占用 | JMeter、LoadRunner、Gatling | 核心接口响应时间 <= 需求阈值 |
| **负载测试** | 验证系统在预期负载下的表现 | 并发用户数、TPS、响应时间百分位 | JMeter | 满足设计负载且指标达标 |
| **压力测试** | 验证系统超出负载极限时的行为 | 崩溃点、错误率、恢复能力 | JMeter | 明确系统极限且无数据损坏 |
| **兼容性测试** | 验证不同环境（OS、浏览器、设备、分辨率）下适配性 | 设备型号、屏幕尺寸、版本兼容性 | BrowserStack、Sauce Labs | 列表内环境 100% 通过 |
| **可靠性测试** | 验证规定条件下和时间内无故障运行及故障恢复能力 | MTBF、容错性、恢复性 | 长时间运行测试、断电恢复测试 | 连续运行无故障 |
| **可用性测试** | 验证用户使用的易用性、可理解性 | 操作复杂度、学习成本、SUS评分 | 用户走查、SUS问卷 | 无严重可用性问题 |
| **无障碍测试** | 验证系统对残障用户的可访问性 | WCAG 2.1合规性、屏幕阅读器兼容 | axe、WAVE、Lighthouse | WCAG 2.1 AA级合规 |
| **本地化测试** | 验证系统在不同语言/地区环境下的适配 | 语言翻译、日期/货币格式、文化适配 | 多语言环境测试 | 目标地区功能正常 |

- **执行原则**：按需求与风险选择性开展，非功能需求应在需求阶段明确定义验收标准
- **性能测试场景设计**：基准测试 → 负载测试 → 压力测试 → 稳定性测试 → 容量测试
- **准入条件**：非功能需求验收标准已明确、功能测试基本通过
- **质量模型映射**：ISO 25010 性能效率、兼容性、易用性、可靠性、维护性、可移植性

### 4.5 安全测试（Security Testing）

- **定义**：评估系统面对威胁和攻击时的安全性能，发现漏洞、弱点与风险
- **安全测试分层**：

| 层级 | 测试内容 | 执行时机 | 工具/方法 |
|------|---------|---------|---------|
| **安全需求验证** | 验证安全需求是否正确实现 | 功能测试阶段 | 需求对照检查 |
| **安全扫描（SAST/DAST）** | 静态/动态安全漏洞扫描 | CI流水线/功能测试阶段 | SonarQube、OWASP ZAP |
| **渗透测试** | 模拟攻击者进行深度安全测试 | 系统测试阶段 | Burp Suite、Metasploit |
| **安全审计** | 安全配置、权限模型、日志审计 | 上线前 | 人工审计 + 工具辅助 |

- **关注维度（OWASP Top 10 对齐）**：认证与授权（越权访问/会话管理/Token有效性/密码策略）、数据保护（加密存储/传输、脱敏、GDPR合规）、注入攻击（SQL/XSS/CSRF/SSRF）、网络安全（HTTPS强制/端口暴露/CORS/HSTS）、权限边界（水平越权/垂直越权/IDOR）、安全配置（默认账户/错误信息泄露/不安全反序列化）、日志与监控（安全事件日志/异常监控/审计追踪）
- **工具建议**：OWASP ZAP、Burp Suite、Nessus、SonarQube
- **设计方法**：威胁建模（STRIDE）+ OWASP Top 10 检查清单 + 渗透测试（高风险系统）
- **准入条件**：功能测试通过、安全需求已明确
- **准出条件**：无高危/严重安全漏洞，中危漏洞已评估并记录，低危漏洞有修复计划
- **质量模型映射**：ISO 25010 安全性

## 五、测试度量指标体系

### 5.1 产品质量指标

| 指标 | 定义/公式 | 说明 |
|------|---------|------|
| 缺陷密度 | 缺陷总数 / KLOC | 识别高风险代码区域 |
| 缺陷到达率 | 新缺陷数 / 时间周期 | 测试早期高属正常，回归期高为预警 |
| 缺陷DI值 | 致命×10 + 严重×5 + 一般×2 + 微小×1 | 加权评估缺陷整体严重程度 |
| 缺陷逃逸率 | 生产缺陷 / 缺陷总数 × 100% | 越低越好，目标 <=5% |
| 需求覆盖率 | 有用例的需求数 / 总需求数 × 100% | 核心需求目标 100% |
| 代码覆盖率 | 已执行代码行 / 总代码行 × 100% | 含语句/分支/路径覆盖率 |
| 缺陷分布 | 按模块/类型/严重程度的缺陷分布 | 识别质量薄弱区域 |

### 5.2 过程有效性指标

| 指标 | 定义/公式 | 说明 |
|------|---------|------|
| 缺陷移除效率(DRE) | 测试发现缺陷 / 总缺陷 × 100% | 评估测试有效性 |
| 重新打开率 | 重新打开缺陷 / 已修复缺陷 | 高则说明修复质量差 |
| 平均修复时长(MTTR) | 总修复时间 / 修复缺陷数 | 反映修复效率 |
| 用例执行率 | 已执行用例 / 计划用例 | 衡量测试进度 |
| 用例通过率 | 通过用例 / 已执行用例 × 100% | 反映系统稳定性 |
| 用例有效性 | 发现缺陷数 / 执行用例数 | 高则用例命中真实问题 |
| 自动化覆盖率 | 自动化用例 / 总用例 × 100% | 评估自动化投入 |
| 探索性测试产出 | 探索发现缺陷 / 探索时长 | 评估探索效率 |

### 5.3 项目管理指标

| 指标 | 定义/公式 | 说明 |
|------|---------|------|
| 测试进度偏差 | (计划用例 - 已执行用例) / 计划用例 × 100% | 偏差>20%触发预警 |
| 测试工时偏差 | (实际工时 - 估算工时) / 估算工时 × 100% | 评估估算准确性 |
| 环境可用率 | 环境正常时长 / 总测试时长 × 100% | 评估环境稳定性 |
| 缺陷修复速率 | 已修复缺陷 / 修复工时 | 评估开发修复效率 |
| 测试资产复用率 | 复用用例 / 总用例 × 100% | 评估用例可维护性 |

### 5.4 指标采集与可视化建议
- 从三类指标中各选 2-3 个建立基线与目标
- 避免指标过多导致仪表盘疲劳
- 指标趋势比绝对值更重要
- 定期复盘指标偏差并调整测试策略
- 建议指标仪表盘包含：用例执行进度图、缺陷DI趋势图、缺陷分布帕累托图、覆盖率仪表盘
