# 测试执行与缺陷管理详细内容参考（Test Execution Details）

> 本文件为 `test-execution-skill` 测试执行与缺陷管理环节的详细内容参考，按需加载。
> SKILL.md 仅保留 Definition of Ready / Definition of Done / 规则，详细表格与本文件对应章节为准。

---

## 一、测试执行顺序（风险驱动）

1. 冒烟测试（P0用例）→ 不通过则退回
2. 功能测试（P0→P1→P2→P3）→ 正向→逆向→边界→异常
3. SIT联调测试 → 单接口→组合接口→端到端链路
4. 接口自动化测试 → 纳入CI持续执行
5. 非功能测试 → 性能→兼容性→可靠性→无障碍
6. 安全测试 → 安全扫描→OWASP Top 10检查→渗透测试
7. 探索性测试 → 补充脚本测试盲区
8. 回归测试 → 缺陷修复后回归验证

**执行记录**：每条用例标记执行结果（通过/失败/阻塞/跳过/不适用），记录实际结果、执行时间、执行人、环境版本

## 二、探索性测试

> 作为脚本测试的补充，利用测试人员的经验和直觉发现脚本未覆盖的问题

**探索性测试原则**：
- 有目的的探索：基于风险区域、复杂逻辑、变更频繁区域聚焦探索
- 时间盒（Time-box）：限定探索时间（如90分钟一个Session）
- 边测边设计边学习：测试设计、执行、学习同步进行
- 记录发现：探索中发现的问题及时记录并补充为正式用例

**探索性测试章程（Charter）模板**：

| 章程要素 | 内容 |
|---------|------|
| 探索目标 | 本次探索要验证的功能区域/风险点 |
| 探索范围 | 明确探索的边界（探索什么、不探索什么） |
| 时间盒 | 预计探索时长（通常60-120分钟） |
| 关注重点 | 基于风险评估的高风险区域 |
| 使用工具 | 辅助探索的工具（浏览器DevTools/抓包工具等） |
| 发现记录 | 探索中发现的问题、新用例、改进建议 |

**探索性测试适用场景**：
- 新功能首次验证（快速了解功能全貌）
- 复杂业务逻辑区域（发现设计盲区）
- 历史缺陷高发区域（补充边界场景）
- 用户交互密集区域（发现可用性问题）
- 回归测试补充（发现非预期副作用）

## 三、缺陷管理

**缺陷生命周期**：
```
新建(New) → 已分配(Assigned) → 处理中(In Progress) → 已修复(Fixed) →
待验证(Retest) → 已关闭(Closed)
                ↘ 重新打开(Reopened) ↗（验证未通过）
其他状态：拒绝(Rejected)、延期(Deferred)、重复(Duplicate)
```

**缺陷报告标准字段**：

| 字段 | 说明 |
|------|------|
| 缺陷编号 | 唯一标识，格式：BUG-{序号} |
| 标题 | 一句话描述问题 |
| 功能模块 | 所属功能模块 |
| 测试类型 | 功能/SIT/接口/非功能/安全 |
| 严重程度 | 致命/严重/一般/微小（测试视角的功能影响） |
| 优先级 | P0-P3（业务视角的修复紧急度） |
| 风险等级 | 极高/高/中/低（来自风险评估） |
| 复现步骤 | 编号步骤，含操作和数据 |
| 实际结果 | 实际发生的表现 |
| 预期结果 | 期望的正确表现 |
| 截图/日志 | 附件证据 |
| 环境 | 测试环境、浏览器、版本 |
| 状态 | 当前生命周期状态 |
| 发现人/修复人/验证人 | 责任人 |
| 关联用例 | 发现该缺陷的用例编号（RTM追溯） |

**缺陷严重程度 vs 优先级**：
- 严重程度（致命/严重/一般/微小）是测试视角的功能影响
- 优先级（P0-P3）是业务视角的修复紧急度
- 二者不总是正相关（如：一个严重程度低但影响核心流程的缺陷可能优先级高）

**缺陷度量指标**：

| 指标 | 定义/公式 | 目标值 |
|------|---------|--------|
| 缺陷密度 | 缺陷总数 / KLOC | 建立项目基线 |
| 缺陷修复率 | 已关闭缺陷 / 缺陷总数 × 100% | 严重+主要 100% |
| 缺陷逃逸率 | 生产缺陷 / 缺陷总数 × 100% | <=5% |
| 重新打开率 | 重新打开缺陷 / 已修复缺陷 | <=10% |
| 缺陷DI值 | 致命×10 + 严重×5 + 一般×2 + 微小×1 | 趋势下降 |
| 用例有效性 | 发现缺陷数 / 执行用例数 | 趋势稳定 |
| 平均修复时长 | 总修复时间 / 修复缺陷数 | 趋势下降 |
