# S-03：docx-requirement-review —— Word 需求评审技能

> 关联工具：T-07 docx_structure_extract · T-03 review_report_gen · T-04 defect_ledger_sync

## 1. 触发条件

用户表达「评审 docx」「评审 SRS」「Word 需求评审」时加载本技能。

## 2. 端到端流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  ① T-07      │    │  ② IEEE 830  │    │  ③ T-03      │    │  ④ T-04      │
│  结构提取     │───▶│  逐节检查     │───▶│  报告生成     │───▶│  台账同步     │
│  标题+段落+表格│    │  完整性/可测性│    │  CSV 落盘     │    │  缺陷登记     │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

### 步骤 1：提取文档结构（T-07）

```sh
python tools/docx_structure_extract.py --input srs.docx --output structure.json --format json
```

### 步骤 2：IEEE 830 逐节检查

按 IEEE 830 SRS 标准检查以下维度：

| 维度 | 检查内容 |
|---|---|
| 完整性 | 是否包含功能需求/非功能需求/接口/约束/数据 |
| 一致性 | 需求间是否矛盾（术语/数据流/接口） |
| 可测性 | 每个需求是否有可验证的验收标准 |
| 可追溯性 | 是否有需求编号 + 来源追溯 |

### 步骤 3：生成评审报告（T-03）

### 步骤 4：同步缺陷台账（T-04）

## 3. 质量门禁

- 完整性 ≥ 80% → 通过
- 可测性 ≥ 70% → 通过
- 严重不一致 → 驳回
