# S-06：review-recheck —— 评审复查技能

> 关联工具：T-06 xlsx_verify · T-03 review_report_gen · T-04 defect_ledger_sync

## 1. 触发条件

用户表达「复查」「修复确认」「回归检查」「重审」时加载本技能。

## 2. 端到端流程

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  ① 加载缺陷   │    │  ② T-06      │    │  ③ T-03      │    │  ④ T-04      │
│  原始清单     │───▶│  逐条验证     │───▶│  复查报告     │───▶│  台账更新     │
│  + 修复后文件  │    │  已修复/未修复 │    │  修复率统计   │    │  状态流转     │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

### 步骤 1：加载原始缺陷清单

读取上一轮评审发现的缺陷清单 JSON。

### 步骤 2：逐条验证（T-06）

```sh
python tools/xlsx_verify.py --input <修复后.xlsx> --defects <原始缺陷.json>
```

### 步骤 3：生成复查报告（T-03）

将验证结果组装为新的评审报告。

### 步骤 4：更新台账（T-04）

```sh
python tools/defect_ledger_sync.py --defects recheck_defects.json --ledger 台账/ --round 2
```

已修复 → 状态更新为「已关闭」；未修复 → 保持「新建」或升级为「重新打开」。

## 3. 质量门禁

- 修复率 = 100% → 复查通过，可进入下一阶段
- 修复率 ≥ 80% → 有条件通过，遗留缺陷需登记跟进
- 修复率 < 80% → 复查不通过，需继续修复
- 新增缺陷（修复引入）→ 单独登记，不影响本轮结论
