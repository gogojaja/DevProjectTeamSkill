## 环节 2：架构逻辑设计细节

### 2.1 4+1 视图设计

| 视图 | 关注点 | 设计内容 | UML 图表 |
|------|--------|----------|----------|
| **逻辑视图** | 系统做什么 | 领域模型、功能分解、类/包结构 | 类图、包图、对象图 |
| **进程视图** | 运行时行为 | 并发/线程/进程通信、同步机制 | 活动图、序列图、通信图 |
| **开发视图** | 代码组织 | 模块分层、包结构、构建依赖 | 组件图、包图 |
| **物理视图** | 部署拓扑 | 服务器/网络/节点映射、部署架构 | 部署图 |
| **场景视图（+1）** | 验证一致性 | 关键用例场景贯穿四视图验证 | 用例图、序列图 |

### 2.2 C4 模型分层设计

| 层级 | 抽象度 | 受众 | 设计内容 |
|------|--------|------|----------|
| **Context（系统上下文）** | 最高 | 业务方/管理层 | 系统整体与外部实体（用户/系统/服务）的关系 |
| **Container（容器）** | 高 | 架构师/技术负责人 | 应用、服务、数据库、消息队列等容器级组件及其交互 |
| **Component（组件）** | 中 | 开发工程师 | 容器内组件划分、职责、接口、依赖 |
| **Code（代码）** | 低 | 开发工程师 | 包/目录结构、命名规范、代码组织（可选，按需） |

### 2.3 组件设计

| 设计项 | 内容 |
|--------|------|
| 组件职责 | 每个组件的单一职责定义 |
| 组件接口 | 对外接口契约（输入/输出/异常） |
| 组件依赖 | 依赖关系图（方向性，避免循环依赖） |
| 组件生命周期 | 创建/初始化/运行/销毁流程 |
| 组件通信 | 同步/异步、协议、数据格式 |

### 2.4 接口设计

| 设计项 | 内容 |
|--------|------|
| API 契约 | REST/RPC/gRPC 接口定义 |
| 版本管理 | API 版本策略（URL/Header/SemVer） |
| 错误码规范 | 统一错误码体系、错误响应格式 |
| 认证授权 | 接口认证机制（OAuth2/JWT/API Key） |
| 限流熔断 | 接口级限流策略、熔断降级规则 |

### 2.5 部署设计

| 设计项 | 内容 |
|--------|------|
| 部署拓扑 | 物理/虚拟节点映射、网络分区 |
| 平台抽象 | 平台差异抽象层、容器化（Docker/K8s） |
| 配置外部化 | 环境配置外置化、12-Factor 适配 |
| 无状态化 | 无状态设计、会话外置、标准化接口 |
| 可移植性 | 部署环境切换成本、数据可迁移 |

### 2.7 七原则落地检查

逐条验证设计方案是否满足七大设计原则，输出《七原则合规检查表》：

| 原则 | 检查项 | 检查结果 | 佐证 |
|------|--------|----------|------|
| 成熟性 | 技术栈是否为 LTS 版本？是否有生产案例？ | ✅/❌ | 具体案例 |
| 稳定性 | 是否有冗余设计？故障隔离方案？ | ✅/❌ | 架构图引用 |
| 安全性 | STRIDE 是否全覆盖？认证授权方案？（转 data-security） | ✅/❌ | 安全设计章节 |
| 高效性 | 性能预算是否制定？异步/缓存方案？ | ✅/❌ | 性能设计章节 |
| 便捷性 | 分层是否清晰？模块职责单一？ | ✅/❌ | 开发视图 |
| 跨平台性 | 是否抽象平台差异？避免厂商锁定？ | ✅/❌ | 物理视图 |
| 可移植性 | 配置是否外部化？无状态化？12-Factor？ | ✅/❌ | 部署设计 |
