# 方案制定流程规则

## 方案复杂度分级

| 级别 | 判定条件 | 必选步骤 | 可选步骤 |
|------|----------|----------|----------|
| 简单 | 变更 <=3 文件 + 无跨项目影响 | Step 1-4 | Step 5-8 可跳过 |
| 标准 | 变更 4-10 文件 或 单项目内多模块 | Step 1-6 | Step 7-8 按需 |
| 复杂 | 跨项目 或 变更 >10 文件 | Step 1-8 全部 | 无 |

## 判定流程

```
用户提出方案需求
    ↓
Q1: 是否跨项目（涉及 2+ 个独立仓库）？
    ├─ 是 → 复杂方案
    └─ 否 → Q2
Q2: 变更文件数 > 10？
    ├─ 是 → 复杂方案
    └─ 否 → Q3
Q3: 变更文件数 > 3？
    ├─ 是 → 标准方案
    └─ 否 → 简单方案
```

## 路由规则

| 方案类型 | 路由目标 |
|----------|----------|
| 技术选型/架构决策 | `best-practice-solution` |
| 项目级实施方案 | `plan-creation`（本子技能） |
| 测试方案 | `role-testing` → `write_plan` |
| 发布方案 | `role-deployment` → `write_plan` |
| 架构设计 | `role-architecture` |
| 咨询方案 | `role-mgmt-consulting` → `design_solution` |

## 版本命名规则

| 阶段 | 版本格式 | 示例 |
|------|----------|------|
| 草案 | v0.x | v0.1, v0.2 |
| 评审修订 | v0.x+1 | v0.2 → v0.3 |
| 基线定稿 | v1.0 | v1.0 |
| 重大变更 | v{N+1}.0 | v2.0 |
| 小幅修订 | v{N}.{M+1} | v1.1 |

## 交付物命名规则

| 文档 | 命名 | 示例 |
|------|------|------|
| 技术方案 | `{方案名}方案.md` | `自动化任务扩展方案.md` |
| 执行计划 | `{方案名}_执行计划.md` | `自动化任务扩展_执行计划.md` |
| 评审报告 | `{方案名}_评审报告.md` | `自动化任务扩展_评审报告.md` |

## 变更控制规则

基线化后的任何修改必须：
1. 填写变更请求（变更内容 + 原因 + 影响分析）
2. 评估对范围/进度/成本/质量的影响
3. 获批后更新版本号（v1.0 → v1.1 或 v2.0）
4. 在方案文档末尾记录变更历史

## 复盘模板（AAR）

```markdown
## 经验教训 — {方案名}

### 计划
- 我们计划做什么？
- 预期成果是什么？

### 实际
- 实际完成了什么？
- 与计划有什么偏差？

### 差异分析
- 为什么有差异？
- 根因是什么？

### 改进
- 下次应该怎么做？
- 哪些做法应该固化？
- 哪些做法应该避免？
```
