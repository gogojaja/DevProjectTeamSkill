# 风险协同与问题升级（Coordination & Escalation）

> 所属技能：`risk-mgmt` v1.0.0 · 标准：`references/raid_standard.md` §7-§8

## 1. 问题分级（P1~P4）

启动阶段 `role-project-init` 的 `define_issue_escalation` 确立分级，本技能承接巡检期升级执行（写入 `12_风险问题台账.csv` 优先级字段）：

| 级别 | 定义 | 示例 | 响应时限 |
|------|------|------|----------|
| P1 阻断 | 项目无法推进/主流程不可用/数据丢失 | 生产阻断、关键链路宕机、范围致命冲突 | ≤ 4h |
| P2 高 | 关键功能受阻/里程碑延期风险 | 核心接口不可用、依赖缺失、资源冲突未决 | ≤ 1 个工作日 |
| P3 中 | 局部功能受影响/可绕行 | 非核心缺陷、进度轻微滞后 | ≤ 3 个工作日 |
| P4 低 | 一般性问题/优化建议 | 文档缺失、体验优化 | 记录即可 |

> 风险分（概率×影响）自动映射 P1~P4（见 `scan.md`）；issue 类可另按上表业务影响定级。

## 2. 升级阶梯（四级路径）

| 级别 | 处理主体 | 职责 | 响应时限 |
|------|----------|------|----------|
| L1 | 项目团队（Owner） | 识别问题、记录台账、尝试解决 | 问题发生时 |
| L2 | 项目经理 | 分析决策、资源调配、跨团队协调 | P1/P2 即时、P3 ≤ 1 工作日 |
| L3 | 指导委员会/项目委员会 | 决策仲裁、范围/预算/优先级裁决 | P1 ≤ 1 个工作日 |
| L4 | 高层/Sponsor | 战略干预、资源追加、终止决策 | 按治理节奏 |

**升级规则**：
- **单一 Owner 原则**：每条问题唯一 Owner（对齐 RACI 唯一 A），Owner 缺失不得升级，路径清晰可追溯。
- **升级条件**：超过本级响应时限未决 / 超出本级权限（预算·范围·人员）/ 多干系人冲突无法裁决。
- **协同**：P1/P2 升级与 multi-perspective-validation 的 P0~P6 仲裁、`change_audit` 变更审计衔接；升级不经审批链外绕过，全程留痕至台账（涉高危操作另记 `13_安全审计台账.csv`）。
- **关闭**：问题处理完成须记解决动作与验证结果，Owner 确认后 `close`，关闭记录在阶段评审复核。

## 3. 风险与变更协同

| 变更来源 | 协同动作 | 委派 |
|----------|----------|------|
| 需求/范围变更 | 同步评估风险影响，重大变更后重新识别风险 | `scope-tracking` 变更生命周期 |
| 架构变更 | 同步更新风险登记册（技术风险重估） | `role-architecture` 协同 |
| 进度/成本偏差 | 延期/超支风险联动登记（SPI/CPI<0.9 触发） | `schedule-cost` EVM 预警 |
| 资源冲突 | 资源不足风险登记与平衡 | `resource-ops` |

- 重大变更后**必须**重新 `scan` 识别新风险；风险升级为重大问题 → 按 §2 升级阶梯推送人工决策。
- `scan --json` 输出供 MCP `risk_scan`/PMO 仪表盘消费，跨项目风险升级归 `role-program-mgmt`。

## 4. 人工决策门槛

- **P1 阻断问题**（≤4h）→ 强制升级 L2/L3，不可停留 L1。
- **连续 2 次延期/风险失控** → 停止 AI 自动调整，推送人工决策（L3 指导委员会）。
- 超本级权限（预算/范围/人员）→ 升级 L3 仲裁；战略级 → L4 Sponsor。

**DoD**：变更风险已评估 · 升级问题已推送对应层级 · 单一 Owner 已明确 · 升级/关闭全程留痕。

> 边界：本环节做升级与变更协同；登记册见 `register-init.md`；分级扫描见 `scan.md`；应对策略见 `response.md`。
