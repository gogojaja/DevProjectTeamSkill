# 进度成本基准建立（Schedule & Cost Baseline）

> 所属技能：`schedule-cost` v1.0.0 · 标准：`references/evm_standard.md` §1-§2

## 1. 进度基准（03_进度基准.csv）

进度基准是 EVM 的计划侧锚点，项目初始化时建立，任务分解至可跟踪粒度。

| 要素 | 说明 | 台账列（防御式别名） |
|------|------|---------------------|
| 阶段划分 | 启动/需求/架构/开发/测试/投产 等阶段序列 | 阶段 |
| 里程碑清单 | 每阶段可验证的交付节点（编号唯一，不复用） | 里程碑编号 / 里程碑名称 |
| 任务拆解 | 里程碑下的工作包（WBS 叶节点，可跟踪粒度） | 任务拆解 |
| 工期 | 计划开始·完成日期（YYYY-MM-DD） | 计划开始 / 计划日期 |
| 依赖关系 | 里程碑间 FS/SS 依赖（关键路径判定输入） | 依赖关系 |

**规则**：
- 基准在项目初始化时建立；里程碑编号 `M<n>` 唯一不复用。
- 计划完成日期是准点率判定与时间进度比 AC 估算的锚点，必填。
- 关键路径里程碑（依赖链最长）优先保障，延期直接传导总工期。

## 2. 成本基准（04_成本基准.csv）

成本基准提供 BAC（Budget at Completion，完工预算），是 PV 的价值来源。

| 要素 | 说明 | 台账列（防御式别名） |
|------|------|---------------------|
| 人力工时预估 | 各里程碑/工作包的预估工时 | 人力工时预估 / 预估工时 |
| 成本阈值 | 完工预算 BAC（总成本基线） | 成本阈值 / 预算 / BAC |
| 超支标准 | 触发超支预警的偏差阈值（如 10%） | 超支标准 |

**BAC 与 PV 的关系**：
- 若里程碑显式声明 `计划值`（PV），则 PV = Σ 各里程碑计划值（推荐，精确到里程碑）。
- 若里程碑未声明计划值，`evm_ops.py` 回退按 BAC 均摊：`pv_i = BAC / 里程碑数`。
- BAC 亦缺失时，回退默认 `pv_i = 1.0`（保证 CPI/SPI 比值仍可计算，绝对值仅供参考）。

## 3. 基准 → 台账落地（evm_ops.py）

```bash
# 登记里程碑（写入 09_进度跟踪台账.csv，含计划值 PV）
python3 tools/evm_ops.py add-milestone --id M1 --name "需求基线" \
       --start 2026-09-01 --end 2026-09-30 --value 1000
```

- `add-milestone` 写入 `09_进度跟踪台账.csv`：里程碑编号/名称/计划开始/计划日期/计划值/状态(默认未开始)/更新日期。
- 重复 ID 拒绝（rc1），防重复登记污染 PV。
- 既有台账若为差异 schema，沿用既有表头追加（防御式，非破坏）。

**DoD**：进度基准（03）写入完成 · 成本基准（04）写入完成 · 里程碑（09）登记且计划值明确。

> 边界：本环节仅建基准与登记里程碑；里程碑状态更新与 EVM 计算见 `milestone-evm.md`；基准调整须走变更审批（委派 `scope-tracking` 变更生命周期）。
