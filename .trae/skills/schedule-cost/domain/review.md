# 进度成本周期复盘与偏差纠偏（Review & Corrective Action）

> 所属技能：`schedule-cost` v1.0.0 · 标准：`references/evm_standard.md` §7、§9

## 1. 复盘触发时机

| 时机 | 动作 | 主命令 |
|------|------|--------|
| 阶段边界评审（PRINCE2） | EVM 绩效作为流转裁决依据 | `calc` |
| 周期例会（周/迭代） | 进度成本趋势 + 偏差识别 | `status` · `calc` |
| 严重偏差告警 | 立即纠偏分析 | `calc --json` |
| 里程碑连续延期 | 升级人工决策 | `status` + 人工研判 |

## 2. 偏差分析（calc --json 结构化）

```bash
python3 tools/evm_ops.py calc --json   # 供 MCP evm_analyze / PMO 仪表盘消费
```

复盘须回答四问：
1. **进度**：SPI 是否 < 1？SV 负多少？哪些里程碑延期（准点率）？
2. **成本**：CPI 是否 < 1？CV 负多少？AC 是实测还是估算（看 `ac_source`）？
3. **趋势**：CPI/SPI 较上期改善还是恶化？
4. **根因**：偏差来自基准不合理、执行低效、还是外部依赖阻塞？

> AC 为「时间进度比估算」时，CPI 仅供参考，复盘须优先补齐 10 成本消耗台账后重算。

## 3. 纠偏方案（按健康判定分级）

| 健康判定 | 处置 |
|----------|------|
| ✅ 健康（CPI≥1.0 且 SPI≥1.0） | 保持，记录良好实践 |
| ⚠️ 轻度偏差（≥0.9） | 关注 + 制定改进项，限期复核，不停流转 |
| ❗ 严重偏差（<0.9） | 强制纠偏方案 + 阶段流转门禁驳回，直至回到容忍带 |

纠偏手段（择一或组合）：
- **进度滞后（SPI<1）**：关键路径赶工/快速跟进、资源增援（委派 `resource-ops`）、范围裁剪（委派 `scope-tracking` 变更审批）。
- **成本超支（CPI<1）**：成本动因分析、资源效率优化、重新估算 EAC。
- 纠偏措施触及基准（PV/BAC/计划日期）→ 走变更审批，禁止逆向修基准。

## 4. 人工决策升级门槛

- **连续 2 次延期/超支** → 停止 AI 自动调整计划，强制推送人工决策（升级至项目经理/PMO）。
- 严重偏差无可行纠偏方案 → 升级阶段边界评审，研判继续/重规划/终止（PRINCE2）。
- 决策留痕：偏差事实 + 纠偏方案 + 决策人 + 复核期限。

## 5. 复盘产出

- **进度成本复盘报告**：EVM 绩效卡（PV/EV/AC/CPI/SPI/CV/SV/准点率）+ 健康判定 + 偏差分析 + 纠偏方案 + 人工决策记录。
- **交接对象**：role-governance（阶段评审门禁 EVM 口径）、role-project-mgmt（日常管控）、MCP `evm_analyze`（PMO 仪表盘）、role-program-mgmt（跨项目 CPI/SPI/准点率统一度量口径）。

**DoD**：EVM 绩效已算 · 偏差已分析 · 健康判定已裁决 · 纠偏方案已定（或偏差已消除）· 连续延期已升级人工决策 · 复盘报告留痕。

> 边界：本环节做复盘与纠偏裁决；里程碑更新与 EVM 计算见 `milestone-evm.md`；范围裁剪委派 `scope-tracking`、资源平衡委派 `resource-ops`、风险联动委派 `risk-mgmt`。
