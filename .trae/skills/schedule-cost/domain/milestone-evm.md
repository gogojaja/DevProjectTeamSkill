# 里程碑更新与挣值分析（Milestone Update & EVM）

> 所属技能：`schedule-cost` v1.0.0 · 标准：`references/evm_standard.md` §5-§7

## 1. 里程碑状态更新（09_进度跟踪台账）

里程碑是 EV 的客观挣值事件（0/100 规则）：达成即计全额计划值，未达成计 0。执行期持续推进状态。

```bash
# 更新状态/完成率/实际完成日（已完成自动补实际完成日）
python3 tools/evm_ops.py update-milestone --id M1 --status 已完成 [--actual-end 2026-09-28] [--completion 100]
```

| 状态 | 含义 | EV 计法 |
|------|------|---------|
| 未开始 | 尚未启动 | 0 |
| 进行中 | 执行中（可记完成率供参考） | 0（未达里程碑） |
| 已完成 | 交付节点达成（终态） | 全额计划值 PV |
| 延期 | 超计划完成日未达成 | 0，记偏差责任到人 |

**规则**：
- 「已完成」判定含 `已完成/完成/已交付/done/closed/complete`（大小写不敏感）。
- 置为已完成且未填实际完成日 → 自动补当天日期（准点判定输入）。
- 里程碑不存在 → rc1；09 台账为空 → rc1（先 `add-milestone`）。
- 完成率（`任务完成率`）仅供人工参考，**不参与 EV 计算**（EV 严格 0/100）。

## 2. 工时成本记录（10_成本消耗台账）

AC（实际成本）主源为 `10_成本消耗台账.csv`。执行期将工时消耗/资源成本/工具成本记入台账。

| AC 取值优先级 | 来源 | ac_source 标注 |
|---------------|------|----------------|
| 1 | `累计消耗` 列最大值（别名 累计成本/cumulative） | 台账10_成本消耗 |
| 2 | `Σ(资源成本 + 工具成本)` | 台账10_成本消耗 |
| 3（回退） | 时间进度比估算：`Σ pv_i × clamp((today−start)/(end−start),0,1)` | 时间进度比估算 |

> 回退估算用于台账缺数据的过渡期，`calc` 输出显式标注 `ac_source`，提示 AC 为估算非实测（复盘须谨慎解读 CPI）。

## 3. EVM 挣值分析（calc）

```bash
python3 tools/evm_ops.py calc [--milestone M1] [--json]
```

**核心公式**（详见 `references/evm_standard.md` §6）：

| 指标 | 公式 | 判读 |
|------|------|------|
| PV | Σ 全部里程碑计划值 | 计划应完成价值 |
| EV | Σ 已完成里程碑计划值（0/100） | 实际已挣价值 |
| AC | 台账实际成本 / 时间进度比回退 | 实际已花成本 |
| CPI | EV / AC | >1 节约，<1 超支 |
| SPI | EV / PV | >1 超前，<1 滞后 |
| CV | EV − AC | >0 节约，<0 超支 |
| SV | EV − PV | >0 超前，<0 滞后 |
| 准点率 | 准点完成数 / 总数 | 实际完成日 ≤ 计划完成日 |

## 4. 健康判定（CPI/SPI 双维）

| 判定 | 条件 |
|------|------|
| ✅ 健康 | CPI ≥ 1.0 且 SPI ≥ 1.0 |
| ⚠️ 轻度偏差 | CPI ≥ 0.9 且 SPI ≥ 0.9（未达健康） |
| ❗ 严重偏差 | CPI < 0.9 或 SPI < 0.9 |

- CPI<1.0 → `[WARN] 成本超支`；SPI<1.0 → `[WARN] 进度滞后`。
- 严重偏差须转 `review.md` 纠偏；连续 2 次延期/超支停止 AI 自动调整，推送人工决策。
