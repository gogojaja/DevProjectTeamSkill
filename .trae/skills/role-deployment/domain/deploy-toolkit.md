## 1. 部署脚本规范

所有部署脚本必须满足（对齐 tool_calling_standard.md）：

| 规范 | 要求 | 反例 |
|------|------|------|
| ROOT 解析 | `os.environ.get("PROJECT_ROOT", __file__兜底)`，禁止硬编码绝对路径 | `open("/home/user/app/config")` |
| 无副作用模式 | 必须提供 `--dry-run` 预览 | 直接执行不可逆操作 |
| 幂等性 | 重复执行结果一致（先检查后执行） | 无脑 append 配置 |
| 退出码 | 0=成功 / 1=失败 / 2=跳过（熔断） | 全部 exit 0 |
| 可观测 | 关键步骤回显 + 失败原因明确 | 静默失败 |
| 双实现 | `.sh`（macOS/Linux）+ `.py`（跨平台）功能一致 | 单平台脚本 |

## 2. 部署前环境检查清单

发布执行（`execute_release`）前强制核对：

- [ ] 目标环境组确认（非生产组/生产组，生产组独立隔离）
- [ ] 端口/独占资产可用（查 20_环境配置 + CMDB）
- [ ] 回滚预案已随发布计划编写（铁律：回滚预案必须随计划）
- [ ] 部署脚本 `--dry-run` 预览通过
- [ ] 配置差异已确认（密钥仅别名，A 级不入库）
- [ ] 监控三支柱就绪（DORA/SRE：指标/日志/追踪）
- [ ] 变更分级审批已过（`change_audit`）

## 3. 回滚演练工具化

| 演练类型 | 频率 | 方法 | 验收 |
|----------|------|------|------|
| 脚本回滚演练 | 每次重大发布前 | 测试环境执行 `rollback --dry-run` → 真回滚一次 | 数据还原验证通过 |
| 数据还原演练 | 季度 | 备份恢复至隔离环境比对 | 差异为零 |
| 切换演练（蓝绿） | 架构变更时 | 流量切换 + 切回 | 双向往返无异常 |

演练结果登记发布台账；**未演练的回滚预案视为无效预案**（Go-Live 门禁驳回）。

## 5. 独立化评估触发条件（先技能后评估）

满足任一条件时启动独立评估（走孵化器 `incubator-initiation`）：
1. 部署工具代码量 >2000 行且与本库发布流程解耦
2. ≥3 个外部项目需要复用部署工具链
3. 工具演进节奏与技能库发布节奏冲突

## 闭环执行系统

### 1. 任务入口
- 输入：编写/评审部署脚本、发布前检查、回滚演练
- 前置：发布计划已批准、回滚预案已编写

### 2. 执行状态
待检查 → 检查中 → 通过/驳回 → 演练完成

### 3. 验收门禁
- 脚本规范（§1）全过；检查清单（§2）全过；回滚演练（§3）有记录

### 4. 失败处理
- 检查项缺失 → 驳回至发布准备；演练失败 → 修订回滚预案后重演

### 5. 产出与交接
- 检查清单记录 + 演练报告（CSV）→ 发布台账

### 6. 审计记录
- 发布/回滚/演练一律 `change_audit` + 13 台账（四维定位）
