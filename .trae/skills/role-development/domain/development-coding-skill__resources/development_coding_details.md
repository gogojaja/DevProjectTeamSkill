## 环节 3：代码开发细节

### 3.1 模块实现规范

| 实现项 | 规范要求 | 禁止项 |
|--------|----------|--------|
| 代码结构 | 按分层架构组织（Controller/Service/DAO） | 跨层直接访问数据源 |
| 命名 | 语义化命名、缩写需在注释中说明 | 拼音缩写、魔法数字裸用 |
| 函数设计 | 单一职责、参数 ≤ 4 个、行数控制 | 超长函数、深层嵌套 |
| 类型处理 | 显式类型、空值防护 | 隐式类型转换、忽略空值 |
| 异常处理 | 统一异常体系、异常携带上下文 | 空 catch、吞异常、泄露堆栈 |
| 日志 | 分级日志、关键路径打点、敏感信息脱敏 | 打印密码/Token、无级别日志 |

### 3.2 注释规范

| 注释类型 | 要求 | 示例 |
|----------|------|------|
| 文件头 | 版权、功能说明、作者、日期 | `# Copyright (c) 2026` |
| 类/模块 | 职责说明、使用方式 | Docstring / Javadoc |
| 函数 | 参数、返回值、异常说明 | `:param` / `@param` / `@return` |
| 复杂逻辑 | 关键算法、业务规则说明 | 行内注释 |
| TODO | 标注未完成事项及负责人 | `TODO(owner): desc` |

### 3.3 API 实现规范

| API 项 | 规范 |
|--------|------|
| REST 风格 | 资源命名（复数名词）、HTTP 方法语义正确 |
| 状态码 | 正确使用 2xx/4xx/5xx，业务错误用 4xx |
| 响应结构 | 统一响应包装（code/message/data） |
| 参数校验 | 入参校验、长度/格式/边界验证 |
| 版本控制 | URL 版本前缀 `/v1/` 或 Header 版本 |

### 3.4 数据库操作规范

| 操作项 | 规范要求 |
|--------|----------|
| SQL 注入 | 参数化查询（PreparedStatement）、禁止字符串拼接 |
| 事务 | 明确事务边界、使用声明式事务 |
| 索引 | 查询字段建索引、避免全表扫描 |
| 分页 | 使用 LIMIT/OFFSET 或游标分页 |
| 连接池 | 合理配置连接池大小、及时释放 |

### 3.5 安全编码要求（OWASP ASVS 落地）

| ASVS 要求 | 编码实现 |
|-----------|----------|
| V5 输入验证 | 白名单校验、参数化查询、文件上传白名单 |
| V2 身份认证 | 密码加盐哈希（bcrypt/argon2）、登录限速 |
| V6 密码学 | 使用标准库加密算法、密钥不硬编码 |
| V7 错误处理 | 统一错误码、不返回内部堆栈 |
| V8 数据保护 | 传输 TLS、存储加密、日志脱敏 |
| V12 文件操作 | 路径规范化、文件类型白名单 |
| V13 API 安全 | 速率限制、认证中间件、超时配置 |

### 3.6 编码强制规则（七原则落地）

| 规则 | 执行要求 |
|------|----------|
| 编码规范 | 提交前 `linter` 通过、`formatter` 格式化 |
| 测试先行 | TDD：先写失败测试，再实现，再重构 |
| 安全编码 | 实现 ASVS 映射清单对应项 |
| 代码审查 | 提交 PR 前自审、走查清单自查 |
| 持续集成 | 提交触发构建、通过后合并 |
| 质量门禁 | 静态分析无阻断级问题 |
| 文档同步 | 关键接口、配置变更同步文档 |

### 3.7 编码完成自检清单

- [ ] 代码通过 linter/formatter 检查
- [ ] 单元测试通过且覆盖率达标
- [ ] 无阻断级静态分析问题
- [ ] ASVS 映射项已实现
- [ ] 关键逻辑有注释、无遗留 TODO（业务阻塞项除外）
- [ ] 变更已同步开发追溯矩阵
