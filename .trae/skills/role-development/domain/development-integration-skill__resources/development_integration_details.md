## 环节 6：系统联调细节（System Integration）

### 6.1 联调策略制定

**联调层次（自底向上）**：

| 层次 | 内容 | 验证点 |
|------|------|--------|
| L1 单模块内部 | 模块内函数/类协作 | 模块内部逻辑一致性 |
| L2 模块间接口 | 模块间 API/服务调用 | 接口契约符合性、参数/返回一致性 |
| L3 跨服务集成 | 微服务间调用链 | 服务发现、负载均衡、熔断降级 |
| L4 端到端链路 | 全链路业务场景 | 业务全流程正确性、数据一致性 |
| L5 外部系统 | 第三方/遗留系统对接 | 外部依赖契约、容错与降级 |

### 6.2 联调准备

| 准备项 | 内容 |
|--------|------|
| 联调环境 | 集成环境搭建（staging）、数据初始化 |
| 接口清单 | 参与联调的接口列表（含依赖关系） |
| 联调数据 | 场景化测试数据准备 |
| 桩服务 | 未就绪依赖的 Mock/Stub 服务 |
| 联调计划 | 联调顺序、负责人、时间窗口 |

### 6.3 联调用例设计

| 用例类型 | 内容 |
|----------|------|
| 接口契约用例 | 入参/出参/异常符合接口文档 |
| 链路场景用例 | 端到端业务场景（主流程/分支流程） |
| 异常场景用例 | 超时、重试、熔断、降级、幂等 |
| 并发场景用例 | 并发提交、锁竞争、冲突处理 |
| 数据一致性用例 | 事务边界、最终一致性、补偿 |

### 6.4 联调执行与缺陷管理

| 环节 | 内容 |
|------|------|
| 执行 | 按联调计划逐项执行联调用例 |
| 缺陷记录 | 记录缺陷（模块/接口/复现步骤/严重度） |
| 缺陷定界 | 定位缺陷所属模块与责任方 |
| 缺陷修复 | 责任方修复、更新单元测试 |
| 回归联调 | 缺陷修复后重跑受影响链路 |

### 6.5 联调完成标准

- 全部联调用例执行完毕（通过/失败有明确记录）
- 阻断级缺陷 0 遗留
- 接口契约一致性确认（全部接口通过契约校验）
- 关键端到端链路 100% 通过
- 联调报告生成（场景、缺陷、遗留问题清单）

## 环节 7：代码质量检查细节（Quality Check）

### 7.1 静态代码分析

| 分析项 | 工具示例 | 检查内容 |
|--------|----------|----------|
| 代码规范 | pylint / eslint / checkstyle | 命名、格式、结构 |
| 代码异味 | SonarQube | 重复代码、过长函数、过深嵌套 |
| 潜在缺陷 | SonarQube / PMD | 空指针、资源泄漏、并发问题 |
| 代码复杂度 | SonarQube / lizard | 圈复杂度、认知复杂度 |

### 7.2 代码安全扫描（SAST）

| 扫描项 | 工具示例 | 检查内容 |
|--------|----------|----------|
| 注入漏洞 | Bandit / Semgrep | SQL 注入、命令注入、LDAP 注入 |
| 敏感信息 | git-secrets / truffleHog | 硬编码密钥、密码、token |
| 不安全函数 | Bandit | 危险函数调用（eval、exec） |
| 加密问题 | SonarQube Security | 弱加密算法、硬编码 IV |
| XSS/CSRF | ESLint Security | 不安全的 DOM 操作 |

### 7.3 依赖安全扫描（SCA）

| 扫描项 | 工具示例 | 检查内容 |
|--------|----------|----------|
| 已知漏洞 | Snyk / OWASP Dependency-Check | 依赖包已知 CVE |
| 许可证合规 | FOSSA / ScanCode | 开源许可证合规性 |
| 过期依赖 | Dependabot / Renovate | 依赖版本更新提示 |

### 7.4 代码复杂度检查

| 指标 | 目标值 | 门禁标准 |
|------|--------|----------|
| 圈复杂度 | <= 15 | > 15 → 门禁驳回 |
| 认知复杂度 | <= 10 | > 10 → 门禁驳回 |
| 函数行数 | <= 50 行 | > 50 → 警告 |
| 类行数 | <= 300 行 | > 300 → 警告 |
| 文件行数 | <= 500 行 | > 500 → 门禁驳回 |

### 7.5 技术债务评估

| 债务类型 | 评估方法 |
|----------|----------|
| 代码异味 | SonarQube Code Smells 统计 |
| 重复代码 | 重复块数、重复行数 |
| 过时依赖 | 过期依赖数量 |
| 未处理 TODO | TODO/FIXME/HACK 注释统计 |
| 测试债务 | 未测试代码、测试覆盖率缺口 |

### 7.6 代码质量门禁标准

| 检查项 | 目标 | 门禁 |
|--------|------|------|
| 阻断（Blocker）问题 | 0 | > 0 → 门禁驳回 |
| 严重（Critical）问题 | 0 | > 0 → 门禁驳回 |
| 主要（Major）问题 | <= 5 | > 5 → 门禁驳回 |
| 圈复杂度 | <= 15 | > 15 → 门禁驳回 |
| 重复代码率 | < 3% | >= 3% → 门禁驳回 |
| 安全漏洞（高危） | 0 | > 0 → 门禁驳回 |
| 依赖漏洞（高危） | 0 | > 0 → 门禁驳回 |
| 行覆盖率 | >= 80% | < 80% → 门禁驳回 |
| PR 审查 | 至少 1 人通过 | 未通过 → 门禁驳回 |

## 环节 8：开发总结与基线固化细节（Baseline & Summary）

### 8.1 开发总结报告（8 章）

| 章节 | 内容 |
|------|------|
| 1. 开发概况 | 项目信息、开发周期、参与人员 |
| 2. 代码统计 | 代码行数、文件数、模块数、提交次数 |
| 3. 质量指标 | 覆盖率、复杂度、重复率、问题统计 |
| 4. 安全指标 | SAST/SCA 扫描结果、漏洞修复情况 |
| 5. 技术债务 | 债务清单、清偿计划、优先级 |
| 6. 变更记录 | 需求变更、架构变更、代码变更记录 |
| 7. 经验教训 | 问题、解决方案、改进建议 |
| 8. 资产清单 | 全部开发产出物清单 |

### 8.2 开发追溯矩阵建立

| 需求编号 | 模块 | 文件 | 函数 | 测试用例 | 覆盖率 |
|----------|------|------|------|----------|--------|
| REQ-FUNC-001 | AuthModule | auth.py | login() | test_login | 100% |
| REQ-FUNC-002 | OrderModule | order.py | create_order() | test_create_order | 85% |

写入 ProjectMonitorSkill 主台账「开发追溯矩阵」Sheet。

### 8.3 对接 ProjectMonitorSkill

- `stage_review`：开发阶段评审（五维度 + 范围跟踪检查）
- `check_gate`：开发阶段门禁校验（含专项）
- `stage_close`：开发基线固化（备份 + 更新版本 + 产出物清单）

## 环节 9：开发变更分析细节（Change Analysis）

### 9.1 影响评估

| 维度 | 评估内容 |
|------|----------|
| 需求影响 | 是否涉及需求变更 |
| 架构影响 | 是否涉及架构调整 |
| 模块影响 | 受影响的模块列表 |
| 接口影响 | 受影响的接口契约 |
| 测试影响 | 受影响的测试用例 |
| 安全影响 | 是否引入新的安全风险 |
| 质量影响 | 对覆盖率/复杂度的影响 |

### 9.2 变更流程

```
提出代码变更 → 影响评估 → ProjectMonitorSkill change_audit → 用户审批 → 
更新代码 → 更新单元测试 → 重新质量检查 → 更新追溯矩阵 → 重新固化基线
```
