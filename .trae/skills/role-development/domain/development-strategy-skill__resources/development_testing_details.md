## 环节：单元测试细节（Unit Testing）

### 1. 单元测试用例编写（TDD 模式）

| TDD 阶段 | 执行内容 |
|----------|----------|
| Red | 编写失败的测试用例（定义期望行为） |
| Green | 编写最小代码使测试通过 |
| Refactor | 重构代码，保持测试通过 |

**测试用例设计方法**：

| 方法 | 应用场景 |
|------|----------|
| 等价类划分 | 输入范围测试 |
| 边界值分析 | 边界条件测试 |
| 错误推测 | 常见错误场景测试 |
| 路径覆盖 | 逻辑分支测试 |
| 状态迁移 | 状态机测试 |

### 2. 测试覆盖率目标

| 指标 | 目标值 | 门禁标准 |
|------|--------|----------|
| 行覆盖率 | >= 80% | < 80% → 门禁驳回 |
| 分支覆盖率 | >= 70% | < 70% → 门禁驳回 |
| 函数覆盖率 | >= 90% | < 90% → 门禁驳回 |
| 关键路径覆盖率 | 100% | < 100% → 门禁驳回 |

### 3. Mock/Stub 配置

| 隔离对象 | Mock 方法 |
|----------|-----------|
| 外部 API | HTTP Mock Server / responses mock |
| 数据库 | 内存数据库 / mock repository |
| 消息队列 | mock producer/consumer |
| 文件系统 | mock filesystem / temp dir |
| 时间 | mock datetime / freezegun |

### 4. 自动化测试执行

| 执行场景 | 触发方式 |
|----------|----------|
| 本地开发 | 保存自动触发 / 手动执行 pytest |
| 提交前 | Git Hook 自动执行 |
| CI 流水线 | 每次 push/PR 自动执行 |

### 5. 回归测试

| 执行时机 | 内容 |
|----------|------|
| 每次功能新增 | 全量单元测试执行 |
| 每次重构 | 全量单元测试执行 |
| 每次 bug 修复 | 新增回归测试 + 全量执行 |
