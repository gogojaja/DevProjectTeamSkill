## 环节 4：代码走查（Code Walkthrough）

### 4.1 走查流程（基于 Fagan Inspection 方法论）

```
开发者自审 → 走查清单自查（逐项核对） → 走查会议/异步走查 → 
记录发现项（问题类型/严重度） → 问题修复 → 复走查 → 走查通过
```

| 阶段 | 执行内容 | 产出 |
|------|----------|------|
| 计划 | 确定走查范围、参与者、角色（作者/走查员/记录员） | 走查计划 |
| 准备 | 走查员独立阅读代码，标记问题 | 走查问题预清单 |
| 会议 | 逐模块走读，记录问题（不讨论解决方案） | 走查记录表 |
| 修复 | 作者修复问题，记录修复结果 | 修复记录 |
| 复检 | 走查员确认修复，关闭问题 | 走查结论 |

### 4.2 走查检查维度

| 维度 | 检查内容 |
|------|----------|
| 正确性 | 逻辑正确、边界处理、分支覆盖 |
| 清晰度 | 命名语义化、注释充分、无魔法数字 |
| 可维护性 | 模块化、低耦合、单一职责 |
| 安全性 | 输入验证、敏感信息、注入风险 |
| 性能 | 复杂度、循环优化、资源使用 |
| 健壮性 | 异常处理、资源释放、空值防护 |
| 规范一致性 | 编码规范、接口契约、架构一致性 |

### 4.3 走查问题分级

| 严重度 | 定义 | 处理时限 |
|--------|------|----------|
| 阻断（Blocker） | 功能错误、安全漏洞、数据损坏 | 立即修复，禁止合并 |
| 严重（Critical） | 核心逻辑缺陷、明显性能问题 | 24 小时内修复 |
| 主要（Major） | 局部缺陷、规范偏差 | 本迭代内修复 |
| 次要（Minor） | 风格问题、建议项 | 可选择处理 |

## 环节 5：代码审查（Code Review / PR Review）

### 5.1 审查流程（强制）

```
开发者提交 PR → 自动检查（CI通过/质量门禁）→ 审查者审查 → 
问题修复 → 审查通过 → 合并到主干
```

### 5.2 代码审查检查清单（12 项）

| 序号 | 检查项 | 说明 |
|------|--------|------|
| 1 | 代码是否遵循编码规范 | 命名、格式、注释是否符合规范 |
| 2 | 是否有输入验证和边界处理 | 所有外部输入是否验证 |
| 3 | 是否有异常处理和日志记录 | 异常是否捕获、日志是否记录 |
| 4 | 是否存在注入风险 | SQL/命令/LDAP/XPath 注入 |
| 5 | 是否有硬编码敏感信息 | 密码、密钥、token、凭证 |
| 6 | 是否有死代码/未使用变量 | 未使用的导入、变量、函数 |
| 7 | 是否有重复代码 | 违反 DRY 原则 |
| 8 | 圈复杂度是否在合理范围 | <= 15 |
| 9 | 测试用例是否覆盖核心逻辑 | 关键路径是否有测试 |
| 10 | 是否有并发安全问题 | 竞态条件、死锁、线程安全 |
| 11 | 资源是否正确释放 | 文件、连接、内存、锁 |
| 12 | 是否符合架构接口契约 | 输入/输出/异常是否符合设计 |

### 5.3 审查角色与门槛

| 角色 | 职责 | 门槛 |
|------|------|------|
| 开发者 | 提交 PR、响应审查意见 | 自审 + CI 通过 |
| 审查者 | 12 项清单检查、给出结论 | 至少 1 人通过 |
| 合并者 | 合并到主干 | 审查通过 + 门禁通过 |

### 5.4 代码评审报告

| 字段 | 内容 |
|------|------|
| PR 编号 | 合并请求编号 |
| 审查者 | 审查人员 |
| 审查时间 | 审查日期 |
| 问题数 | 发现的问题数量（严重/主要/次要） |
| 修复状态 | 已修复/待修复 |
| 审查结论 | 通过/有条件通过/驳回 |
