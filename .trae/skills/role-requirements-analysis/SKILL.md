用户表达「收集需求/分析需求/写 SRS/需求评审/需求变更/需求追溯/初始化需求基线」时加载本包。先 Read 路由表（下方 §3），命中后只读对应 `domain/*.md`。

## 4. 全局强制刹车规则

1. 收集：同源 3 次矛盾 → 暂停，干系人仲裁；
2. 分析：同需求 2 次矛盾结论 → 高优冲突，干系人确认；
3. 编写：质量校验 ≥3 项 ❌ → 返回分析环节；
4. 评审：第 2 轮仍存严重/主要缺陷 → 停止自动修复，人工介入；
5. 变更：同需求连续 3 次无审批变更 → 冻结基准预警；
6. 追溯：断链率 >20% → 暂停流转，补全追溯。

## 5. 输出规范与边界

- 分析报告 / SRS / 追溯矩阵按 token_standard §3 输出 CSV（禁止 .xlsx）；
- 评审经 `../shared/governance.md`；台账读写经总控；
- 边界：仅需求域；架构/测试等路由到对应角色包。

## 闭环执行系统

### 1. 任务入口
- 输入：用户要求收集、分析、评审、追溯或变更需求，并需要形成需求基线或 SRS；
- 前置：必须有已有项目背景、范围约束、阶段/迭代信息，以及相关干系人或用户故事来源；
- 不适用：没有需求对象、没有可验证输入、或需求已被其他阶段冻结时不应重复执行。

### 2. 执行状态
| 状态 | 进入条件 | 退出条件 | 处理方式 |
|------|---------|---------|---------|
| 待启动 | 需求来源已确认 | 需求基线建立或再确认 | 读取范围与背景 |
| 执行中 | 需求收集或分析已开始 | 需求已落地文档 | 逐项展开分析与追溯 |
| 校验中 | 需求文档已生成 | 评审通过/失败 | 检查完整性、冲突与优先级 |
| 阻塞 | 需求冲突/缺失/模糊 | 补充信息/人工仲裁 | 暂停推进并标记风险 |
| 完成 | 评审通过并确认基线 | 进入架构/开发阶段 | 归档证据并交接 |
| 回退 | 评审未过或变更冲突 | 回到最近稳定需求状态 | 保留审计与冲突结论 |

### 3. 执行动作层
- 执行步骤 1：收集需求来源并确认边界；
- 执行步骤 2：分析需求、剥离冲突与优先级；
- 执行步骤 3：编写 SRS/追溯矩阵并完成评审；
- 所需工具/脚本：需求评审模板、CSV 输出规范、总控台账；
- 输入输出约束：必须输出到 CSV 或交接文档，不能在任务结束前只停留在口头结论。

### 4. 验收门禁
- 必须产出物：需求收集记录、需求分析报告、SRS、追溯矩阵、评审结果；
- 通过条件：需求无重大冲突，双向追溯完成且门禁通过；
- 失败条件：模糊需求、断链、超出范围、未经评审直接流转；
- 审核对象：需求负责人与 role-governance 总控。

### 5. 失败处理
- 失败类型：冲突需求、缺失前置信息、追溯断链、评审失败；
- 恢复策略：回到收集与分析阶段重新确认边界；
- 回滚方案：退回上一版需求基线并保留审计；
- 重试策略：仅在干系人确认和缺失信息补齐后重试；
- 是否需要人工确认：重大需求变更、范围调整、需求冲突仲裁必须人工确认。

### 6. 产出与交接
- 产出物列表：需求基线、SRS、追溯矩阵、评审报告；
- 保存路径：项目根与总控需求台账；
- 交接对象：架构、开发、测试和总控；
- 下一步动作：进入设计/开发阶段或处理需求变更；
- 归档条件：需求门禁通过、变更记录齐全并确认基线。

### 7. 审计记录
- 执行时间：需求收集、分析、评审、变更发生时间；
- 关键参数：需求 ID、优先级、版本、决策结论；
- 关键决策：是否接受、拒绝、调整或冻结需求；
- 结果证据：SRS、追溯矩阵、评审 CSV、变更记录；
- 失败原因：记录在总控审计链与交接文档。
