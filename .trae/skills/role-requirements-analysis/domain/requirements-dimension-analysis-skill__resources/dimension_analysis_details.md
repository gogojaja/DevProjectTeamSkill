# 需求分析七维度详细内容参考（Dimension Analysis Details）

> 本文件为 `requirements-dimension-analysis-skill` 七大分析维度、维度参数化配置、冲突消解规则的详细参考，按需加载。
> SKILL.md 仅保留流程骨架、维度分级表、输出物与刹车规则，详细内容以本文件对应章节为准。

---

## 一、七大分析维度

### 维度 1：功能分析（func）

- **目标**：定义系统应提供的全部功能行为。
- **分析内容**：
  - 功能清单枚举与分层（业务功能 → 子功能 → 功能点）
  - 每个功能的输入、处理逻辑、输出定义（IPO 模型）
  - 功能优先级评定（MoSCoW 法：Must/Should/Could/Won't）
  - 功能间依赖关系图
  - 业务流程图（标准 BPMN 或流程图）
  - 功能用例图（UML Use Case）
- **输出**：`需求分析报告.xlsx`「功能分析」Sheet，包含功能清单表、用例描述、业务流程步骤。

### 维度 2：非功能分析（nfr，ISO/IEC 25010 质量模型）

- **目标**：定义系统质量属性要求，覆盖八大质量特征。
- **分析内容**：
  - **功能性**：功能完备性、正确性、appropriateness
  - **性能效率**：响应时间、吞吐量、资源利用率（明确量化指标）
  - **兼容性**：与其他系统共存能力、互操作性标准
  - **易用性**：可识别性、可学习性、可操作性、用户错误防护、UI 美观度
  - **可靠性**：成熟性、可用性、容错性、可恢复性（SLA 指标）
  - **安全性**：保密性、完整性、不可抵赖性、可追溯性、权限控制
  - **维护性**：模块化、可重用性、可分析性、可修改性、可测试性
  - **可移植性**：适应性、可安装性、可替换性
- **输出**：`需求分析报告.xlsx`「非功能分析」Sheet，每项指标含量化验收标准。

### 维度 3：接口分析（if）

- **目标**：定义系统与外部系统、内部模块间的全部接口。
- **分析内容**：
  - 外部接口清单（对接系统名称、接口方向、协议类型）
  - 接口详细规格（请求/响应格式、字段定义、数据类型、必填项）
  - 接口认证与安全机制（Token/OAuth/证书/IP 白名单）
  - 接口异常处理策略（超时、重试、降级、熔断）
  - 接口版本管理策略
  - 接口时序图（文字描述）
- **输出**：`需求分析报告.xlsx`「接口分析」Sheet，含接口清单表与详细字段定义。

### 维度 4：操作界面分析（ui）

- **目标**：定义系统用户界面的交互需求与布局规范。
- **分析内容**：
  - 用户角色与操作场景矩阵（角色 × 场景 × 操作行为）
  - 界面布局需求（页面结构、导航逻辑、信息层级）
  - 交互行为定义（表单校验、操作反馈、状态流转）
  - 界面一致性规范（组件复用、命名规范、视觉风格）
  - 可访问性要求（无障碍标准 WCAG 等级）
  - 响应式适配要求（分辨率、设备类型）
  - 关键页面原型线框图描述（文字描述 + 布局要点）
- **输出**：`需求分析报告.xlsx`「界面分析」Sheet，含角色-场景矩阵与页面布局描述。

### 维度 5：安全分析（sec）

- **目标**：定义系统安全防护需求，覆盖全链路安全控制点。
- **分析内容**：
  - 身份认证机制（认证方式、会话管理、多因素认证）
  - 授权与访问控制（RBAC 模型、权限粒度、数据范围控制）
  - 数据安全（传输加密 TLS、存储加密、脱敏规则、密钥管理）
  - 安全审计（操作日志范围、保留期限、防篡改机制）
  - 安全合规（等保级别、行业监管要求、数据出境合规）
  - 威胁建模（STRIDE 模型：欺骗/篡改/否认/信息泄露/拒绝服务/权限提升）
  - 安全边界（网络隔离、API 网关、WAF 规则）
- **输出**：`需求分析报告.xlsx`「安全分析」Sheet，含威胁建模清单与安全控制点矩阵。

### 维度 6：数据要求分析（data）

- **目标**：定义系统数据模型、数据流、数据管理需求。
- **分析内容**：
  - 核心数据实体识别与 ER 模型（文字描述）
  - 数据字典（实体、属性、类型、长度、约束、默认值）
  - 数据流分析（数据来源、流向、处理、存储、归档）
  - 数据生命周期管理（创建、使用、归档、销毁策略）
  - 数据质量要求（完整性、一致性、准确性、时效性规则）
  - 数据迁移需求（历史数据迁移范围、映射规则、校验方案）
  - 数据备份与恢复策略（备份频率、保留周期、RTO/RPO）
- **输出**：`需求分析报告.xlsx`「数据分析」Sheet，含 ER 模型描述与数据字典。

### 维度 7：系统运行环境分析（env）

- **目标**：定义系统部署运行环境与技术栈约束。
- **分析内容**：
  - 部署架构需求（单机/集群/云原生/混合云）
  - 运行环境基线（OS 版本、中间件版本、数据库版本、运行时版本）
  - 网络环境要求（带宽、延迟、端口、域名、防火墙规则）
  - 硬件资源基线（CPU、内存、磁盘、最小/推荐配置）
  - 第三方依赖清单（组件名称、版本、许可证、替代方案）
  - 环境矩阵（开发/测试/预生产/生产环境差异说明）
  - 容灾与高可用需求（RTO/RPO、双活/主备策略）
- **输出**：`需求分析报告.xlsx`「环境分析」Sheet，含环境矩阵与依赖清单。

## 二、项目类型自动推荐维度组合

| 项目类型 | 推荐维度 | 跳过维度 | 说明 |
|:---|:---|:---|:---|
| software_system（标准软件系统） | 全部 7 维度 | 无 | 默认值，完整分析 |
| pure_business（纯业务流程优化） | func / sec / data / env / ui | nfr / if | 无系统对接，质量属性要求低 |
| ui_only（纯界面改版） | func / ui / sec | nfr / if / data / env | 仅限界面层，不涉及数据与逻辑 |
| data_migration（数据迁移项目） | func / data / sec / env | nfr / if / ui | 聚焦数据迁移，无界面交互 |
| embedded（嵌入式/后台服务） | func / nfr / sec / data / env | if / ui | 无用户界面，无外部接口对接 |

## 三、维度参数化配置（全需求域共享）

- `dimensions` 与 `project_type` 均为**可选参数**，不传入时默认启用全部 7 维度（向后兼容）；
- 必选维度（func/sec/data/env）不可移除，若移除则报错并自动补回；
- 可选维度（nfr/if/ui）可自由增删，已选维度不可中途移除（仅可新增）；
- 未传 dimensions 默认 7 维度；仅传 project_type 按推荐自动填充。

## 四、需求冲突消解

**优先级链**：安全 > 合规 > 功能 > 非功能 > 界面。

| 冲突场景 | 消解规则 |
|----------|----------|
| 功能与非功能冲突（nfr 已选） | 非功能优先 |
| 安全与易用性冲突（ui 已选） | 安全优先 |
| 性能与成本冲突 | 交 ProjectMonitorSkill 风险评估，用户决策 |
| 未选维度间冲突 | 不参与消解 |

**维度联动清理**：
- 维度移除 → 扫描「需求冲突消解记录.xlsx」涉及维度列，单维度冲突标记「已失效」，多维度冲突更新涉及维度列，生成《冲突记录清理日志》写入「清理日志」Sheet；
- 维度新增 → 全量分析 + 扫描既有条目新冲突，标注「维度新增触发」。

---

## 五、分析阶段刹车规则

1. 同一需求已选维度分析中 2 次矛盾结论 → 标记高优冲突，暂停分析待干系人确认；
2. 超范围 → 转变更审计（ProjectMonitorSkill）。
