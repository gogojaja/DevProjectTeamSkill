# 需求生命周期管理详细内容参考（Requirements Lifecycle Details）

> 本文件为 `requirements-lifecycle-skill` 需求评审、变更分析、追溯矩阵更新的详细参考，按需加载。
> SKILL.md 仅保留流程骨架、输出物清单与刹车规则，详细内容以本文件对应章节为准。

---

## 一、需求评审（review_requirements）

### 1.1 评审五维度

| 维度 | 定义 |
|------|------|
| 完整性 | 是否覆盖全部已选维度需求 |
| 一致性 | 需求间无冲突矛盾 |
| 可测试性 | 验收标准可量化可验证 |
| 可追溯性 | 需求编号可追溯至来源 |
| 合规性 | 满足合规/标准要求（数据、安全等） |

### 1.2 评审前置门禁（quality_gate）

评审前须满足：

| 门禁项 | 标准 |
|--------|------|
| 追溯覆盖率 | 100% |
| 冲突消解 | 记录为空或全部已关闭 |
| 验收标准覆盖 | 每条需求含量化验收标准 |
| 标准合规 | 无合规违规 |

### 1.3 评审输出

- 评审意见（按五维度给出）；
- 评审结论：通过 / 有条件通过 / 不通过；
- 不通过时生成整改清单。

## 二、需求变更分析（change_analysis）

### 2.1 变更触发

- 需求范围调整、外部接口变化、合规新规、干系人新诉求。

### 2.2 变更分析流程

1. **变更登记**：登记至 `需求变更记录.xlsx`（变更编号、发起人、日期、描述、影响维度）；
2. **影响扫描**：变更涉及的维度，进行该维度变更影响分析；
3. **必选维度强制扫描**：涉及必选维度（func/sec/data/env）的变更，若影响，全维度扫描（联动其他维度影响）；
4. **变更影响输出**：输出变更影响分析报告（影响范围、受影响需求清单、成本/进度影响、风险评估）。

### 2.3 变更门禁

- 成本/进度影响超阈值 → 交 ProjectMonitorSkill 变更审计与干系人审批。

## 三、需求追溯矩阵更新（update_trace_matrix）

- 更新 `需求规格说明书_SRS_v1.1.xlsx`「10-追溯矩阵」Sheet；
- 写入 ProjectMonitorSkill 台账「需求追溯矩阵」Sheet（17 Sheet 之一）；
- 每次需求变更/评审结论落地后同步更新。

---

## 四、生命周期阶段刹车规则

1. 追溯矩阵断裂（需求无来源或未映射）→ 暂停，补齐追溯；
2. 变更未审批先实施 → 暂停，补审批；
3. 评审门禁未达标 → 禁止评审通过，转整改。
