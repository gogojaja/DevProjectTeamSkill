## 环节 1：需求工作目录初始化（create_requirements_baseline）

### 1.1 初始化内容

| 项目 | 内容 |
|------|------|
| 需求工作目录 | 项目根 `requirements/` 目录创建 |
| Excel 模板 | `需求收集清单.xlsx`（2 Sheet：「需求清单」「来源映射」） |
| 与其他技能协同 | 台账初始化由 project-governance-skill `create_baseline` 完成 |

### 1.2 初始化前置

- 项目启动基线已固化（project-init-skill）；
- 台账「范围基准」已写入范围初定义。

## 环节 2：需求收集（gather_requirements）

### 2.1 需求来源识别

| 来源类型 | 示例 | 说明 |
|----------|------|------|
| 业务方 | 产品经理、业务部门、最终用户 | 核心需求来源 |
| 访谈 | 干系人访谈、焦点小组 | 挖掘隐性需求 |
| 现有系统 | 遗留系统、竞品分析 | 功能/数据迁移来源 |
| 合规 | 法规、行业标准、安全规范 | 强制需求来源 |
| 技术约束 | 平台、基础设施、第三方依赖 | 技术边界来源 |

### 2.2 结构化登记

登记至 `需求收集清单.xlsx`「需求清单」Sheet：

| 字段 | 内容 |
|------|------|
| 需求编号 | 临时编号（正式编号在 SRS 编写时按规则生成） |
| 来源 | 来源类型（业务方/访谈/现有系统/合规/技术约束） |
| 来源类型 | 来源具体类型 |
| 原始描述 | 干系人原始表述 |
| 提出人 | 需求提出人 |
| 日期 | 收集日期 |
| 优先级 | 初步评定（MoSCoW：Must/Should/Could/Won't） |
| 分类标签 | 初步分类（功能/非功能/接口/界面/安全/数据/环境） |

### 2.3 来源追溯

来源追溯写入「来源映射」Sheet：来源编号 → 来源名称 → 来源类型 → 关联需求编号 → 收集日期。

### 2.4 收集盲区校验

对照七维度清单（func/sec/data/env 必选，nfr/if/ui 可选）校验收集盲区，输出《需求收集完整性检查表》，识别未覆盖维度。

---

## 环节 3：收集阶段刹车规则

1. **矛盾仲裁**：同一来源 3 次以上矛盾描述 → 暂停收集，业务方仲裁；
2. **范围控制**：需求超范围 → 标记「范围外」转 ProjectMonitorSkill `change_audit` 变更审计。
