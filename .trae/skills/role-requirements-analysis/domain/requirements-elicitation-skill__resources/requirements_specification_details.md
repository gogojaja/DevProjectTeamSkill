# 需求规格化（SRS 编写）详细内容参考（IEEE 830 Specification Details）

> 本文件为 `requirements-specification-skill` SRS 结构与编写规范、需求编号规则、质量校验清单的详细参考，按需加载。
> SKILL.md 仅保留流程骨架、输出物清单与刹车规则，详细内容以本文件对应章节为准。

---

## 一、SRS 输出结构（IEEE Std 830-1998 章节对应）

`SRS_v1.1.xlsx` 共 10 个 Sheet，对应关系：

| Sheet | IEEE 830 章节 | 内容 |
|-------|--------------|------|
| 1-引言 | §1 | 目的、范围、定义、参考文献、概述 |
| 2-总体描述 | §2 | 产品透视、功能概述、用户特征、约束、假设与依赖 |
| 3-外部接口需求 | §3 | 界面/接口/通讯等外部接口 |
| 4-功能需求 | §4 | 功能分类与描述 |
| 5-性能需求 | §5 | 性能指标量化 |
| 6-设计约束 | §6 | 设计标准、合规、硬件/软件约束 |
| 7-质量属性 | §7 | 可靠性、可用性、可维护性、可移植性等 |
| 8-其他需求 | §8 | 数据管理、法律、操作需求等 |
| 9-附录 | 附录 | 补充图表、示例 |
| 10-追溯矩阵 | §7 | 需求追溯与映射 |

## 二、需求编号规则

### 2.1 正式编号格式

```
REQ-<维度>-<模块>-<序号>
```

| 段 | 规则 | 示例 |
|----|------|------|
| 维度段 | 功能 FUNC / 非功能 NFR / 接口 IF / 界面 UI / 安全 SEC / 数据 DATA / 环境 ENV | REQ-FUNC- |
| 模块段 | 模块英文缩写（≤4 位），无模块时用 REQ | REQ-FUNC-REQ- |
| 序号段 | 3 位递增 | REQ-FUNC-REQ-001 |

### 2.2 追溯矩阵填写

- 每行一个需求，含维度、编号、来源、验收标准、优先级、变更记录；
- 门禁要求：每个需求**必须**可追溯至收集来源（来源映射 Sheet）。

## 三、SRS 质量校验清单（完整验证后输出）

| 校验项 | 校验内容 | 通过标准 |
|--------|----------|----------|
| 正确性 | 每条需求真实准确反映用户意图 | 无虚假需求 |
| 无歧义性 | 每条需求仅一种解释 | 术语表已定义 |
| 完整性 | 覆盖全部已选维度需求 | 100% 追溯覆盖 |
| 一致性 | 需求间无冲突矛盾 | 冲突消解记录为空 |
| 可验证性 | 每条需求可量化验证 | 含验收标准 |
| 可追踪性 | 需求编号可追溯 | 追溯矩阵 100% 填充 |
| 可修改性 | 结构便于修改 | 编号规则一致 |

**性能指标量化标准**：响应时间 P95 ≤ 目标值、吞吐量 ≥ 目标值、可用性 ≥ 99.9%、数据恢复 RTO ≤ 4h / RPO ≤ 15min、容量基准并发 ≥ 目标值。

## 四、编写阶段刹车规则

1. 追溯矩阵出现未填项 → 暂停编写，补齐来源映射；
2. 编号重复或规则冲突 → 暂停编写，修正编号。
