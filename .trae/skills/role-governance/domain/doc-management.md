# doc-management — 文档管理能力

> 来源：dev-doc-manager 项目技能化（项目群规划 v3.0，评分 74/100 → 技能化决策）
> 定位：项目级文档生命周期治理（方法论层），与 `role-program-mgmt` 项目群级文档配置管理（31_文档配置管理台账）互补：本域管**治理与审计**，项目群域管**配置与分发**。
> 参考：ISO 15489（文件管理）· ISO 10007（配置管理技术指南）
> 版本：v1.0.0（2026-09-01）

---

## 1. 文档生命周期

```
创建 → 评审 → 发布(基线) → 使用 → 变更 → 归档/废止
```

| 阶段 | 治理动作 | 台账/产物 |
|------|----------|-----------|
| 创建 | 命名规范检查（见 §2）+ 密级标注 | 文档登记 |
| 评审 | 经 `stage_review` 五维评审 | 评审报告 |
| 发布 | 纳入基线（版本号锁定） | 基线快照 |
| 使用 | 引用一致性检查（`check_skill_links` 同理） | — |
| 变更 | 经 `change_audit` 留痕，重大变更走变更分级审批 | 变更台账 |
| 归档/废止 | 归档至 `docs/legacy/`；废止按铁律废弃清理门禁（grep 残留引用） | 归档记录 |

## 2. 命名规范

| 文档类型 | 命名模式 | 示例 |
|----------|----------|------|
| 方案文档 | `<主题>_<方案类型>_v<版本>.md` | 项目群整体规划方案_v3.0.md |
| 评审报告 | `评审报告_<对象>_<日期>.md` | 评审报告_项目群全量评估_20260901.md |
| 立项建议书 | `INC-<日期>-<序号>_<对象>.md` | INC-2026-09-01-001_dev-project-mgmt.md |
| 证据卡 | `evidence_cards_<对象>_<日期>.json` | evidence_cards_dev-task-scheduler_20260831.json |
| 交接事项 | `交接事项_<对象>_<日期>.md` | 交接事项_free-api-hub功能边界清理_20260901.md |

规则：日期用 `YYYYMMDD`；版本号语义化（主.次.修订）；中文标题与文件名一致；禁止无版本号覆盖式更新正式方案文档。

## 3. 密级与权限（对齐铁律 §3）

| 密级 | 处理 | 示例 |
|------|------|------|
| A 级 | 禁止入库，只存别名 | 密钥/凭据/Token |
| B 级 | 脱敏入库 | 主机名/IP/用户名/绝对路径 |
| C 级 | 正常入库 | 一般技术文档 |

文档归档/发布前强制脱敏扫描（`tools/desensitize/desensitize.py --scan`）。

## 4. 归档策略

| 触发条件 | 动作 |
|----------|------|
| 方案被新版本替代（如 v2.0 → v3.0） | 旧版保留原位，新版引用「替代关系」；连续 2 个大版本未引用 → 移 `docs/legacy/` |
| ADR 状态=废弃 | 立即走废弃清理门禁（铁律：全库 grep 引用 + 运行态三查） |
| 项目收尾 | 全套文档归档 + `handover_export` 交接 |

## 5. 文档审计（governance 视角）

- **引用完整性**：文档间相对引用可达（断链列入评审缺陷）
- **单一信源**：同一信息只在一处维护，他处引用不复制（违反列入变更审计）
- **版本一致性**：文档声明版本与台账登记版本一致（`check_version_consistency` 同理）
- **留痕完备**：重大文档变更必有 13 台账留痕

## 闭环执行系统

### 1. 任务入口
- 输入：用户要求文档治理/归档/命名检查/密级审查/文档审计
- 前置：明确目标文档范围与生命周期阶段

### 2. 执行状态
待执行 → 审计中 → 已出报告 → 已归档/已整改

### 3. 验收门禁
- 命名规范符合 §2；密级处理符合 §3；归档动作有留痕

### 4. 失败处理
- 引用断链/密级违规 → 登记缺陷台账，阻断归档，整改后复检

### 5. 产出与交接
- 文档审计报告（CSV）+ 归档记录；交接断点更新

### 6. 审计记录
- 文档变更/归档一律 `change_audit` + 13 台账留痕
