## 环节 1：范围门禁校验（Scope Gate）

### 1.1 流转前范围核查

| 检查项 | 内容 |
|--------|------|
| 产出物匹配 | 本阶段产出物是否匹配「范围基准」Sheet 定义 |
| 超范围内容 | 是否存在未经审批的超范围内容 |
| 拦截规则 | 无审批超范围内容 → 拦截流转 |

### 1.2 产出物条目化比对（check_gate 协同）

| 步骤 | 内容 |
|------|------|
| ① 读取基准 | 上一阶段 `stage_close` 固化的产出物基准清单（「范围跟踪台账」Sheet） |
| ② 读取准入 | 下一阶段准入条件清单（产出物名称、验收标准） |
| ③ 逐条比对 | 生成《产出物条目化比对表》：✅ 匹配 / ❌ 缺失 / ⚠️ 内容偏差 |
| ④ 门禁判定 | 全部 ✅ → 通过；存在 ❌ → 驳回补全；仅 ⚠️ → 有条件通过，偏差项录缺陷台账限期整改 |
| ⑤ 结果写入 | 比对表追加写入「门禁验收记录」Sheet 并作为评审 Excel 独立 Sheet 输出 |

### 1.3 范围跟踪检查（stage_review 第⑤维度协同）

| 检查项 | 内容 |
|--------|------|
| 基准读取 | 上一阶段固化基线产出物条目清单（「范围跟踪台账」Sheet） |
| 逐条比对 | 与本阶段实际产出物比对（产出物名称/条目数量/内容覆盖度） |
| 严重缺陷 | 🔴 本阶段遗漏上阶段必需条目（范围缩水） |
| 主要缺陷 | 🟠 新增未审批条目（范围蔓延） |
| 次要缺陷 | 🟡 条目数量一致但内容变化，需确认是否影响范围基准 |
| 结果写入 | 比对表作为评审报告独立 Sheet 输出，并更新「范围跟踪台账」Sheet |

## 环节 2：变更审计（Change Audit）

### 2.1 变更影响评估五维

| 维度 | 评估内容 |
|------|----------|
| 范围影响 | 是否扩大/缩小范围，涉及范围基准变更 |
| 进度影响 | 是否影响里程碑、工期、交付节点 |
| 成本影响 | 是否增加工时、资源、成本 |
| 质量影响 | 是否影响质量验收标准、缺陷风险 |
| 安全影响 | 是否引入新的安全风险、合规问题 |

### 2.2 变更审计流程

```
提出变更 → 生成《变更影响评估表》→ 五维风险评估 → 
重大变更强制 user_confirm=同意 → 记录追加「范围变更台账」→ 实施
```

| 变更类型 | 审批要求 |
|----------|----------|
| 轻微变更 | 评估表记录 + 用户知悉 |
| 重大变更 | 强制 `user_confirm=同意`，否则中止 |
| 核心架构文件 | 自动转发安全审计（见 project-security-audit-skill） |

### 2.3 刹车机制

- 同一需求连续 3 次无审批变更 → 触发风险预警，建议人工冻结范围基准；
- 用户连续 2 次拒绝同一变更 → 永久终止本次变更。
