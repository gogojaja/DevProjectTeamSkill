## 环节 1：风险登记册初始化（Risk Register Init）

### 1.1 初始风险预设

| 风险类别 | 示例风险 | 应对策略 |
|----------|----------|----------|
| 范围风险 | 需求蔓延、范围缩水 | 变更审批 + 范围冻结机制 |
| 进度风险 | 里程碑延期、任务滞后 | 进度预警 + EVM 监控 |
| 成本风险 | 成本超支、资源不足 | 成本阈值 + 超支预警 |
| 技术风险 | 技术选型失败、兼容性问题 | POC 验证 + 备选方案 |
| 质量风险 | 缺陷率高、覆盖率不足 | 质量门禁 + 缺陷闭环 |
| 安全风险 | 漏洞、数据泄露 | SAST/SCA 扫描 + 安全审计 |
| 人员风险 | 关键人员流失 | 知识交接 + 文档化 |

写入「风险&问题台账」Sheet。

## 环节 2：风险巡检（risk_scan）

### 2.1 巡检流程

| 步骤 | 内容 |
|------|------|
| ① 读取台账 | 读取「风险&问题台账」Sheet 全部风险 |
| ② 状态复核 | 复核各风险当前状态（新增/持续/缓解/已关闭） |
| ③ 新风险识别 | 结合当前进度/成本/质量/安全数据识别新风险 |
| ④ 评估更新 | 更新风险概率、影响、等级 |
| ⑤ 登记册更新 | 新增风险写入，关闭风险标记 |

### 2.2 风险等级评估

| 等级 | 概率×影响 | 处理 |
|------|-----------|------|
| 高 | 高概率×高影响 | 立即制定应对方案，上报决策 |
| 中 | 中概率×中影响 | 制定应对预案，持续监控 |
| 低 | 低概率×低影响 | 登记监测，定期复核 |

### 2.3 触发时机

- 定期巡检（每阶段切换、周期复盘）；
- 阶段切换时；
- 项目重大变更后。

## 环节 3：风险应对

| 应对策略 | 适用场景 |
|----------|----------|
| 规避 | 高风险且可避免 |
| 减轻 | 降低概率或影响 |
| 转移 | 可转移至第三方 |
| 接受 | 低风险且应对成本高 |
| 应急预案 | 高风险但不可控，预设触发条件 |

## 环节 4：问题解决与升级机制（issue escalation）

启动阶段 `define_issue_escalation` 确立（写入「风险&问题台账」Sheet/`12_风险问题台账.csv` 升级字段）：

### 4.1 问题分级（P1~P4）

| 级别 | 定义 | 示例 | 响应时限 |
|------|------|------|----------|
| P1 阻断 | 项目无法推进/主流程不可用/数据丢失 | 生产阻断、关键链路宕机、范围致命冲突 | ≤ 4h |
| P2 高 | 关键功能受阻/里程碑延期风险 | 核心接口不可用、依赖缺失、资源冲突未决 | ≤ 1 个工作日 |
| P3 中 | 局部功能受影响/可绕行 | 非核心缺陷、进度轻微滞后 | ≤ 3 个工作日 |
| P4 低 | 一般性问题/优化建议 | 文档缺失、体验优化 | 记录即可 |

### 4.2 升级阶梯（四级路径）

| 级别 | 处理主体 | 职责 | 响应时限 |
|------|----------|------|----------|
| L1 | 项目团队（Owner） | 识别问题、记录台账、尝试解决 | 问题发生时 |
| L2 | 项目经理 | 分析决策、资源调配、跨团队协调 | P1/P2 即时、P3 ≤ 1 工作日 |
| L3 | 指导委员会/项目委员会 | 决策仲裁、范围/预算/优先级裁决 | P1 ≤ 1 个工作日 |
| L4 | 高层/Sponsor | 战略干预、资源追加、终止决策 | 按治理节奏 |

- **单一 Owner 原则**：每个问题唯一 Owner（对齐 RACI 唯一 A），Owner 缺失不得升级，升级路径清晰可追溯；
- **升级条件**：超过本级响应时限未决、超出本级权限（预算/范围/人员）、多干系人冲突无法裁决；
- **协同**：P1/P2 问题升级与 multi-perspective-validation 的 P0~P6 仲裁、`change_audit` 变更审计衔接，升级不经审批链外绕过，全程留痕至台账与 `13_安全审计台账.csv`（如涉高危操作）；
- **关闭**：问题处理完成须记录解决动作与验证结果，Owner 确认后关闭，关闭记录在阶段评审复核。

## 环节 5：风险与范围变更协同

- 需求变更 → 同步评估风险影响（见 project-scope-change-skill）；
- 架构变更 → 同步更新风险登记册（见 architecture-design-skill 协同）；
- 风险升级为重大问题 → 按环节 4 升级阶梯推送人工决策。
