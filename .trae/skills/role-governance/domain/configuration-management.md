# configuration-management — 配置管理聚合能力

> 定位：项目/技能库级**配置管理（CM）治理聚合层**——把分散在 5 处的 CM 要素拉通为 ISO 10007 四活动闭环，产出《配置管理计划(CMP)》与配置审计报告。**只做治理聚合与配置审计，不复制任何单一信息源数据。**
> 参考：ISO 10007（配置管理技术指南）· PMBOK 7（CM 属整合管理/变更控制系统）· CMMI CM PA（标识/控制/状态记实/审计）· ITIL 4（SCM + CMDB）
> 版本：v1.0.0（2026-09-09）

---

## 1. 职责边界（守单一信息源，禁止复制数据）

本域是 CM 的**聚合与审计入口**，各类配置项(CI)的真实数据仍由其单一信息源维护，本域只引用、只审计：

| CI 类别 | 单一信息源（数据归属） | 本域职责（治理聚合） |
|---------|----------------------|--------------------|
| 环境 CI | CMDB `tools/cmdb/cmdb-cli.py` + `20_环境配置.csv` / `25_环境资源清单.csv`；项目群级见 `role-program-mgmt` §9.8 | 引用 CI 状态，纳入配置审计，不复制 |
| 代码 / 分支 CI | `domain/branch-governance.md`（单一分支 + pre-push hook）+ `role-development`（分支编码规范） | 基线一致性审计，不重复定义分支策略 |
| 文档 CI | `domain/doc-management.md` + `role-program-mgmt` `manage_documents`（`31_文档配置管理.csv`） | 归档/版本一致性审计，不复制文档台账 |
| 技能包 CI | `tools/solidify.py` ALL_ROLES + `skills_backup_v<版本>/` 快照 + `dist/` | 版本/快照/部署四目录一致性审计 |

> **铁律**：环境 CI 归 CMDB 单一信息源；本域**仅引用不复制**（违反即列入变更审计）。

## 2. 配置管理四活动（ISO 10007 / CMMI CM PA 映射）

| 活动 | 落地机制（已有能力聚合） | 产物 |
|------|------------------------|------|
| 配置标识 | CI 四类分类（§1）+ 命名规范（引 `doc-management.md` §2）+ CMDB CI 唯一 ID | CI 清单视图 |
| 配置控制 | 基线固化 `solidify_baseline` + 分支治理 `branch_governance` + 变更审计 `change_audit` + 执行合同闸门（铁律 #10 Tier3 六件套） | 变更台账 / 基线快照 |
| 配置状态记实 | `31_文档配置管理.csv` + 交接文档断点区 + CMDB 状态 + solidify 快照元数据 | 状态记实记录 |
| 配置审计 | **`config_audit`（本域新增闭环动作，见 §4）** | 配置审计报告 CSV |

## 3. 配置管理计划（CMP）模板

发布/固化前，重大版本须有一份 CMP（可裁剪），最少包含：

| 章节 | 内容 |
|------|------|
| 1. CI 范围 | 纳入配置管理的四类 CI 清单及其单一信息源 |
| 2. 命名与标识 | CI 命名规则、唯一标识来源（CMDB ID / 版本号 / 快照名） |
| 3. 基线策略 | 何时建基线（阶段门禁 / 发布点）、基线载体（`skills_backup_v<版本>/`、git tag） |
| 4. 变更控制 | 变更分级、审批路径、Tier3 六件套触发条件、回滚点 |
| 5. 职责(RACI) | 配置标识/控制/审计的 R-A-C-I（默认 A=role-governance，环境CI R=CMDB owner） |
| 6. 配置审计周期 | 审计触发条件与频率（见 §4.3） |

## 4. 配置审计动作 `config_audit`（补齐当前唯一缺口）

### 4.1 审计项（一次性拉通四类 CI）
1. **基线一致性**：当前磁盘状态 vs 最近 `skills_backup_v<版本>/` 快照，无未登记漂移；
2. **版本一致性**：复用 `tools/check_version_consistency.py`（各角色包元数据/页脚版本齐平）；
3. **分支保护**：复用 `branch_governance.sh`（单一 main 分支、无非 main 残留）；
4. **文档归档**：复用 `doc-management.md` §5（引用完整/单一信源/留痕完备）；
5. **环境 CI 占用**：引用 CMDB（关键资产状态、资源负载 ≤80%），不复制数据。

### 4.2 输出
- `台账/` 配置审计报告 CSV（UTF-8 with BOM，禁 .xlsx）：审计项 / 结果(通过|偏差|阻断) / 证据 / 整改建议；
- 偏差与阻断项一律 `change_audit` 留痕。

### 4.3 触发条件
| 触发 | 时机 |
|------|------|
| 发布/固化前 | `solidify` / `publish_production` 前作为前置校验（与版本/闭环/发布门禁并列） |
| 阶段门禁 | 阶段流转前（与 `check_gate` 叠加） |
| 周期审计 | 每周（与 `cmdb_audit` / `branch_governance` 同窗口） |
| 手动 | 用户要求配置审计时 |

## 闭环执行系统

### 1. 任务入口
- 输入：用户要求配置管理治理、编制 CMP、执行配置审计、发布/固化前配置一致性核验
- 前置：明确 CI 范围与单一信息源可达（CMDB / 快照 / 分支 / 文档台账）
- 不适用：无配置项、无基线、无审计对象时不发放放行结论

### 2. 执行状态
待执行 → 标识/聚合中 → 审计中 → 已出报告 → 已整改/已放行

### 3. 验收门禁
- CMP（如适用）六章齐备；四类 CI 均指向单一信息源、无复制；`config_audit` 五项全跑并出 CSV

### 4. 失败处理
- 基线漂移 / 版本不齐 / 非 main 分支 / 文档断链 / CMDB 超载 → 登记偏差，阻断发布/固化，整改后复检

### 5. 产出与交接
- 配置审计报告 CSV + CMP + 基线快照引用；交接断点区更新

### 6. 审计记录
- 配置变更/审计结论一律 `change_audit` + `13_安全审计台账.csv` 留痕
