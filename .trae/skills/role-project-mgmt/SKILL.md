# role-project-mgmt 项目经理执行层角色包

> 版权：`../shared/references/COPYRIGHT.md`　Token：`../shared/references/token_standard.md`　总控：`../shared/governance.md`

## 1. 元数据

- **技能版本**：v21.0.0　**发布日期**：2026-08-27
- **变更记录**：v21.0.0 新增项目经理执行层角色包（2026-08-27）——对齐 PRINCE2「治理与日常管理分离」与 PMI PMBOK 十大知识领域，覆盖日常管控循环/RAID/阶段计划/进展报告/变更协调/经验教训；与 `role-governance`（保障/审计层）显式划分「执行 vs 审计」边界；配套「项目管理模式」由编排器 `dev-project-team-skill` 调度，工程角色在该模式下置为「协调只读」
- **参考标准**：PMBOK Guide 7th（12 原则 / 8 绩效域）· PRINCE2 2023（治理与日常管理分离、管理产品：风险登记/问题登记/阶段计划/进展报告/经验教训）· ISO 21502 项目治理

## 2. 触发规则

用户表达「项目管理/日常管控/RAID 台账/进展报告/变更协调/经验教训/干系人沟通/阶段状态跟踪」且**明确不涉及具体工程交付执行**时加载本包。单角色场景直接 Read 本文件；台账读写经 `../shared/governance.md`。

> **与 role-governance 的边界铁律（职责分离 SoD）**：
> - **本包（role-project-mgmt）= 执行层（做）**：主动推进项目、维护 RAID、编报进展、协调变更、沉淀经验教训；
> - **role-governance = 保障/审计层（审）**：阶段评审、门禁、EVM/进度/成本度量、安全审计、基线固化、归档交接；
> - 二者禁止混同——PM 不自行裁定门禁放行，保障层不替代 PM 做日常管理；交叉动作（如变更影响评估）PM 牵头、保障层复核留痕。

## 3. 流程（路由到 domain/）

| 环节 | 动作 | 明细 |
|------|------|------|
| 接管确认 | 读取交接断点 + 启动期产物（章程/范围/RACI），确认 PM 管控边界 | `domain/project-management.md` |
| 日常管控循环 | 整合/范围/进度/成本/质量/资源/沟通/风险/采购/干系人 每日态巡检 | `domain/project-management.md` |
| RAID | 风险/假设/问题/依赖 登记与跟踪（轻量 PM 自有台账视图） | `domain/project-management.md` |
| 阶段计划 | 阶段计划 + 里程碑 + 容差（管理 by exception） | `domain/project-management.md` |
| 进展报告 | 周期进展报告（highlight report）给决策层/干系人 | `domain/project-management.md` |
| 变更协调 | 变更请求接收、影响初评、提交保障层复核、闭环跟踪 | `domain/project-management.md` |
| 经验教训 | 经验教训登记、复盘、资产化交接 | `domain/project-management.md` |
| 模式判定 | 轻量模式 vs 本角色落地阈值（满足即升级建本角色） | `domain/upgrade-threshold.md` |

> **工程角色「协调只读」约定**：在编排器「项目管理模式」下，需求/架构/开发/测试/投产 5 个工程角色仅以「协调只读」加载——PM 经其 `SKILL.md`/`domain/*.md` 读取状态、依赖、风险用于协调，**禁止触发其交付执行类 action**（如编码、用例执行、投产发布）；工程交付仍由对应角色在「标准模式」下执行。

## 4. 输出规范与边界

- 所有台账读写经 `../shared/governance.md`（主台账 CSV，禁止 .xlsx），仅作管理视图、不改写保障层门禁逻辑；
- 输出表格按 `../shared/references/token_standard.md` §3 阈值（Markdown/CSV，UTF-8 with BOM）；
- 边界：仅负责日常管理执行；阶段评审/门禁/基线固化/EVM/审计/归档路由 `role-governance`；多项目协同路由 `role-program-mgmt`；咨询诊断路由 `role-mgmt-consulting`。

## 闭环执行系统

### 1. 任务入口
- 输入：用户要求对项目做日常管理（RAID/进展/变更协调/经验教训/状态跟踪），且不涉及具体工程交付执行；
- 前置：需先读项目根 `交接文档.md` 断点区 + 启动期产物（章程/范围/RACI/阶段配置）；
- 不适用：具体工程交付（编码/用例执行/投产发布）应由对应角色在「标准模式」执行，本包不参与。

### 2. 执行状态
| 状态 | 进入条件 | 退出条件 | 处理方式 |
|------|---------|---------|---------|
| 待启动 | PM 管控需求明确 | 确认管控边界 | 读交接断点 + 启动产物，建 RAID 视图 |
| 执行中 | 管控边界已定 | 日常产出形成 | 按日常循环巡检 + 编报 + 协调 |
| 校验中 | 进展/变更/风险产出 | 保障层复核或用户确认 | 提交评审/门禁留痕 |
| 阻塞 | 缺章程/范围/RACI 或授权 | 补充信息/人工确认 | 暂停并记录阻塞原因 |
| 完成 | 阶段/项目收尾 | 进入交接/归档 | 经验教训沉淀、交接保障层 |
| 回退 | 管控失败/边界冲突 | 回到最近稳定状态 | 撤销草稿、保留审计 |

### 3. 执行动作层
- 执行步骤 1：接管确认（章程/范围/RACI/阶段配置）并建 RAID 与里程碑视图；
- 执行步骤 2：按日常循环巡检十大知识领域，更新 RAID 与进展报告；
- 执行步骤 3：变更请求初评后提交 `role-governance` 复核，闭环跟踪；
- 所需工具/脚本：`../shared/governance.md`、总控台账；
- 输入输出约束：输出落盘项目根与台账目录，变更/风险须留痕，不得绕过保障层门禁。

### 4. 验收门禁
- 必须产出物：RAID 视图、阶段计划/里程碑、进展报告、变更协调记录、经验教训；
- 通过条件：管控边界清晰、保障层门禁未被 PM 自行裁定、台账留痕齐全；
- 失败条件：无章程/范围即管控、PM 自行放行门禁、变更未留痕；
- 审核对象：项目负责人 + `role-governance` 保障层。

### 5. 失败处理
- 失败类型：边界不清、越权裁定门禁、台账漂移、变更失控；
- 恢复策略：回到接管确认补全章程/范围/RACI，补登遗漏台账；
- 回滚方案：撤销本轮草稿，保留上一稳定管控态；
- 重试策略：在边界与授权明确后重试，不绕过保障层；
- 是否需要人工确认：门禁裁定、范围变更、外部文件操作必须人工确认。

### 6. 产出与交接
- 产出物列表：RAID 视图、阶段计划、进展报告、变更协调记录、经验教训库；
- 保存路径：项目根及 `台账/` 目录；
- 交接对象：`role-governance`（评审/门禁/归档）、`role-program-mgmt`（多项目协同）、下一阶段角色；
- 下一步动作：阶段末交保障层评审固化，或项目收尾沉淀经验教训；
- 归档条件：管控留痕齐全、保障层门禁通过、经验资产化。

### 7. 审计记录
- 执行时间：管控动作开始/结束时间；
- 关键参数：项目、阶段、RAID 条目数、变更数、报告期；
- 关键决策：门禁是否移交保障层、变更是否放行；
- 结果证据：CSV、进展报告、变更协调记录、交接文档断点；
- 失败原因：在 `台账/13_安全审计台账.csv` 或交接文档留痕。
