# knowledge-base — 知识库能力

> 来源：dev-knowledge-base 项目技能化（项目群规划 v3.0，评分 71/100 → 技能化决策）
> 定位：在记忆层（ProjectMemory/Notepad/KnowledgeGraph）之上提供**组织级知识资产**管理——记忆管「这个项目的上下文」，知识库管「跨项目可复用的经验资产」。
> 衔接：`retrospect_harvest`（22_阶段复盘 + 23_复用资产台账）· `../../skills/self-improve/SKILL.md`（经验库 lessons）· `tools/retro_cli.py --write-lessons`
> 版本：v1.0.0（2026-09-01）

---

## 1. 知识资产分类

| 类别 | 说明 | 载体 | 示例 |
|------|------|------|------|
| 决策知识 | 为什么这么做（ADR/评审结论） | ADR + 评审报告 | 「调度器选 APScheduler 而非 Celery」 |
| 经验教训 | 踩坑与规避（lessons） | 经验库（retro_cli） | 「并行 edit 污染源码（DEV-001）」 |
| 复用资产 | 可跨项目复用的方案/代码/模板 | 23_复用资产台账 | 「熔断器模式（mirror_push）」 |
| 标准规范 | 铁律/契约/标准 | references/ | 「tool_calling_standard」 |

## 2. 知识沉淀流程

```
阶段复盘（retrospect_harvest）
  ├→ 22_阶段复盘：做得好/待改进/行动项
  ├→ 23_复用资产：登记可复用资产（名称/类型/路径/适用场景）
  └→ 经验库：--write-lessons 沉淀教训（写库前强制脱敏扫描）
```

登记要求（缺一不入库）：
- **适用场景**：何时该用/何时不该用
- **反信号**：失败案例或失效条件
- **来源锚点**：出处（事故编号/评审报告/ADR）

## 3. 知识检索

| 检索场景 | 优先载体 | 方法 |
|----------|----------|------|
| 「以前遇到过吗」 | 经验库 + 22_阶段复盘 | 关键词 + 事故编号 |
| 「有现成方案吗」 | 23_复用资产台账 | 按类型/适用场景过滤 |
| 「为什么这么设计」 | ADR + 知识图谱影响分析 | `domain/knowledge-graph.md` |
| 「标准是什么」 | references/ | 路由表（SKILL_INDEX） |

**外部信号优先**（对齐 best-practice-solution HRF）：库内知识过期时先核验外部现状，再更新库内条目。

## 4. 知识复用规则

- **单一信源**：知识只在一处维护，他处引用不复制（违反列入文档审计）
- **脱敏入库**：经验/教训含主机名、路径等 B 级信息时强制脱敏（`tools/desensitize/`）
- **生命周期**：复用资产 6 个月未被引用 → 复盘时评估归档；被证伪的经验 → 标记废弃不删除（留反例价值）

## 5. 与记忆层分工

| 维度 | 记忆层（本技能既有） | 知识库（本域） |
|------|---------------------|----------------|
| 范围 | 单项目上下文 | 跨项目资产 |
| 时效 | 会话~项目周期 | 长期 |
| 写入 | 随时（自动） | 复盘驱动（门禁） |
| 载体 | notepad/memory/graph | 22/23 台账 + 经验库 + references |

## 闭环执行系统

### 1. 任务入口
- 输入：阶段复盘收割、知识查询、复用资产登记
- 前置：复盘输入齐备（good/improve/action）或查询关键词明确

### 2. 执行状态
待沉淀 → 脱敏扫描 → 已入库 / 待检索 → 已命中+引用

### 3. 验收门禁
- 入库：三要素齐备（适用场景/反信号/来源锚点）+ 脱敏扫描通过
- 检索：命中条目带来源锚点，禁止无锚点输出

### 4. 失败处理
- 脱敏不通过 → 阻断入库；知识冲突 → 以运行态/最新评审为准并登记偏差

### 5. 产出与交接
- 22/23 台账更新 + 经验库登记；阶段交接断点引用关键知识条目

### 6. 审计记录
- 知识入库/废弃经 `retro_cli` 留痕；废弃标记走变更审计
