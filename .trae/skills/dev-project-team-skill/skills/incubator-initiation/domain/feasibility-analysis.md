# Feasibility Analysis 可行性分析（五维 + 独立性判定）

> 归属：`../SKILL.md` §2.2.2　版本：v1.1.0

## 1. 目的

对孵化对象做结构化可行性判定：五维可行性矩阵（能不能做）+ 独立性判定（该不该独立），为孵化决策提供量化依据。对齐 PMBOK 启动过程组可行性评估与本库五维可行性（`role-project-init` check_ready 复用）。

## 2. 可行性五维矩阵（必做）

| 维度 | 评估要点 | 档位 |
|------|----------|------|
| 技术可行性 | 技术路线成熟度、先例验证（如 dev-task-scheduler 模式）、依赖可得性 | 高/中/低 |
| 经济可行性 | 开源/自研成本、许可证费用、维护投入折算 | 高/中/低 |
| 合规可行性 | 敏感数据涉入度（铁律 #8 A/B/C 级）、许可证合规、对外契约 | 高/中/低 |
| 资源可行性 | 单人/团队可维护性、技能/工具归属方明确 | 高/中/低 |
| 时间可行性 | 骨架周期 + 功能渐进节奏、与既有迭代冲突度 | 高/中/低 |

**判定规则**：五维全高→可行性极高；≥1 维低→可行性存疑，须在建议书中给出缓解措施或降为「继续孵化」；关键维度无证据支撑 → 标注 INSUFFICIENT，不得凭空填高。

## 3. 独立性判定

### 3.1 三判据（防过度拆分，源自孵化器方案 §3）

| 判据 | 判定 | 满足条件示例 |
|------|------|--------------|
| 复用率 | 跨项目/跨仓库反复使用 → 倾向独立化 | ≥3 个外部项目实际引用 |
| 独立性 | 与技能库无强耦合、可独立解释 → 倾向独立化 | 调用链可经薄封装代理解耦 |
| 维护成本 | 独立后自管理成本 < 内嵌维护成本 → 独立化 | 演进节奏与本库发布节奏冲突 |

### 3.2 8 维评分（有存量评估报告时复用）

若 `docs/reviews/` 已含全量评估报告（如项目群全量评估：单一职责/独立部署/跨项目复用/团队归属/领域复杂度/依赖隔离/资源隔离/故障隔离，满分 100），直接复用其评分并注明锚点，禁止重复评分。评分参考线：≥80 强烈推荐独立；60~79 可独立需缓解；<60 不独立。

### 3.3 反信号（一刀切防护）

- 三判据 0/3 满足 → 不独立化，继续技能形态维护（先例：EVAL-2026-09-01-001 dev-deploy-tools）
- 独立化后调用率下降/无人维护 → 触发回收入本库（复评条件须写入建议书）

## 4. 产物

```markdown
## 可行性矩阵
| 维度 | 评估 | 档位 |
|------|------|------|
| 技术 | ... | 高/中/低 |
（五维齐备）

## 独立性判定
| 判据 | 实测 | 判定 |
|------|------|------|
| 复用率 | ... | ✅/❌ |
| 独立性 | ... | ✅/❌ |
| 维护成本 | ... | ✅/❌ |

**结论**：<可行性档位> + <独立化倾向>
```

## 5. 门禁

- 五维任一空缺或无依据填高 → 驳回，补充后重评
- 三判据须逐项给实测证据（引用计数/代码量/提交频率等可量化锚点），禁止主观判定
- INSUFFICIENT 维度 >1 → 阻塞，请求用户补充数据
