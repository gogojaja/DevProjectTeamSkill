# 自我诊断：PDCA 五步闭环 / 五层根因 / 哈希链防篡改 / 上下文健康

> 编排器：`../SKILL.md`

---

## 1. 定位

本域合并原 `shared/evolution.md`（SkillEvolutionSkill 技能自省）的**只读诊断**能力与自我改进循环的**写改**能力，形成完整闭环：

| 模式 | 能力 | 写权限 | 产物 |
|------|------|--------|------|
| 只读诊断 | PDCA 五步 / 五层根因 / 哈希链 / 健康监控 | 无（只读） | 诊断报告、缺陷清单 |
| 写改循环 | 偏差侦测 → 根因 → 提案 → 实验 → 发布 | 有（经审批） | 改进落地、版本发布 |

> 原则：**先只读诊断，后写改落地**；诊断阶段禁止直接改 SKILL.md。

---

## 2. PDCA 五步闭环诊断（evolve_start）

### 2.1 五步
| 步 | 动作 | 产物 |
|----|------|------|
| P1 | 收集信号（执行记录/复盘/反馈/门禁报告） | 信号清单 |
| P2 | 对比预期 vs 实际，列出偏差 | 偏差清单（见 `deviation-detection.md`） |
| P3 | 根因分析（五层框架） | 根因链（见 `root-cause-analysis.md`） |
| P4 | 提议 P0-P2 分级改进 | 提案卡（见 `improvement-proposal.md`） |
| P5 | 实验验证 + 发布收敛 | 实验报告 + 发布记录 |

### 2.2 触发
- 手动：用户要求「自省」「诊断」「检视技能库」
- 自动（默认关闭）：预设自动条件满足时触发

### 2.3 限制
- 单次会话最多一轮诊断（禁止递归）；
- scope=full_system 且预算 >15K 时拆解或先确认；
- 诊断中禁止触发业务技能。

## 3. 五层根因框架

| 层 | 名称 | 问因方向 |
|----|------|----------|
| L1 | 角色层 | 操作者角色职责/行为是否错位 |
| L2 | 流程层 | 流程步骤/检查点/门禁是否缺失 |
| L3 | 规则层 | 规范/标准/约束是否缺失或冲突 |
| L4 | 上下文层 | 上下文丢失/压缩/残留导致遗漏 |
| L5 | 追溯性层（可选） | 决策/变更/版本是否可追溯 |

前四层必选，第五层可选；每层结论须附证据（证据编号）。

## 4. 哈希链防篡改（evolve_check_log）

### 4.1 机制
- `stored_hash` = SHA256(记录内容 + prev_hash)
- 首条 = 创世基线（`genesis` 建立）
- 篡改 → 链断裂 → `check` 定位首条断点

### 4.2 存储
| CSV | 内容 |
|-----|------|
| `Skill_Evolution_Log.csv` | 演进记录（含哈希链） |
| `Skill_Lessons_Learned.csv` | 经验教训（含哈希链） |

### 4.3 触发
- 怀疑篡改 / 定期校验（月度）
- 快照与基线完整性校验（配合 solidify 快照）

## 5. 上下文健康监控（ctx_health_check）

### 5.1 五项指标
| 指标 | 说明 |
|------|------|
| Token 占用率 | 已用 / 上限 |
| 轮次 | 对话轮数 |
| 工具输出累积 | 工具输出量 |
| 技能负载 | 已载入角色包数 |
| 关键信息位置 | 关键内容在上下文中的位置深度 |

### 5.2 四级预警
| 级别 | 阈值 | 动作 |
|------|------|------|
| 绿 | 0-60% | 正常 |
| 黄 | 60-75% | 提示，考虑整理 |
| 橙 | 75-85% | 介入，压缩瘦身（MicroCompact） |
| 红 | 85%+ | 强制压缩，先 solidify 固化 |

### 5.3 执行频率
- 每轮对话后自包含执行；
- 阶段切换前强制检查；
- 红区强制压缩后**重读 `references/iron_rules.md`** 作锚点。

---

## 6. 只读安全铁律

1. 诊断模式**只读**：禁止改 SKILL.md、删移文件；
2. 每条缺陷须附证据编号（`#` 引用）；
3. 提案 P0-P2 分级，不得无限扩散；
4. 写改必须经审批后才动手（走 `improvement-proposal.md` 生命周期）；
5. 诊断中禁止触发业务技能（只做技能库自省）。

---

## 7. 与写改循环衔接

```
ctx_health_check ──→ 诊断触发
        │
        ▼
PDCA 五步（只读）──→ 偏差清单 + 根因 + 提案
        │
        ▼
提案审批通过 ──→ 写改落地（improvement-proposal → versioned-release）
        │
        ▼
实验验证 + 哈希链记录 + 发布收敛
```
