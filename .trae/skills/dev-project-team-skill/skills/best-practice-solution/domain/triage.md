# Triage 分级（Frame + 档位判定）

> 归属：`../SKILL.md` §2.2.1　版本：v1.2.0

## 1. 目的
把「要学什么」转换为「要决定什么」，并对决策给出可重复的档位判定（LIGHT/FULL），防止低风险请求被拖入全量调研、也防止高风险请求被降档跳评。

## 2. 操作

### 2.1 Frame：决策问题消解
1. 用户请求 → 提问「这个请求真正要**决定**什么？」
2. 列出会改变决策的问题，按影响排序；剔除"有趣但不影响结论"的旁枝
3. 若决策方向互斥且用户未定 → 输出决策问题清单请求确认，不默认选边
4. 无可决策问题（纯信息查询）→ 判为「无决策 → 例行问答」退出前强制过一关：**「若用户后续要落地实施，本结论会被直接采用吗？」——是则不得退出，改判为有决策问题**；确无决策含义才退出转常规回答，并输出一句"为何无决策含义"

### 2.2 分级 4 问
| # | 问题 | 命中 → |
|---|------|--------|
| 1 | 影响范围：单文件 / 模块 / **系统级**？ | 系统级 → FULL |
| 2 | 可逆性：可回退 / **不可逆**（重构/迁移/删除数据）？ | 不可逆 → FULL |
| 3 | 敏感性：涉**生产核心链路或数据变更 / 合规 / 涉密 / 许可证 / 对外契约 / 大额资金**？ | 涉敏 → FULL |
| 4 | 选型锁定：**技术栈/框架/依赖选型且影响跨模块或产生长期锁定成本**？（与可逆性解耦） | 是 → FULL |

任一命中 → FULL；全部不中 → LIGHT（缺省）。

> **判据冲突取最严**：档位判定与用户主张冲突（如"就是小改动/常识问题"）→ 取最严档，防诱导降档。

### 2.3 不可下调黑名单（FULL 强制，禁止降档）
- 架构重构 / 生产核心链路或数据变更 / 合规敏感 / 涉密决策 / 许可证合规 / 对外契约破坏性变更 / 技术栈或框架选型且跨模块或长期锁定 / 金额 ≥5 万元或超单月预算 10%（按项目可裁剪阈值）/ 用户显式要求第三方评审
- 命中黑名单而模型初判 LIGHT → **必须纠正为 FULL**，不得以"就是日常咨询"降档
- 降档留痕：任何经过 Blacklist 豁免的判定须在收敛时记录理由（供审计）

## 3. 产物
```json
{
  "decision_questions": ["按影响排序的决策问题"],
  "grade": "LIGHT | FULL",
  "blacklist_hit": ["命中的黑名单项"] 
}
```

## 4. 门禁
- 未产出档位判定前禁止进入 Research/Draft（禁直接答题）
- 黑名单命中而档位=LIGHT → 判 FAIL，必须重判
