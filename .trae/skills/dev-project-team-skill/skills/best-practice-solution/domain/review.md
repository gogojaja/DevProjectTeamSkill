# Review 第三方多视角评审（FULL）

> 归属：`../SKILL.md` §2.2.4b　版本：v1.1.0

## 1. 目的
对高风险决策方案做多视角评审，收敛形成最优；本库语境下为「多视角自评（非真实第三方）」，必须显式申明并补充真实外部信号。

## 2. 视角集（决策选型专用，缺省 3 视角）
| 视角 | 聚焦 | 输出 |
|------|------|------|
| 架构/技术路线一致性 | 方案是否符合技术路线、可演进性、接口边界 | PASS/FAIL + 意见 |
| 安全合规 | 威胁、合规、敏感信息、数据保护 | PASS/FAIL + 意见 |
| 成本+可演进性 | 实施/维护成本、长期演进、替换成本 | PASS/FAIL + 意见 |
| 性能（按需，≤4 视角） | 延迟/吞吐/资源/扩展性 | PASS/FAIL + 意见 |

> 评审对象真是"代码/文档"时，复用 `multi-perspective-validation` 原装五视角（Architect/CodeReviewer/Security/Test/Performance）。

## 3. 评审动作
1. **独立生成**：各视角先输出证据引用，再输出结论，互不共享中间草稿
2. **显式申明**：报告头部写明「多视角自评，非真实第三方；如需真实第三方，请用户指定外部评审人或转人工」
3. **真实外部信号（必修，≥1 条）**：
   - 真实工具核验（实际编译/测试/跑脚本）
   - 官方文档版本比对（webfetch 核验实际版本与 claim 一致）
   - 人工复核签署（用户/总控确认）
   - 缺失 → 该评审标记「未完成」
4. **裁决规则**：
   - 证据加权（T1/T2 来源数）优先于自我反思
   - 外部信号 > 内部自评
   - 平票：由收敛者裁定，强制记录反信号
5. **防 conformity**：仅真并行（team-orchestration 多 Worker / 多模型）时启用匿名化+防翻转显式提示；串行执行时不做仪式化防翻转，只保留对照证据与反向信号检查

## 4. 产物
```markdown
# 多视角评审报告（FULL）
- 模式：多视角自评（声明确认）＋外部信号清单
- 决策：SIGNED_OFF / CHANGES_REQUESTED / BLOCKED
- 意见清单：CR-001..（观点 | 严重度 | 证据引用）
```
- 报告 CSV 按 MPV `token_standard` §3 规范（UTF-8 BOM），仅回显首 5 行

## 5. 门禁
- 缺失真实外部信号 → 评审记为「未完成」，不可作为 SIGNED_OFF 依据
- BLOCKED → 回到 Draft v0 修订；计入 ≤2 轮收敛，第 2 次 BLOCKED 强制人工确认
- 未经人工确认不得交付 BLOCKED 原方案
