# env-management — 环境管理能力

> 来源：dev-env-manager 项目技能化（项目群规划 v3.0，评分 76/100 → 技能化决策）
> 定位：并行开发环境的**环境层**管理——与 worktree（代码层隔离）互补：worktree 管代码工作区隔离，本域管运行时环境（端口/进程/数据/容器）隔离与生命周期。
> 衔接标准：`../../../../references/environment_topology.md`（双套拓扑）· `../../../../references/environment_standard.md` · `../../../../references/multi_project_isolation.md` §5（CMDB 资产注册）
> 版本：v1.0.0（2026-09-01）

## 1. 双套环境拓扑（继承标准）

| 环境组 | 组成 | 隔离策略 |
|--------|------|----------|
| 非生产组 | dev + test | 共享基础软硬件，文件/端口区间隔离 |
| 生产组 | prod | 独立隔离，不与非生产组共用运行时 |

## 2. 环境资源分配

### 2.1 端口区间分配
每个 worktree/并行任务分配独立端口区间，登记 `20_环境配置.csv`（环境组/端口区间/共用边界/权限角色列）：

```
<project>/<task> 创建 worktree 时：
1. 查 20_环境配置.csv 已占用区间
2. 分配未占用区间（步长 100，如 8100-8199）
3. 写回台账 + 会话元数据（.psm-session.json 增 env 字段）
```

### 2.2 独占资源（CMDB 注册）
大模型容器 / GPU / Docker 单一运行时 / 独占端口等，经 `tools/cmdb/cmdb-cli.py register_env_asset` 登记——先注册先得，冲突升阶 `change_audit` 留痕（对齐 multi_project_isolation §5）。

### 2.3 数据隔离
| 资源 | 隔离方式 |
|------|----------|
| 数据库 | 每任务独立库名/文件（`<project>_<task>_dev.db`） |
| 缓存 | 独立目录或 key 前缀 |
| 日志 | 每任务独立日志目录 |

## 3. 环境生命周期

```
分配（worktree 创建时）→ 使用中（端口/资产占用）→ 回收（worktree 清理时）
```

| 阶段 | 动作 | 台账 |
|------|------|------|
| 分配 | 端口区间 + CMDB 资产注册 | 20_环境配置 / CMDB |
| 使用中 | 环境配置抽取（`record_env_config`，密钥别名） | 20_环境配置 |
| 回收 | 释放端口区间 + `cmdb-cli.py release` + 数据文件清理 | 20_环境配置 / CMDB |

**回收门禁**：worktree `cleanup`/`remove` 前必须先回收环境资源，孤儿资产（注册表有、worktree 无）列入清理报告。

## 4. 环境检查清单（创建时）

- [ ] 端口区间未占用
- [ ] 独占资产已注册（或确认可共享）
- [ ] 数据目录已建且隔离
- [ ] 密钥仅存别名（A 级，对齐铁律 §3）
- [ ] 环境组归属明确（非生产组/生产组）

## 闭环执行系统

### 1. 任务入口
- 输入：创建/清理 worktree 时的环境分配与回收；环境冲突排查
- 前置：项目环境组已定义（20_环境配置）

### 2. 执行状态
待分配 → 已分配 → 使用中 → 回收中 → 已回收

### 3. 验收门禁
- 创建：检查清单（§4）全过；清理：无孤儿资产/端口残留

### 4. 失败处理
- 端口冲突 → 换区间重试；资产冲突 → 升阶 change_audit；回收失败 → 登记孤儿资产待人工清理

### 5. 产出与交接
- 20_环境配置更新 + CMDB 登记 + 会话元数据 env 字段

### 6. 审计记录
- 资产注册/释放、冲突升阶一律留痕（CMDB 审计日志 + 13 台账）
