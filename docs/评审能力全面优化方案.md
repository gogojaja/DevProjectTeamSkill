将评审能力从「方法论完备但工具化不足」升级为「全评审域工具覆盖 + 规则驱动 + Agent 自动编排 + 效能可度量」。

### 第二域：代码与安全评审（行业对标新增）

#### T-08：code_review_agent —— AI 代码审查 Agent

| 项 | 内容 |
|---|------|
| **输入** | `--diff <git diff 或 commit range>` `--output <报告CSV>` `--dry-run` |
| **输出** | 结构化评审报告 CSV：`文件,行号,严重级别,类别,描述,建议修复` |
| **核心逻辑** | ① git diff 解析 → ② 变更文件语言识别 → ③ 静态分析（Pylint/Flake8/Bandit）→ ④ LLM 语义评审（逻辑/安全/架构）→ ⑤ 结果聚合去重 → ⑥ CSV 报告 |
| **解决** | P8 |
| **依赖** | git + 静态分析工具 |
| **预估** | 4h |
| **对接** | `nightly_quality_gate.py` + `commit-run-gates` 决策模式 |

**多层分析架构**（参考 CodeRabbit/PR-Agent）：
```
git diff
  ↓
Layer 1: 静态分析（Pylint/Flake8/Bandit）→ 已知模式问题
  ↓
Layer 2: 影响范围分析（调用链/依赖图）→ 变更影响面
  ↓
Layer 3: LLM 语义评审 → 逻辑漏洞/安全风险/架构问题
  ↓
聚合去重 → 结构化报告（按严重级别排序）
```

## 九、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|:---:|:---:|------|
| code_review_agent LLM 评审误报 | 中 | 中 | Layer 1/2 先过滤已知问题；Layer 3 仅标记不自动修复 |
| dep_vuln_scan 网络依赖 | 中 | 低 | 支持离线模式（本地缓存 CVE 库） |

## 十三、职责边界澄清

### 13.1 T-08 code_review_agent vs quality_gate.py

| 维度 | quality_gate.py（现有） | T-08 code_review_agent（新增） |
|---|---|---|
| **定位** | 运行时门禁（PASS/FAIL 二元判定） | 深度评审（逐文件逐行标注问题） |
| **触发** | post-commit / nightly | post-commit / 手动 / PR |
| **输出** | 门禁结论（PASS/FAIL + 摘要） | 结构化报告（文件/行号/严重级别/建议） |
| **LLM 依赖** | Architect + CodeReviewer 标记为 host seam | Layer 3 独立调用 LLM 语义评审 |
| **分工** | 决定「能否推送」 | 决定「代码质量如何 + 哪里需改」 |

**协作关系**：`commit-run-gates` 先跑 quality_gate（门禁判定）→ PASS 后跑 T-08（深度评审）→ 报告归档。

### 13.2 S-05 security-scan-suite vs nightly_quality_gate.py

| 维度 | nightly_quality_gate.py（现有） | S-05 security-scan-suite（新增） |
|---|---|---|
| **定位** | 夜间全项目编排器（调度各视角门禁） | 安全专项扫描套件（被编排者） |
| **职责** | 调度 + 聚合裁决 + 告警 | 提供安全维度扫描结果（T-09 + desensitize + audit） |
| **关系** | nightly 调用 S-05 作为安全扫描子步骤 | S-05 可独立运行也可被 nightly 编排 |

## 十四、降级与离线策略（补齐可行性）

### 14.1 T-08 code_review_agent 模型降级策略

```
强模型（GPT-4/Claude/Gemini）
  → Layer 1+2+3 全开（静态分析 + 影响范围 + LLM 语义）
  ↓ 不可用/超时
中模型（本地中等模型）
  → Layer 1+2 执行，Layer 3 跳过（仅输出静态分析结果）
  ↓ 不可用
弱模型/无模型
  → 仅 Layer 1（Pylint/Flake8/Bandit 静态分析）
  → 报告标注「仅静态分析，未做语义评审」
```

**检测方式**：启动时探测环境变量 `AGENT_LLM_MODEL`，未设置则降级到 Layer 1+2。

### 14.2 T-09 dep_vuln_scan 离线降级方案

```
在线模式（默认）
  → 调用 OSV API (api.osv.dev) 查询 CVE
  → 实时获取最新漏洞数据
  ↓ 网络不可达
离线模式（自动降级）
  → 读取本地缓存 `tools/dep_vuln_scan/cve_cache.json`
  → 缓存有效期 7 天，超期标注「数据可能过期」
  → 每次在线扫描成功后自动刷新缓存
  ↓ 无缓存
空模式
  → 输出「无法执行漏洞扫描（网络不可达且无缓存）」
  → 不阻断流程，标记为 SKIP
```

## 十七、风险量化与 Phase 缓冲方案

### 17.1 T-08 误报率控制

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| Layer 1 静态分析误报率 | ≤ 10% | Pylint/Flake8/Bandit 已知规则，误报可配置忽略 |
| Layer 3 LLM 评审误报率 | ≤ 30% | 人工抽检最近 10 份报告，标记误报数/总问题数 |
| 综合误报率（Layer 1+2+3 聚合后） | ≤ 20% | T-13 review_metrics 自动统计 |

**超标处理**：综合误报率 > 30% 时，自动降级到 Layer 1+2（关闭 LLM 语义评审），记录到待决策队列。

### 17.2 工具维护成本度量

通过 T-13 review_metrics 持续监控：

| 指标 | 阈值 | 动作 |
|---|---|---|
| 工具月调用次数 | < 5 次/月 | 标记为「低频」，评估是否合并/废弃 |
| 工具故障率 | > 10% | 触发修复，记录到 RAID |
| 工具维护工时 | > 2h/月/工具 | 评估重构或替换 |

### 17.3 Phase 缓冲方案

| Phase | 原始工时 | 缓冲（+15%） | 调整后 |
|---|:---:|:---:|:---:|
| Phase 1 | 12.5h | +1.9h | **14.5h** |
| Phase 2 | 14.5h | +2.2h | **16.5h** |
| Phase 3 | 13.5h | +2.0h | **15.5h** |
| **总计** | 40.5h | +6.0h | **46.5h（~6 人天）** |

**级联延迟对策**：
- Phase 间设 0.5 天缓冲间隔

- Phase 3 独立性强（T-02/T-07/T-10/T-12/T-13 无 Phase 1/2 依赖），可并行启动
