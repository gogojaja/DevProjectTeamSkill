## ✅ 可稳定达成效果

### 1. 问题根因与熔断机制（核心决策）

**问题**：TRAE 等工具反复提交同质化文件——每条小改动即触发「固化→提交→双推→重试」完整闭环，形成高频率低价值提交循环。

**熔断机制（四层）**：

| 层 | 机制 | 触发 | 动作 |
|----|------|------|------|
| L1 提交批量化 | 小改动合并提交 | 同质操作 ≤2 文件/次 且内容关联 | 合并为单次提交，不碎片化 |
| L2 固化频次控制 | 固化阈值 | 1 小时内固化次数 >3 且内容同质 | 提示暂停固化、攒批 |
| L3 不胜任检测 | 卡循环识别 | 同质操作密度 ≥5 次且无实质新进展 | **判定不胜任** |
| L4 交接熔断 | 停止当前工作 | 触发 L3 且确认多次重复 | 立即停止 + 交接 + 推荐替代工具/模型 |

> **证据**：EV-109[high]（今日 17 次提交 10 条同质化）、EV-110[high]（根因链）、EV-112[high]（DORA VSM 等待时间/瓶颈指标）、EV-113[high]（GitHub PR 聚合提交标准）

### 2. 不胜任判定与交接（行业实践对齐）

**判定规则**：同质操作密度（固化/提交/推重试）≥5 次/会话 且无实质新进展 → **判定不胜任**，立即：
1. 停止当前工作（不再重试/不再机械固化）
2. 开始交接（写 `交接文档.md` 断点 + 13 台账留痕）
3. 推荐替代工具/模型（按 `references/dev_platform_catalog.md` 平台矩阵给出候选）

> **证据**：EV-114[medium]（wait time 领先指标 + 卡循环信号）、EV-116[high]（交接即知识保留 + 交接文档 L1/L2/L3 载体现成）

### 3. 触发频率与阈值参数化

| 指标 | 阈值 | 说明 |
|------|------|------|
| 同质操作次数 | ≥5 次/会话 | 触发不胜任检测 |
| 固化频次 | >3 次/小时 | 提示攒批（L2） |
| 碎片提交 | ≤2 文件/关联变更 | 合并提交（L1） |
| 推送重试 | >2 次连续失败 | 触发网络熔断（已有） |

> **证据**：EV-115[medium]（反信号——阈值可调避免误伤高频有效操作）

### 4. 防误熔断（反信号）

- **区分**「高频有效操作」（自动化发布/正常迭代）vs「同质无进展操作」（碎片提交循环）——阈值只对后者生效
- 阈值参数化存 `references/token_standard.md §7` 或新 `.mechanism.yml`，可调

## 决策记录草案

- **标识**：ADR-2026-08-29-002（待架构角色正式编号）
- **决策**：建立「同质操作熔断 + 不胜任检测」四层机制（提交批量化→固化频次控制→不胜任判定→交接熔断），对齐 DORA VSM（等待时间/瓶颈）与 GitHub PR（聚合提交）
- **选项**：
  - A. 维持现状（无熔断）→ ❌ 碎片提交循环持续
  - B. **四层熔断机制（本方案）** → ✅ 阈值可配、防误熔断、交接有载体
  - C. 仅提交批量化（无不胜任判定）→ ⚠️ 治标不治本、卡循环仍可能
  - D. 全自动停工作（阈值过严）→ ❌ 误伤高频有效操作（DORA 反信号）
- **理由**：EV-109/110 复盘数据确证问题；EV-112/113 行业锚定；L3/L4 对齐「卡循环停止」共识
- **已验证**：今日 32 台账可见多次推送重试（失败 30.8s）；13 审计有四维定位可回溯
- **不确定**：同质操作阈值（5 次/会话）需实测校准
- **未关闭风险**：自动部署场景的误熔断（反信号已设阈值区分）
- **反信号**：若阈值过严导致有效高频操作被熔断 → 调高阈值/区分实质内容
