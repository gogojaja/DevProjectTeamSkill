## ✅ 可稳定达成效果

### 1. 交接文档分层结构（核心结构性改动）
将 `交接文档.md` 重构为 **三层结构**，小模型仅需加载 L1 即可完成关键决策：

| 层级 | 名称 | 目标模型 | 加载触发 | 核心内容 | 预估 Token |
|------|------|----------|----------|----------|------------|
| **L1 必读核心** | 关键决策摘要 | 所有模型（含小模型） | 新会话/新模型**必读** | 当前阶段/角色/任务边界、关键风险/阻塞、下一步唯一动作、铁律锚点(授权/备份/留痕)、Iron Rules #15 执行合同闸门 | **~800 token** |
| **L2 标准上下文** | 标准工作集 | 中/大模型 | L1 判定"需要更多上下文"时按需加载 | 详细工作断点、台账指针、关键文件索引、进行中/待办列表、跨会话交接记录 | ~2,500 token |
| **L3 完整归档** | 全量归档 | 大模型/归档审计 | 显式要求/回溯分析 | 历史固化记录、完整变更日志、废弃资产清理记录、历史评审报告 | ~8,000+ token |

> **证据**：EV-001[high](ACON 适度阈值最优)、EV-007[high](当前扁平结构对小模型不友好)、EV-003[medium](OMP 多策略分层) 「证据: EV-001[high], EV-003[medium], EV-007[high]」

### 2. 显式 Token 预算分配（token_standard §1.3 扩展）
在 `token_standard.md` 新增 **§7 交接预算**，将上下文窗口显式切分：

| 预算项 | 占比 | 硬上限 | 保护策略 |
|--------|------|--------|----------|
| **交接必读预算** | 10% | 2,000 token | L1 必读核心**永不压缩**，始终保留在上下文首部 |
| **工作执行预算** | 75% | 15,000 token | 常规压缩策略（滚动窗口/语义去重/工具输出剪枝） |
| **压缩缓冲/系统预留** | 15% | 3,000 token | 系统提示词、iron_rules.md、工具调用开销 |

> **证据**：EV-006[high](现有预算无显式交接分配)、EV-002[medium](Hermes token-budget型尾部保护)、EV-001[high](ACON 阈值 4096/1024 经验值) 「证据: EV-001[high], EV-002[medium], EV-006[high]」

### 3. Handoff 专用压缩策略（三模式可配）
参考 OMP/Hermes，在 `token_standard.md §1.3` 增补 **handoff 专用配置段**，新增三种策略供项目按模型能力选择：

| 策略 | 适用场景 | 核心机制 | 小模型友好度 |
|------|----------|----------|--------------|
| **handoff-struct** (默认) | 小模型/受限上下文 | 结构化摘要保留：仅保留 L1 核心 + 关键实体索引(阶段/角色/风险/阻塞/下一步) + Iron Rules 锚点，其余折叠为 `{{folded:N sections}}` 占位符 | ⭐⭐⭐⭐⭐ |
| **handoff-full** | 中/大模型 | 完整 L1+L2 保留，L3 折叠，工具输出剪枝+语义去重 | ⭐⭐⭐ |
| **handoff-snap** | 极度受限/离线 | Snapcompact 思路：折叠段落渲染为极简文本索引（无图像依赖），仅保留实体指针，恢复时按需展开 | ⭐⭐⭐⭐ |

> **证据**：EV-003[medium](OMP 三策略)、EV-002[medium](Hermes 双层+尾部保护)、EV-005[low](工具输出剪枝可内嵌工作流) 「证据: EV-002[medium], EV-003[medium], EV-005[low]」

### 4. 结构化摘要生成与辅助压缩模型
新增 **交接摘要生成器**（`tools/handoff_summarizer.py`），在 `solidify.sh` 固化时自动执行：

- **输入**：完整交接文档 + 当前阶段/角色/任务上下文
- **输出**：L1 核心摘要（结构化 Markdown，含实体索引）
- **模型**：可配置辅助模型（默认 `qwen2.5-coder:7b` 本地小模型，满足 Hermes"辅助模型上下文≥主模型"要求）
- **触发点**：`solidify.sh` §2 刷新断点区前自动运行
- **保护**：L1 摘要写入交接文档头部 `## 0. L1核心摘要`，受 `token_standard §7` 交接预算保护

> **证据**：EV-002[medium](Hermes 辅助模型上下文≥主模型、结构化摘要)、EV-001[high](小模型可做压缩)、EV-003[medium](OMP 独立 handoff 任务) 「证据: EV-001[high], EV-002[medium], EV-003[medium]」

### 4.1 语义去重 Embedding 模型选型与资源量化（CR-004）
语义去重不再引入额外模型，**复用本地 `qwen2.5-coder:7b` 做 mean-pooling embedding**（最后一层隐藏状态平均池化），零额外模型部署：

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **模型** | `qwen2.5-coder:7b` (Ollama 本地) | 复用现有部署，mean-pooling 最后一层 hidden state |
| **向量维度** | 3584 | qwen2.5-coder 隐藏层维度 |
| **内存峰值** | ≤1.2 GB | 模型权重(~4.5GB量化) + KV缓存 + embedding批次(≤32条×3584) |
| **CPU 占用** | <30% (单核) | 批次推理 ≤32 条/次，无 GPU 依赖 |
| **延迟** | <200 ms / 32 条 | 单次前向传播，纯 CPU 推理 |
| **向量持久化** | **无** | 仅内存计算相似度，用后即丢，**不落盘、不入库** |

> **证据**：EV-001[high](小模型可做压缩)、EV-007[high](已有 Ollama 部署)、EV-002[medium](Hermes 辅助模型复用) 「证据: EV-001[high], EV-002[medium], EV-007[high]」

### 5. 预压缩优化管道（零额外 LLM 调用）
在现有工作流内嵌预压缩步骤（参考 BuildMVP "工具输出剪枝内嵌工作流"）：

| 步骤 | 触发时机 | 操作 | Token 节省 |
|------|----------|------|------------|
| **工具输出剪枝** | 每次工具调用返回 | 仅保留 `stdout` 关键行/错误/结果摘要，丢弃冗长日志/进度条 | 20-40% |
| **敏感数据脱敏** | 语义去重前 | 强制运行 `desensitize.py --dictionary tools/desensitize/desensitize_dictionary.csv` 对文本脱敏（A/B/C 级全覆盖），**仅脱敏后文本进入 embedding**，向量**仅内存计算、不落盘、用后即丢** | — |
| **语义去重** | 脱敏后/每轮对话结束 | 计算消息嵌入相似度(阈值 0.85)，仅保留最信息密集版本 | 15-25% |
| **边界对齐保护** | 压缩前 | 识别 tool_call/tool_result 组，保持组完整不拆分 | 防信息丢失 |

> **证据**：EV-005[low](工具输出剪枝内嵌工作流)、EV-002[medium](Hermes 边界对齐 `_align_boundary_backward`)、EV-004[medium](OpenCode 请求预算)、「CR-002 修正：脱敏前置」 「证据: EV-002[medium], EV-004[medium], EV-005[low]」

## ⚠️ 理论最优效果与当前限制

| 限制/风险 | 说明 | 缓解/反信号 |
|-----------|------|-------------|
| **L1 核心摘要可能遗漏边缘关键信息** | 结构化摘要必然有损压缩 | 关键风险/阻塞/下一步动作字段强制保留；提供"展开 L2"显式触发词 |
| **辅助压缩模型需部署维护** | 需本地小模型(qwen2.5-coder:7b)常驻 | 复用现有 Ollama 部署；fallback 到纯规则摘要(正则/关键词提取) |
| **三策略配置增加复杂度** | 项目需按模型选择策略 | 提供智能默认：检测模型上下文窗口/能力档位自动选策略 |
| **技能按需加载需架构重构** | 涉及编排器加载机制大改 | 列为可选增强(独立 PR)，核心交接优化不依赖此项 |
| **Snapcompact 无视觉模型回退** | 本库无视觉模型部署 | `handoff-snap` 降级为纯文本索引模式，不依赖图像渲染 |
| **现有固化脚本耦合度高** | `solidify.sh` 需注入摘要生成器 | 通过环境变量/参数解耦，保持脚本接口不变 |

## 决策记录（SIGNED_OFF）

- **标识**：ADR-2026-08-28-001（已预置模板于 `架构资产/01_架构策略/ADR-2026-08-28-001.md`，待架构角色正式编号/登记追溯矩阵）
- **决策**：实施三层交接文档结构 + 显式交接预算 + 三模式 Handoff 策略 + 摘要生成器 + 预压缩管道（含脱敏前置/Embedding模型复用/性能基准门禁）
- **选项对比**：
  - A. 仅优化压缩阈值（低投入/低收益/不解决小模型根本问题）
  - B. **三层结构+显式预算+三策略+摘要生成器+预压缩管道+性能门禁**（本方案，中投入/高收益/解决根因）

  - D. 完全依赖大模型/扩大上下文窗口（不解决成本/受限环境问题）
- **理由**：EV-001/002/003 证据链支撑分层预算+多策略；EV-007 定位当前痛点；P1 独立可交付不依赖 P3；CR-001~004 已全部在方案中闭环

- **不确定**：小模型摘要质量阈值需实测校准（fallback 纯规则摘要）
