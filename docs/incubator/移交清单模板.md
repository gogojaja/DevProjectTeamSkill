# 移交清单模板（孵化器 → 独立项目/运营者）

> **用途**：孵化决策为「移交独立项目」后，将方案+评审+证据卡+ADR 移交独立项目运营者的标准清单（孵化器方案 M2 产物，对齐 `docs/孵化器模式与git剥离方案.md` §1/§3 与 `docs/incubator/INC-*.md` 实操范式）
> **职责边界**：孵化器只出方案与登记，**不代落地**；本清单移交完成即孵化器收口，后续仅登记引用（不内嵌）
> **关联技能**：`incubator-initiation`（`domain/handover-list.md`）

---

## 一、移交产物清单

| # | 产物 | 路径/标识 | 移交状态 |
|---|------|-----------|----------|
| 1 | 立项建议书 | `docs/incubator/INC-<日期>-<序号>_<对象名>.md` | ☐ |
| 2 | 方案文档（如有独立方案） | `docs/<方案名>.md` | ☐ |
| 3 | 证据卡 | 入库于 `docs/` 目录（命名：证据卡前缀 + 对象 + 日期，参照本目录存量 INC 关联文件与 `check_review_artifacts.py` 入库规则） | ☐ |
| 4 | 评审报告 | `docs/reviews/评审报告_<对象>_<日期>.csv/md` | ☐ |
| 5 | 决策记录草案（ADR） | 交 `role-architecture` 正式化编号 | ☐ |
| 6 | 关联技能/方法论（单一信源互补） | `.trae/skills/role-*/` | ☐ |
| 7 | 复评条件与观察期 | 见本模板 §四 | ☐ |

## 二、登记闭环（五项，缺一不可）

| # | 登记项 | 位置 | 完成 |
|---|--------|------|------|
| 1 | 独立项目登记 | `references/project-registry.md`（项目名/路径/授权号/单一信源声明） | ☐ |
| 2 | AGENTS.md 登记 | 仓库根 `AGENTS.md` 独立关联项目区（薄封装代理调用说明） | ☐ |
| 3 | 授权登记 | `台账/14_授权登记.csv`（`register_auth`，铁律 #7a） | ☐ |
| 4 | 审计留痕 | `台账/13_安全审计台账.csv`（`tools/audit.py` 四维，铁律 #7） | ☐ |
| 5 | 交接断点 | `交接文档.md` 待办/进行中工作区 | ☐ |

## 三、移交前检查（强制）

- ☐ **脱敏**：移交产物跑 `tools/desensitize/desensitize.py --scan`（铁律 #8：A 级禁入库、B 级脱敏后复查全文）
- ☐ **评审模式申明**：评审产物含「评审模式 + 真实外部信号 ≥1 条」标注（check_review_artifacts 门禁）
- ☐ **单一信源声明**：明确「方案/标准以独立项目为唯一权威，本库不保留实现，仅薄封装代理调用 + 引用登记」
- ☐ **无内嵌实现**：本库不迁移/不保留落地代码（工具实现归独立项目）

## 四、复评条件与回收机制

| 项 | 内容 |
|----|------|
| 复评条件 | <满足任一即重新评估：如 ≥3 外部项目实际复用 / 代码量或耦合度达阈值 / 演进节奏冲突> |
| 观察期 | <如：3 个月> |
| 回收反信号 | 独立化后调用率下降 / 无人维护 → 回收入本库保持单源 |
