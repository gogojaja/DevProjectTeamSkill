## 1. 背景与目标

### 1.1 背景

2026-09-07 TwinForge 项目发生「脱敏工作目录误入库」事件：`脱敏工作/` 目录（含反向映射表）被 `git add -A` 卷入提交 `6497d3e`，虽已通过历史改写 + 强推 + gc 彻底清除，但暴露出现有机制的系统性缺陷：

- **依赖人工自觉**：仅靠 .gitignore + 人工检查，无自动化拦截
- **无项目级强制继承**：新项目可能不声明遵守 §3.2
- **无审计机制**：无定期检查各仓库是否合规
- **无事件响应流程**：发现泄密后如何处置无标准流程

### 1.2 目标

建立**系统级涉密信息管理铁律机制**，确保：

1. **零泄密文件入库**：通过自动化扫描 + 人工检查双重防线
2. **全项目强制继承**：所有启用项目必须声明遵守并落实
3. **事件可追溯**：发现泄密后有标准响应流程
4. **定期可审计**：有检查清单和审计记录

## 2. 行业最佳实践调研

### 2.1 工具层

| 工具 | 类型 | 优势 | 适用场景 |
|------|------|------|---------|
| **gitleaks** | 静态扫描 | Go 实现，速度快，100+ 规则，支持自定义 | Pre-commit hook + CI/CD |
| **trufflehog** | 静态扫描 + 验证 | 800+ secret 类型，可验证有效性 | 历史扫描 + CI/CD |
| **git-secrets** | AWS 官方 | 专注 AWS 凭据 | AWS 环境 |
| **BFG Repo-Cleaner** | 历史清理 | 比 git filter-branch 快 10-720x | 大规模历史改写 |

### 2.2 流程层

**GitHub 推荐流程**：
1. **Pre-commit hook**（本地拦截）：gitleaks protect --staged
2. **CI/CD 门禁**（远端拦截）：PR 触发 gitleaks 扫描，失败则阻止合并
3. **定期全量扫描**：每周/每月 gitleaks detect --source .
4. **事件响应**：发现泄露 → 立即轮换密钥 → 改写历史 → 通知团队

**OWASP 建议**：
- 分类分级（Public / Internal / Confidential / Restricted）
- 最小权限原则
- 密钥轮换周期（90 天）
- 审计日志保留 1 年

### 2.3 组织层

**SANS 框架**：
- 安全冠军（Security Champion）：每个团队指定 1 人负责安全审查
- 威胁建模（Threat Modeling）：项目启动时识别敏感数据流
- 安全编码培训：每年至少 1 次

## 4. 铁律机制设计

### 4.1 总体架构

```
┌─────────────────────────────────────────────┐
│  第一道防线：.gitignore 硬约束              │
│  - 泄密文件路径必须写入 .gitignore          │
│  - git check-ignore -v 实测命中            │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  第二道防线：Pre-commit 自动扫描            │
│  - gitleaks protect --staged               │
│  - 命中则阻止提交                           │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  第三道防线：人工复核                       │
│  - 提交前 git diff --cached 回看           │
│  - 确认无 3.2.1 类文件                      │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│  第四道防线：定期审计                       │
│  - 每月 gitleaks detect --source .         │
│  - 审计结果记入 13_安全审计台账            │
└─────────────────────────────────────────────┘
```

### 4.2 新增铁律条款

#### 4.2.1 增强 §3.2（泄密文件禁令）

在现有 §3.2 基础上增加：

**§3.2.4 项目级强制继承**

所有启用 DevProjectTeamSkill 的项目必须：

1. 在项目章程或 AGENTS.md 中声明「遵守 iron_rules.md §3.2 泄密文件禁令」
2. 项目初始化时（role-project-init）检查 .gitignore 是否包含 §3.2.1 类文件的屏蔽规则
3. 未声明遵守的项目禁止进入生产环境

**§3.2.5 事件响应流程**

发现涉密文件已入库时，必须按以下流程处置：

1. **立即隔离**：停止该仓库的所有推送操作，通知 PMO
2. **评估影响**：确定泄露文件类型、影响范围、是否已推送远端
3. **处置决策**：
   - 未推送：`git reset --soft HEAD~1` + 重新提交
   - 已推送本地：`git push --force-with-lease` 强推改写后的历史
   - 已推送公共：立即轮换所有可能泄露的密钥，通知相关方
4. **彻底清除**：`git reflog expire --expire=now --all && git gc --prune=now`
5. **事后复盘**：记入 `13_安全审计台账.csv`，分析根因，更新 .gitignore

**§3.2.6 审计检查清单**

每月审计时检查：

- [ ] .gitignore 是否包含 §3.2.1 类文件的屏蔽规则
- [ ] `git check-ignore -v <路径>` 实测是否命中
- [ ] `gitleaks detect --source .` 扫描是否通过（如已配置）
- [ ] 最近 30 天提交是否包含敏感文件
- [ ] 项目章程/AGENTS.md 是否声明遵守 §3.2

#### 4.2.2 新增 Pre-commit Hook 模板

在 `references/` 下新增 `pre-commit-hook-template.sh`：

```bash
#!/bin/sh
# Pre-commit hook: 涉密文件自动扫描
# 安装方式：cp references/pre-commit-hook-template.sh .git/hooks/pre-commit

# 第一关：.gitignore 检查
echo "[pre-commit] 检查 .gitignore 是否包含泄密文件屏蔽规则..."
if ! grep -q "脱敏工作" .gitignore 2>/dev/null; then
  echo "❌ .gitignore 缺少「脱敏工作/」屏蔽规则"
  echo "   请按 iron_rules.md §3.2.2 添加"
  exit 1
fi

# 第二关：gitleaks 扫描（如已安装）
if command -v gitleaks >/dev/null 2>&1; then
  echo "[pre-commit] gitleaks 扫描暂存区..."
  gitleaks protect --staged --verbose
  if [ $? -ne 0 ]; then
    echo "❌ gitleaks 检测到敏感信息，提交已阻止"
    exit 1
  fi
else
  echo "[pre-commit] gitleaks 未安装，跳过自动扫描"
  echo "   建议安装：winget install Gitleaks.Gitleaks"
fi

echo "[pre-commit] ✅ 检查通过"
```

#### 4.2.3 新增项目初始化检查项

在 `role-project-init` 中增加：

```python
# 涉密信息管理检查
def check_sensitive_info_compliance(project_root):
    """检查项目是否遵守 iron_rules.md §3.2"""
    
    # 1. 检查 .gitignore 是否包含泄密文件屏蔽规则
    gitignore_path = os.path.join(project_root, '.gitignore')
    if not os.path.exists(gitignore_path):
        return False, "缺少 .gitignore"
    
    with open(gitignore_path, 'r', encoding='utf-8') as f:
        content = f.read()
    
    required_patterns = ['脱敏工作/', '反向映射', '术语替换表']
    missing = [p for p in required_patterns if p not in content]
    if missing:
        return False, f".gitignore 缺少: {', '.join(missing)}"
    
    # 2. 检查项目章程或 AGENTS.md 是否声明遵守 §3.2
    agents_path = os.path.join(project_root, 'AGENTS.md')
    charter_path = os.path.join(project_root, '项目章程.md')
    
    declared = False
    for path in [agents_path, charter_path]:
        if os.path.exists(path):
            with open(path, 'r', encoding='utf-8') as f:
                if '§3.2' in f.read() or '泄密文件' in f.read():
                    declared = True
                    break
    
    if not declared:
        return False, "未在项目章程或 AGENTS.md 中声明遵守 §3.2"
    
    return True, "合规"
```
