## §2 根因分析（四项 Gap）

1. **Contract-Gap（契约空白）**：此前无书面执行合同模板（清单→确认→执行），仅口头/偏好文字，大上下文下 AI 易把"同路径授权过"误判为"本次也授权做"，产生 E-01「顺带扩展」。
2. **Scope-Gap（授权粒度粗）**：`AUTH-xxx` 粒度是「路径/文件」，非「操作项列表+参数」。路径级授权无法拦截同路径下顺带做别的事（行业称 `approval parameter binding`，授权须绑定命令参数哈希，参数变授权失效）。
3. **Gate-Gap（缺前置闸门）**：缺高风险操作 pre-tool gate。Edit/Write/Tier-3 操作执行前无结构化 pause-and-wait 节点（对照 Zalt 2026「Tier3 高辐射工具须先暂停做人审门禁」）。
4. **Memory-Gap（记忆易截断）**：禁令只存偏好长文，跨会话摘要截断可能漏看，缺最小固定铁律片段（放在 Prompt 开头或 tool 前置条件）。

## §4 六段执行合同（强制）

> 适用范围：**每一次带副作用操作（不含纯读）**必须走完 6 段；未过闸门 = 不允许执行。

1. **理解段**：复述用户本次指令的「明确操作项列表」（只列名词，不含推理）。
2. **拆解段**：把每项拆为【目标文件 / 改什么 / 不改什么 / 改动量级】。
3. **清单段**：输出结构化改动清单（对齐 §6 审批五要素）。
4. **确认段**：明确要求用户输出**特定确认词**——白名单：`执行` / `OK` / `确认` / `改吧` / `方案X`（用户自定义字母编号）。**不接受模糊措辞**（如"你看着办""随便"），未等到确认词前什么都不做。
5. **执行段**：严格按清单执行；参数若有变化必须回确认段重确认。
6. **复验段**：执行后给出通过/失败的**客观证据链**，不允许用"我认为成功了"替代。

## §7 参数哈希绑定与重确认

- **绑定对象 3 项**：①操作名 ②目标路径 ③改动内容 SHA-256 前 10 位（由 `tools/audit.py --param-hash` 自动算）。
- **变更→回确认段流程 3 步**：参数变更（换目标文件/改条目数/换写法/加新操作）→ 暂停当前执行 → 输出变更清单 → 重新等确认词 → 新审批生效、**旧审批哈希作废**。
- **行业出处**：PlanVault checklist #14（approval parameter binding）+ Zalt 2026（Tier3 高辐射须参数绑定）。本仓库裁剪：哈希写入台账 13，机器可比对变更。
- 未重确认即变更 = **越界反弹**（红灯，见 §8）。

## §8 越界识别红黄灯 + 回滚 SOP

**红灯（≥1 条即越界）**
1. 未确认即执行（无确认词留痕）；
2. 顺带做范围外操作（同路径/同会话夹带未授权项）；
3. 参数变了不重申请（旧哈希仍用）；
4. 路径越界（写项目外/系统文件未走 #7 授权）。

**黄灯（要素不全，须补齐再确认）**
1. 清单要素不全（缺 §6 五要素之一）；
2. 风险级标低（Tier3 误标 Tier2）；
3. 接受模糊确认词（未用 §4 白名单）。

**回滚 SOP 3 步**
1. **证据保全**：冻结当前改动、导出 diff、登记 `13_安全审计台账.csv`；
2. **还原备份**：`git checkout` / 从 `/.backup/` 还原到即时备份点；
3. **记违规次数**：在 `13` 台账标红灯 + 累计违规计数；**连续 2 次红灯 → 进入「全闸模式」**：下一轮所有 Tier2/Tier3 操作须走完整 6 段合同 + **额外再要一轮确认词**；1 次完整合规操作后解除。

## §10 非功能性需求（NFR）

- **NFR-1 可审计性**：文档每节有可引用标题锚点；所有外部来源有标题+日期+裁剪说明。
- **NFR-2 可执行性**：所有制度条款均为二值判定（过闸门/不过），无模糊建议；`tools/audit.py` 提供机器可执行的参数哈希绑定。
- **NFR-3 跨会话持久化**：合同锚点落在 AGENTS.md #15（每次会话必加载），台账列扩展可回溯，不依赖易丢失的偏好记忆。
- **NFR-4 可读性**：正文不超过 **6,000 中文字**（当前约 3,500 字），表格/加粗/代码块丰富，5 分钟可读通核心 6 段合同。
- **NFR-5 不入库执行代码**：本文档仅交付 md + csv 两份文档产物，无 .py/.sh 可执行代码。

## 附录 B：常见问答

- **Q1 只读操作要不要清单？** 否。Tier1 只读自由执行，合同仅约束带副作用操作。
- **Q2 "改了就行"算确认词吗？** 不算白名单词（模糊）。建议回「执行」类词；若用户坚持，须在清单中显式列出并获「执行」确认。
- **Q3 全闸模式持续多久？** 进入后，下一轮所有 Tier2/Tier3 走完整 6 段 + 额外一轮确认；**1 次完整合规操作后自动解除**。
