# DevProjectTeamSkill v21.2.1 方案：敏捷迭代模式 + 迭代内多线并行

> 目标：为现有 8 角色包体系新增**敏捷迭代执行模式**，实现从需求到投产的快速交付（MVP 迭代 10 个工作日），并在敏捷模式下支持**迭代内多线并行**。
> 本文为**方案文档**，仅定义模式设计、契约、门禁分级与改造清单，不直接修改技能库。经确认后按 `common_standards.md` §3 快照 + skill-authoring 流程逐项落地。
>
> **本期范围**：仅实现「纯敏捷迭代」与「敏捷内并行」；瀑布内阶段重叠、混合多线并行等高风险方式**本期不执行**（见 §6 风险闸口）。
>
> **v21.2.1 修订**（按行业最佳实践评审，见 `评审报告_敏捷迭代模式方案_v21.2.0_缺陷.csv`）：补 Velocity/容量规划（P0-1）；补迭代回顾（P0-2）；发布级门禁增自动化质量阈值（P1-1）；技术债显式管理（P1-2）；DoD 达「潜在可发布」（P1-3）；架构角色随迭代演进（P1-4）；迭代内范围冻结（P1-5）；测试左移（P1-6）；补门禁防绕过机制（P2-4）；基线对比（P2-2）。

## 0. 现状与设计约束

| 项 | 现状 | 约束 |
|----|------|------|
| 执行模式 | 5 种：标准（瀑布）/ 阶段裁剪 / 单角色 / 多角色联合 / 双角色裁剪 | 阶段门禁 + 基线固化是质量底线 |
| 流程裁剪 | `init_tailor` 产出 `00_阶段配置.csv`（台账 17→18 CSV） | 敏捷模式复用裁剪机制，不重建 |
| 角色包 | 8 包：启动/需求/架构/开发/测试/投产/总控 + 编排器 | 角色隔离铁律不破：任务限本角色包内 |
| 台账 | 18 CSV（UTF-8 with BOM） | 复用，迭代数据以新增列承载，不新建台账 |
| 上下文 | 追加式，靠 compaction 回收 | 迭代切换强制压缩（token_standard §1.3） |

**核心原则**：用「迭代级轻量评审」换速度，用「发布级强门禁」守质量。**发布级门禁（stage_review + check_gate + solidify_baseline）在任何模式下均不可裁剪。**

## 1. 方案一：敏捷迭代模式（纯敏捷迭代）

### 1.1 模式定位（编排器 §3 新增一行）

| 模式 | 触发 | 节奏 | 门禁策略 |
|------|------|------|----------|
| 标准（默认，瀑布） | 全生命周期 | 阶段序贯 | 每阶段强门禁 |
| **敏捷迭代（新增）** | "用敏捷/迭代/快速上线" | 1~2 周迭代 | 迭代轻量评审 + **发布级强门禁** |

### 1.2 迭代配置（init_tailor 扩展）

启动阶段执行 `init_tailor`，在 `00_阶段配置.csv` 基础上新增产出 `01_迭代配置.csv`：

| 列 | 说明 |
|----|------|
| 迭代编号 | IT-01、IT-02… |
| 周期（天） | 5~10（1~2 周） |
| 吸收容量 | 迭代承诺规模 = 上期 Velocity × 可用人日（P0-1） |
| MVP 范围 | 本迭代吸收的 PBI 清单（MoSCoW 优先，S/M/L 规模估算） |
| 技术债登记 | 本迭代产生的技术债 + 偿还迭代计划（每 N 迭代 ~20% 容量）（P1-2） |
| DoR | 可进入迭代的前置条件 |
| DoD | 迭代完成标准（缺陷关闭 + 文档更新 + **部署预生产/金丝雀 + 冒烟通过**）（P1-3） |
| 发布点 | Y/N，仅 Y 触发发布级门禁 |
| 角色包范围 | 本迭代启用的角色包（通常需求+开发+测试，可选部署） |

### 1.3 需求粒度与范围冻结（role-requirements-analysis）

- 新增 `iterate_backlog` action：需求按 EARS 原子化拆条进**产品待办（PBI）**，跳过全量 SRS；仅发布点要求输出迭代版需求基线。
- PBI 规模估算：S/M/L（S=0.5d、M=1d、L=2d），作为容量规划输入（P0-1）。
- MoSCoW 优先级：MUST 优先吸收，SHOULD 视容量，COULD/WON'T 顺延。
- **范围冻结（P1-5）**：迭代内范围冻结，需求变更经 `register_change` 登记后**排入下迭代**；仅 P0 缺陷允许迭代内吸收。已冻结的发布点范围不可改动。

### 1.4 门禁分级（role-governance）

| 级别 | 时机 | 内容 | 固化动作 |
|------|------|------|----------|
| 迭代级 | 每迭代末 | 变更审计 + 缺陷门禁 + 台账更新（1 条 CSV）+ **迭代回顾**（P0-2） | 不固化基线 |
| **发布级** | 迭代配置 `发布点=Y` | 完整 `stage_review` + `check_gate` + 全套产出 | `solidify_baseline` |

**发布级 check_gate 自动化质量阈值（P1-1）**：
- 自动化测试通过率 ≥95%；
- 关键路径用例全绿（阻断级 0 遗留）；
- SAST/SCAN 扫描无高危；安全审计（高危操作）通过。

**迭代回顾（P0-2）**：每迭代末输出回顾记录 CSV——「做得好 / 需改进 / 行动项」，作为下迭代改进输入（PDCA 闭环）。

**门禁防绕过机制（P2-4）**：`release_gate` 由 role-governance 独立执行；`01_迭代配置.csv` 无 `发布点=Y` 记录时禁止进入投产（role-deployment），杜绝无门禁发布。

### 1.5 执行节奏（编排器调度）

```
启动(0.5d) → 迭代循环[需求→开发→测试]×N → 发布点强门禁 → 投产(role-deployment) → 固化
                    ↑_____ 迭代末轻量评审 + 回顾 + 压缩 _____|
```

- MVP 最短路径：需求(2d) → 开发(5d) → 测试(2d) → 金丝雀发布(1d) ≈ **10 个工作日**（落地后须与改造前瀑布基线对比验证，P2-2）。
- 迭代切换前执行上下文压缩 + 刷新 `交接文档.md` 断点区。

### 1.6 架构角色在敏捷中的演进（P1-4）

- 首迭代前可选执行「迭代 0」：轻量架构铺垫（技术栈/模块边界/接口契约，1 天）；
- 架构决策随迭代演进：每发布点对新增 ADR 执行评审（role-architecture），防止技术债跨迭代放大。

### 1.7 测试左移（P1-6）

- 开发内联单测：开发角色在编码时产出单测，随 PBI 完成提交；
- 迭代级集成测试：每迭代末跑集成测试（不放行阻断缺陷）；
- 全量回归仅在发布点执行（role-testing），避免测试单线成瓶颈。

## 2. 方案二：敏捷内多线并行

### 2.1 并行模型

| 并行类型 | 说明 | 适用范围 |
|----------|------|----------|
| PBI 线并行 | 同迭代多条 PBI 并行开发，WIP 限制 3~5 条 | 所有敏捷迭代 |
| 特征线并行 | 跨迭代特征并行，特征独立交付 | 模块耦合度低 |
| CI 流水线并行 | 开发/测试/部署流水线自动并行 | 有 CI 环境 |

### 2.2 WIP 限制规则（防上下文切换损耗）

- 单会话/单 Agent 同时进行中的 PBI ≤ 2；
- 团队级并行 PBI 3~5 条（Kanban WIP），超出按优先级排入下迭代；
- WIP 数值按实际吞吐校准（Little's Law，P2-3）；
- 并行线共享同一台账与 role-governance，进度按线聚合登记。

### 2.3 依赖治理

- 并行 PBI 依赖关系在 `01_迭代配置.csv` 显式登记（接口契约先行，`api_contracts.md`）；
- 存在循环/深层依赖的 PBI 禁止并行，按序执行。

## 6. 风险评估与本期限界

### 6.1 本期执行项风险（已管控）

| 风险 | 等级 | 缓解 |
|------|------|------|
| 发布级门禁被稀释 | 高 | **铁律：发布级门禁任何模式不可裁剪 + 防绕过机制（P2-4）** |
| 迭代承诺过载 | 高 | Velocity 容量规划（P0-1） |
| 并行上下文切换损耗 | 中 | WIP 限制（会话级 ≤2）+ Little's Law 校准 |
| 跨迭代上下文丢失 | 中 | 迭代切换压缩 + 交接文档断点刷新 |
| 技术债累积 | 中 | 显式登记 + 每 N 迭代 ~20% 容量偿还（P1-2） |
| 台账/基线失真 | 中 | 并行线统一台账登记，按线聚合 |

### 6.2 本期不执行项（风险闸口）

| 方式 | 不执行原因 | 重新启用条件 |
|------|-----------|--------------|
| 瀑布内阶段重叠（Fast-Tracking） | 门禁串行语义被破坏 | 组织 PMO 成熟度达标且团队独立 |
| 混合多线瀑布并行 | 资源争用 + EVM 聚合失真 | 并行线 ≤2 且模块低耦合 |

## 7. 验收门禁

1. 8 角色包在「敏捷迭代」模式下可完整跑通 MVP 路径（需求→投产 ≤10 工作日，且优于改造前瀑布基线，P2-2）；
2. 发布级门禁在迭代模式全程生效（不可跳过、不可降级，防绕过机制生效）；
3. `01_迭代配置.csv`（含容量/技术债列）+ `02_迭代回顾.csv` 生成，台账 20 CSV 结构校验通过；
4. 新 action 契约登记 + SKILL_INDEX 同步 + shared 副本 SHA256 一致；
5. 交接文档断点区反映最新状态。
