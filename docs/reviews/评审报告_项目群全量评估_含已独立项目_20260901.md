## 二、评估框架：项目独立性判定标准（增强版）

### 2.1 行业最佳实践来源

| 来源 | 原则 | 适用性 |
|------|------|--------|
| **Domain-Driven Design (DDD)** | 限界上下文独立部署 | 高 |
| **Microservices Pattern** | 单一职责、独立部署、跨服务复用 | 高 |
| **Conway's Law** | 系统结构反映组织结构 | 中 |
| **Three Criteria Rule** | 复用率 / 独立性 / 维护成本 | 高 |
| **Google Monorepo Practice** | 相关工具共享仓库，独立工具独立仓库 | 中 |
| **Netflix Microservices** | 独立部署、故障隔离、团队自治 | 高 |
| **Spotify Model** | 小队自治、服务独立 | 中 |

### 2.2 独立性判定八维度（增强版）

| 维度 | 问题 | 权重 | 评分标准 |
|------|------|------|----------|
| **1. 单一职责** | 是否有明确的、聚焦的业务目标？ | 15% | 0-15 |
| **2. 独立部署** | 是否需要独立的发布周期？ | 10% | 0-10 |
| **3. 跨项目复用** | 是否被多个项目依赖？ | 20% | 0-20 |
| **4. 团队归属** | 是否有独立的团队可以拥有？ | 5% | 0-5 |
| **5. 领域复杂度** | 是否足够复杂需要独立维护？ | 15% | 0-15 |
| **6. 依赖隔离** | 是否隔离它能降低耦合？ | 15% | 0-15 |
| **7. 资源隔离** | 是否需要独立的基础设施？ | 10% | 0-10 |
| **8. 故障隔离** | 故障是否会影响其他项目？ | 10% | 0-10 |

**评分标准**：
- 总分 ≥ 75% → **强烈推荐独立**
- 总分 60-74% → **推荐独立**
- 总分 45-59% → **视情况而定**
- 总分 < 45% → **推荐技能化**

## 七、评审结论

### 7.1 核心洞察

> **项目独立性不是越多越好，而是要在"复用价值"和"维护成本"之间找到平衡点。**

| 原则 | 说明 |
|------|------|
| **高复用 + 高复杂度** → 独立 | 如 dev-git-hub, dev-task-scheduler |
