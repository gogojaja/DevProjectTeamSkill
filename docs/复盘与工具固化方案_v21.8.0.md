## 3. 根因分析（Orient）

- **DEV-001**（工具缺失）：已有 `github_ip_refresh.py`（刷新/探测）与 `check_github_connectivity.py`（诊断），但**无「刷新→探测→绑定 IP push」的一键动作**；`mirror_push.py` 对 origin 失败只置冷却，不尝试 IP 回退。→ 缺固定工具动作。
- **DEV-002**（流程缺失）：AGENTS.md 已写"启动三查"要求，但未工具化、未纳入会话启动必经步骤；`mirror_push.py --verify` 存在但未被强制调用。
- **DEV-003**（标准落地不足）：`check_version_consistency.py` 已存在，但发版前未强制先行（solidify 门禁是否覆盖待核）。
- **DEV-004**（配置漂移）：项目级配置写死 `uv`，未按本机 `py -3.11` 校准。
- **DEV-005**（并发写入）：32 台账无最大编号锁，双端各自追加产生重复编号。

## 4. 改进提案（Decide）

### P-001（高优）GitHub 真实 IP 推送固定化 —— 新增 `tools/github_push.py`
- **问题**：DEV-001。GitHub push 反复手动绑定 IP。
- **改进方案**：新增跨平台脚本 `tools/github_push.py`，一键完成：
  1. 解除本地代理污染（可选 `--keep-proxy`）；
  2. 从 `docs/github_ip_records.csv` 读取候选 IP；
  3. 对 `github.com:443` 做**可达性 + TLS 证书合法（SNI=github.com）双重探测**（探测函数从 `github_ip_refresh.py` **抽取为公共模块 `tools/_gh_ip_probe.py`** 供两脚本 import，避免复制双维护）；
  4. 自动尝试 `git -c http.curloptResolve=github.com:443:<IP> push origin <branch>`；
  5. 首个可用 IP 推送成功后输出 `PUSH_OK <IP>` 并退出 0；全部失败输出诊断并退出 1；
  6. 留痕到 `台账/32_镜像同步记录.csv`（remote=origin，脱敏 URL，status 含所用 IP）；
  7. **`--dry-run` 模式**：仅探测并打印将使用的 IP，不实际 push（供回归测试，不改远端）。
- **配套**：
  - `mirror_push.py` 增加 `--github-realip` 参数，双推时若 origin 普通推送失败自动调用真实 IP 回退；**推送成功后清除 origin 的冷却/阻断状态**（熔断状态机兼容）。
  - **IP 探测超时**：单 IP connect+握手 ≤ 8s，命中首个可用 IP 即短路（不串行探测全部）。
- **收益**：GitHub push 从"10 分钟手动流程"降为"一条命令"；减少误判与人工绑定错误。
- **成本**：低（抽取公共探测模块 + 新增 1 脚本 + mirror_push 参数）。
- **风险**：低（仅 push 动作封装，不改凭据/不改远端/默认不写 hosts）。
- **验收**：① 正向：真实推送输出 `PUSH_OK`；② 负向：制造全 IP 不可达（`--dry-run` 下指向死 IP）输出正确诊断并退出 1；③ `--dry-run` 不下发远端变更；④ TLS 证书非法 IP 被跳过不用于推送。

### P-002（高优）启动即双端同步检查 —— 新增 `tools/sync_check.py`（或 `mirror_push.py --check`）
- **问题**：DEV-002。分叉发现滞后。
- **改进方案**：**增强 `mirror_push.py --verify` 语义**（fetch origin+mirror → 对比本地 HEAD 与两端领先/落后 → 输出差异；有分叉即醒目提示并退出非 0，阻止直接 push），避免另起脚本；AGENTS.md 命令区登记为**会话启动必经步骤**（与"废弃资产三查"并列）。
- **收益**：分叉 0 距离发现，杜绝"误以为最新"。
- **成本**：低；**风险**：低。
- **验收**：制造落后场景（`--verify` 对落后本地检出"落后 N 提交"并退出非 0）。

### P-003（中优）版本一致性强制先行
- **问题**：DEV-003。
- **改进方案**：核实 `check_version_consistency.py` 是否已纳入 solidify 硬门禁；若未纳入则加入第 4 门禁前置检查。发版流程文档写明"先跑 check_version_consistency → 再 solidify"。
- **收益**：版本声明永不漂移。
- **成本**：低；**风险**：低。

### P-004（中优）MCP 配置环境对齐（本机校准）
- **问题**：DEV-004。
- **改进方案**：项目级 `opencode.json` 的 MCP command 由 `uv run ...` 改为 `py -3.11 tools/mcp_server.py`（与本机一致）；文档记录全局 MCP 配置方法 + **重启生效**注意项。
- **收益**：项目级 MCP 开箱即用。
- **成本**：低；**风险**：低（仅配置+文档）。

### P-005（低优）32 台账编号幂等
- **问题**：DEV-005。
- **改进方案**：台账追加前先读最大编号（`SYNC-NNN`）取 max+1，写前再校验；`mirror_push.py`/`github_push.py` 统一走该逻辑。
- **收益**：并发/多端追加不再冲突。
- **成本**：低；**风险**：低。
