# 项目群整体规划方案 v3.0（优化方案）

> **版本**：v3.0  
> **日期**：2026-09-01  
> **状态**：评审通过（SIGNED_OFF）  
> **适用范围**：DevProjectTeamSkill 管理的全部项目  
> **核心原则**：平衡复用价值与维护成本，渐进式演进

---

## 一、优化背景

### 1.1 优化动因
- v1.0 方案创建7个新项目，资源需求过高
- v2.0 方案全部技能化，可能违背架构原则
- 需要平衡"复用价值"与"维护成本"

### 1.2 评估方法
- **八维度评估**：单一职责/独立部署/跨项目复用/团队归属/领域复杂度/依赖隔离/资源隔离/故障隔离
- **全量评估**：已独立4个项目 + 提议7个项目，共11个基础设施项目
- **第三方评审**：架构师/产品经理/运维专家多视角验证

---

## 五、模型策略

### 5.1 混合模型策略

| 任务类型 | 推荐模型 | 成本 | 实现方式 |
|----------|----------|------|----------|
| S0 简单任务 | 本机 qwen2.5:7b | 免费 | 直接调用Ollama API |
| S1 常规任务 | 本机 qwen2.5-coder:7b | 免费 | 直接调用Ollama API |
| S2 复杂任务 | Qwen-Plus | ¥0.8/M input | 直连阿里云百炼 |
| S3 高危任务 | Qwen-Max | ¥2.5/M input | 直连阿里云百炼 |

### 5.2 成本控制策略

| 策略 | 实施方式 | 预期节省 |
|------|----------|----------|
| 免费额度最大化 | 利用百炼500万免费Token（90天） | 100%（前90天） |
| 本地模型优先 | S0/S1任务强制使用本机模型 | 100%（日常任务） |
| 按需付费 | S2/S3任务才使用云端模型 | 80%+（相比全云端） |
| Batch调用 | 离线任务使用Batch API（5折） | 50%（批量任务） |
| 上下文缓存 | 重复System Prompt享受折扣 | 30-50%（对话任务） |

## 六、风险评估与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 技能库膨胀 | 维护困难 | 严格遵循技能边界，避免功能重叠 |
| 本地模型能力不足 | 复杂任务质量下降 | 保留Qwen-Max作为后备，按需切换 |
| 直连API稳定性 | 服务中断 | 多提供商配置，自动降级到本地模型 |
| 成本超预算 | 财务压力 | 设置月度消费上限，超限自动告警 |
| 项目独立延迟 | 进度受阻 | 先技能化快速交付，后渐进分离 |
