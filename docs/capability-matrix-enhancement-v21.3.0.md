# DevProjectTeamSkill v21.3.0 改造方案：模型选型 + 阶段复盘收割 + 环境配置抽取 + 账号密钥隔离

> 目标：围绕「高复用、低成本、可验证」四项增强需求，结合行业最佳实践，对技能库做增量改造。
> 本文为**方案文档**，仅定义标准与改造清单，经确认后按 skill-authoring 五步流程逐项落地并固化。
> 涉及模块：编排器（dev-project-team-skill）、总控（role-governance）、开发/测试/投产三个角色包、公共标准（references + shared 副本）、台账映射、仓库安全策略。

## 2. 需求1：阶段开始大模型选型

> 对标业界「模型路由 / 模型分级」（如素 LiteLLM Router、OpenRouter auto-routing）。

### 2.1 选型规则（四级优先）

1. **优先级 1（免费）**：同能力下优先选择免费模型；
2. **优先级 2（价格便宜）**：免费不可用或能力不足时，选价格最低模型；
3. **优先级 3（国内可稳定访问）**：免费/低价均不可行时，选**国内可稳定访问**的优质模型；
4. **排他**：国外无法访问（被墙/不可达）的模型一律排除。

### 2.2 评估维度

| 维度 | 说明 |
|------|------|
| 可访问性 | 中国大陆网络可达 / 可稳定调用（排他硬条件） |
| 成本 | 免费 > 低价 > 按量计费，结合用量估算总成本 |
| 能力匹配 | 按任务类型分级（简单/常规/复杂）匹配模型档位 |
| 稳定性 | API 可用性、限流、上下文窗口 |
| 数据合规 | 敏感数据不得发送至境外不可信服务 |

### 2.3 落地

- 新增公共标准 `references/model_selection.md`（含模型目录 + 规则 + 模板；shared 副本同步）；
- 新增编排器 action `select_model`，**每个阶段开始时执行**；
- 产出台账 `21_模型选型.csv`（阶段/任务类型/候选模型/成本档/可访问性/决策/理由）。

## 3. 需求2：阶段末复盘与交接收割

> **对标业界 Retro → Actionable Backlog + 内部开发者平台（IDP）复用资产**。

### 3.1 新增 action `retrospect_harvest`（阶段末强制）

在每个阶段结束的评审/门禁之后、交接之前强制执行，输出 `02_阶段复盘.csv`，字段：
- 做得好 / 需改进 / 行动项（继承 PDCA）；
- **可固化到 SKILL.md 的流程**（提炼成角色包/SKILL 环节）；
- **可形成可复用小工具的环节**（脚本/命令/模板）；
- **降 token 措施**（减少大模型重复调用的步骤，提升本地处理）。

### 3.2 新增台账 `03_复用资产.csv`

登记全部可复用工具（本地脚本/命令/模板）：名称/用途/触发/保存路径/复用率评估。目标：**提高复用率、减少大模型反复调用、降低 token 消耗、增强本地处理能力**。

### 3.3 交接强制化

`handover_export` 在阶段末强制产出「可固化流程 + 可复用工具」两通道清单，与 evolution lessons 打通（`shared/evolution.md` 只读自省接入）。

## 4. 需求3：开发/测试/生产环境配置抽取

> **对标 Config as Code + 环境矩阵 + 12-Factor 外部化配置**。

### 4.1 新增公共标准 `references/environment_standard.md`

- 环境定义：dev / test / prod 三套环境矩阵；
- 配置项清单（N 类）：连接串、版本、开关、依赖、部署目标等；
- 安全检查点：密钥引用、内网/公网边界、防火墙开通。

### 4.2 新增台账 `20_环境配置.csv`

- 一行一配置项，`dev/test/prod` 三列并排，含 URL/版本/开关/归属角色；
- **密钥只存引用不存明文**（见需求 5）；
- 供一键配置、检查、确认。

### 4.3 角色改造

- 开发 `prepare_env`（`strategy.md`）、测试 `prepare_env`（`preparation.md`）、部署 `planning.md` 统一写入 `20_环境配置.csv`；
- 总控 `check_gate` 增加「环境核对」检查项。

## 6. 需求5：账号/密钥安全隔离

> **对标 OWASP Secrets Management / gitleaks / trufflehog / HashiCorp Vault 最佳实践**。

### 6.1 决策结论

**仅用「单文档 + .gitignore 排除」为弱方案（防误提交层级），建议采用「分层隔离」**，避免明文密钥入库与误提交泄露。

| 层级 | 手段 | 说明 |
|------|------|------|
| ① 不入 VCS | `.gitignore` 排除 `secrets/**`、`*.env`、`*.pem`、`*.key` | 防止误提交 |
| ② 强制拦截 | pre-commit 钩子（`gitleaks` 或轻量 rg）扫描密钥 | 提交即拦截，防漏防泄 |
| ③ 存储介质 | 本地凭据管理器 / 加密 `.env`（不落仓库）/ DPAPI | 优于明文落盘 |
| ④ 结构隔离 | 库内只留 `secrets-example`（占位符），真实密钥本地生成 | 仓库无真实值 |
| ⑤ 轮换审计 | 泄露即轮换；`git log` 审计历史 | 兜底 |

### 6.2 落地清单

1. `.gitignore` 追加密钥/凭证排除规则；
2. 新增 `security/secrets-example/`（占位符模板，入库）；
3. 本地密钥文档置于 `.secrets/`（git ignore），引用方式；用工具本机凭据管理器/加密 `.env`；
4. pre-commit 脚本扫描密钥（防误提交）；
5. 全库巡检确认当前无明文密钥入库。

## 7. 改造范围与优先级

| 序号 | 项 | 优先级 | 涉及 |
|------|-----|--------|------|
| R3 | 环境配置抽取 + 台账 | 高（最易先做） | references + 开发/测试/布置包 + governance |
| R5 | 密钥隔离 + .gitignore | 高（安全） | 仓库根 + security 模板 |
| R2 | 复盘收割 + 复用资产 | 中 | governance + 编排器 §5 |
| R1 | 模型选型 | 中 | 编排器 + model_selection 标准 |
| R4 | 本地测试工具 | 低（单独立项） | 远期 |

> 建议实施顺序：R5 → R3 → R2 → R1（先安全隔离，后配置抽取，再复盘复用，最后模型选型）。每项完成后 `tools/solidify.sh "<项说明>"` 固化 + git 提交。
