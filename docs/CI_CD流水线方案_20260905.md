## 二、改进方案

### 2.1 新增工作流：`ci-skill-gate.yml`

> 技能库专项 CI 流水线，与现有 `nightly-quality-gate.yml`（跨项目质量门禁）互补。

**触发条件**：
- `push` → main 分支
- `pull_request` → main 分支
- `schedule` → 每周日 19:00 UTC（周一凌晨 03:00 CST，全量巡检）
- `workflow_dispatch` → 手动触发

**Job 设计（3 个 Job，渐进式）**：

```
┌─────────────────────────────────────────────────────┐
│  Job 1: syntax-test                                  │
│  ├─ Python 语法编译（tools/*.py 全部 py_compile）      │
│  └─ 单元测试（pytest tests/）                          │
├─────────────────────────────────────────────────────┤
│  Job 2: skill-gate（依赖 Job 1）                      │
│  ├─ [硬门禁] 版本一致性                                │
│  ├─ [硬门禁] 闭环执行                                  │
│  ├─ [硬门禁] 发布级                                    │
│  ├─ [硬门禁] 废弃清理                                  │
│  ├─ [硬门禁] MCP Server                               │
│  ├─ [软门禁] 插件链路                                  │
│  ├─ [硬门禁] 技能引用可达性                              │
│  └─ [硬门禁] 仓库卫生（lint_repo）                       │
├─────────────────────────────────────────────────────┤
│  Job 3: package-verify（依赖 Job 1，仅 schedule/手动）  │
│  ├─ 打包全部角色包（package_skills.py）                  │
│  ├─ 脱敏扫描（desensitize --scan）                      │
│  └─ 产出物上传（GitHub Artifacts）                       │
└─────────────────────────────────────────────────────┘
```

**分层策略**：

| 路径 | 触发 | 运行 Job | 预期时间 |
|------|------|----------|----------|
| PR 快速验证 | pull_request | Job 1 + Job 2 | ~2 min |
| 主分支全量 | push main | Job 1 + Job 2 | ~2 min |
| 夜间/手动巡检 | schedule / dispatch | Job 1 + Job 2 + Job 3 | ~5 min |

### 2.2 门禁结果回写

- PR 提交时：门禁结果通过 GitHub Checks API 回写到 PR（`checks: write` 权限）
- 硬门禁失败 → PR 显示 ❌（建议阻止合并）
- 软门禁失败 → PR 显示 ⚠ warning（不阻止）

### 2.3 与现有工作流关系

```
ci-skill-gate.yml（新增）
  └─ 技能库自身结构/门禁验证（本仓库）

nightly-quality-gate.yml（已有）
  └─ 跨项目 registry 质量门禁（外部项目）

nightly-code-complete.yml（已有）
  └─ AI 代码补全（draft PR 模式）
```

三者互补，不重叠。

### 2.4 不纳入 CI 的项

| 项 | 原因 |
|----|------|
| `check_github_connectivity.py` | CI runner 网络环境与本机不同，连通性检查结果不可靠 |
| `solidify.py` 完整流程 | 包含快照/打包/部署，CI 仅需验证门禁，不需实际部署 |
| `publish_production.py` | 生产发布为本地操作（全局库写入），不适合 CI 远程执行 |

## 三、风险评估

| 风险 | 等级 | 缓解 |
|------|:----:|------|
| CI runner 缺少项目依赖（如 mcp 包） | 低 | 门禁工具均为静态分析，不导入第三方模块 |
| CI 运行时间过长 | 低 | 分层策略：PR 仅跑 Job 1+2（~2min） |
| 门禁误报阻断 PR | 中 | 软门禁仅 warning 不阻断；硬门禁可 `--no-verify` 应急 |
| schedule 消耗 GitHub Actions 配额 | 低 | 仅每周一次全量巡检 |

## 四、工作量估算

| 任务 | 工作量 |
|------|:------:|
| 编写 `ci-skill-gate.yml` | 30 min |

| 推送后 GitHub Actions 实际验证 | 10 min |
| 调试修复（如有） | 15 min |
| **合计** | **~1.5 h** |
