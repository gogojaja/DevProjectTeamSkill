## 一、使用指南

### 1.1 角色包加载流程

**触发规则**：用户表达触发词 → 编排器读取 `SKILL_INDEX.md` → 加载对应角色包

| 角色包 | 触发词示例 | 加载时机 |
|--------|-----------|----------|
| role-project-init | 启动项目/立项/章程 | 项目启动阶段 |
| role-requirements-analysis | 需求/SRS/规格 | 需求分析阶段 |
| role-architecture | 架构/ADR/评审 | 架构设计阶段 |
| role-development | 开发/编码/PR | 开发实施阶段 |
| role-testing | 测试/用例/缺陷 | 测试验证阶段 |
| role-deployment | 投产/发布/回滚 | 投产发布阶段 |
| role-governance | 台账/评审/门禁 | 全程管控 |
| role-program-mgmt | 项目群/多项目协同 | 多项目协调 |

**加载顺序**：编排器 → 阶段角色 → 总控保障（role-governance 强制保留）

### 1.2 阶段流转规范

```
启动 → 需求 → 架构 → 开发 → 测试 → 投产 → 收尾
  ↓      ↓      ↓      ↓      ↓      ↓
 init   req   arch   dev   test  deploy
```

**流转门禁**：
- 需求 → 架构：SRS 评审通过 + 追溯矩阵建立
- 架构 → 开发：ADR 决策完成 + 4+1 视图就绪
- 开发 → 测试：代码评审通过 + 单测覆盖率达标
- 测试 → 投产：测试报告通过 + 缺陷清零（或遗留风险已评估）
- 投产 → 收尾：Go-Live 评审通过 + 运维交接完成

**敏捷迭代**：每个阶段可裁剪（`init_tailor`），但第 0 阶段（启动）与总控保障强制保留。

### 1.3 台账管理要求

**核心台账**（必须维护）：
- `13_安全审计台账.csv`：关键操作留痕（四维定位：主机/客户端/模型/时间）
- `14_授权登记.csv`：项目外目录访问授权（会话级有效期）
- `22_阶段复盘.csv`：阶段末复盘记录（good/improve/action）
- `23_复用资产台账.csv`：可跨项目复用的方案/代码/模板
- `30_项目群主进度.csv`：里程碑/实际日期/偏差/SPI

**管理原则**：
1. **单一信源**：同一信息只在一处维护，他处引用不复制
2. **脱敏入库**：B 级信息（主机名/IP/路径）提交前必须脱敏
3. **连续维护**：禁止事后突击补表，阶段流转前强制运行追溯检查
4. **CSV 优先**：>4K token 或 >20 列 → CSV（UTF-8 with BOM），禁止 .xlsx

## 三、经验教训总结

### 3.1 技术层面

1. **版本一致性门禁**
   - **问题**：SKILL.md 元数据版本与页脚版本不一致，固化被拦截
   - **解决**：修复页脚版本，统一元数据/页脚
   - **教训**：修改版本时必须同步更新元数据和页脚两处

2. **单一信源原则**
   - **问题**：free-api-hub 选型能力与本库 model-selection 重复
   - **解决**：free-api-hub 只保留模型清单，选型能力统一在 model-selection
   - **教训**：同一信息只在一处维护，避免冗余和冲突

3. **薄封装代理模式**
   - **问题**：本仓库内嵌独立项目实现导致膨胀
   - **解决**：经 `tools/*_proxy.py` 薄封装调用，注入 `PROJECT_ROOT`
   - **教训**：方法论在技能库，工具实现在独立项目，保持单一职责

### 3.2 流程层面

1. **执行合同闸门**
   - **问题**：AI 助手可能擅作主张执行副作用操作
   - **解决**：六段合同（理解→拆解→清单→确认→执行→复验），确认词白名单
   - **教训**：Tier2/Tier3 操作必须输出清单并取得确认词，参数哈希绑定

2. **固化频次控制**
   - **问题**：同质小改动反复固化提交，形成碎片化循环
   - **解决**：合并同质改动，一次性固化提交
   - **教训**：避免 1-2 文件的小改动完整闭环，攒批处理

3. **台账连续维护**
   - **问题**：事后突击补表，追溯矩阵断链
   - **解决**：阶段流转前强制运行 `check_traceability.py`
   - **教训**：台账必须随任务进展实时更新，禁止事后补录

### 3.3 协作层面

1. **模型分级策略**
   - **问题**：全部任务用强档模型，成本过高
   - **解决**：S0/S1 本地 7B，S2 Qwen3.7-Plus，S3 Qwen3.8-Max
   - **教训**：按任务复杂度选择模型，本地优先，云端按需

2. **远端仓库管理**
   - **问题**：新项目骨架已建，但远端仓库未创建
   - **解决**：需用户网页创建或授权 `gh repo create`
   - **教训**：本地骨架 + 远端仓库应同步完成，避免遗留

3. **交接文档刷新**
   - **问题**：交接文档版本/阶段/下一步动作未及时更新
   - **解决**：固化时自动刷新交接文档断点区
   - **教训**：交接文档是跨会话上下文恢复的关键，必须保持最新
