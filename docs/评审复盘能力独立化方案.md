## ✅ 可稳定达成效果

### 1. 判断结论：评审/复盘方法论已完备，应「工具化封装」而非「新建技能」

| 能力 | 现有载体 | 成熟度 | 缺口 |
|------|----------|--------|------|
| 评审（代码/文档/方案） | `multi-perspective-validation`（五视角并行）+ `best-practice-solution`（决策水线） | ★★★★ 方法完备 | **无独立 CLI**，靠会话指令，无法被CI/门禁自动调用 |
| 复盘 | `self-improve`（OODA 闭环）+ `lesson-harvesting`（经验沉淀）+ `retrospect_harvest` action | ★★★★ 方法完备 | **行动项→验证→关闭无自动回环**；`retrospect_harvest` 为手工 action |
| 复盘沉淀层 | `22_阶段复盘.csv` + `skill-lessons-learned/01~06 六层 CSV` | ★★★ 数据已结构化 | **缺「复用命中统计」与「验证状态回填」** |

> **证据**：EV-101[high]（MPV 五视角+聚合矩阵）、EV-102[high]（BPS 四段水线+落盘门禁）、EV-103[high]（self-improve OODA）、EV-104[high]（22/23 台账+6层经验库）

### 2. 独立化方向：工具化（tools/）+ 保留子技能编排语义

- **工具**：CLI 封装可执行化（落盘 CSV / 台账 / 经验库），供 CI / pre-commit / 固化门禁自动调用
- **技能**：保留子技能编排语义（人机交互、视角裁决、方法论指导），不重复新建顶层技能
- **分工**：工具=「执行/落盘/校验」｜技能=「方法论/编排/决策」

> **证据**：EV-107[medium]（CMMI/SPICE 复用率高流程提升为能力域）、EV-101~104[high]（方法论已存在，缺的是可执行化）

### 3. 四工具落地（A/B/C/D 分阶段）

| # | 工具 | 对应能力 | 阶段 | 核心行为 |
|---|------|----------|------|----------|
| A | `tools/mpv_cli.py` | 评审五视角 | **P1（推荐先落）** | `--target` + `--perspectives` → 产出评审 CSV 落盘 docs/reviews/ + 复用 check_review_artifacts 链路 |
| B | `tools/retro_cli.py` | 复盘收割 | P2 | `--stage` + `--reflection` → 写 22/23 台账 + 提取行动项(owner/deadline) + 登记 lessons |
| C | `tools/check_retro_closure.py` | 行动项回环 | P2 | 固化时检查前复盘行动项是否关闭，未关闭列待办 |
| D | `tools/improve_cli.py` | self-improve 独立形态 | P3 | `--diagnose/--propose/--experiment` 复用核心循环（复用率达标才启用） |

### 4. 行业实践对齐（复盘闭环）

- **DORA**：复盘是「验证改进进度」的关键步骤；用自动化工具代替纯对话复盘
- **Atlassian**：复盘 5 步（基调→反馈→洞察→行动项→总结）；行动项必须 **owner+deadline**；复盘须进任务系统产生跟进闭环

> **证据**：EV-105[high]（DORA 官方）、EV-106[medium]（Atlassian Team Playbook）

## ⚠️ 理论最优效果与当前限制

| 限制/反信号 | 说明 | 缓解 |
|-------------|------|------|
| 评审工具化需选型（半自动 vs 全自动） | MPV 是 LLM 会话流程，脚本只能做「落盘/校验」半自动，视角判定仍需 LLM | 脚本负责结构化 I/O + 落盘 + 脱敏；视角内容由会话/模型产出 |
| 复盘自动化需统一数据契约 | 22/23 台账与 lessons CSV 字段未唯一化 | 以现有 22 台账「行动项」列 + lessons「验证状态」列为契约锚点，脚本兼容 |
| 过度工具化风险（EV-108） | DORA「不要为度量而度量」；工具化后无人调用/仅刷分则无增值 | 反信号：2 阶段内调用 <3 次 → 收缩回纯子技能 |
| 人类判断不可替代 | 复盘洞察与行动项提炼需人工（Atlassian） | 工具只做汇总/落盘/跟踪，不替代 LLM 决策与人类判断 |

## 决策记录草案

- **标识**：ADR-2026-08-29-001（已预置于 `架构资产/01_架构策略/ADR-2026-08-29-001.md`，待架构角色正式编号）
- **决策**：评审/复盘能力**工具化封装为 tools/ 脚本**（A/B/C/D），不新建顶层技能；方法论仍在子技能单源
- **选项**：
  - A. 新建独立顶层技能 → ❌ 结构冲突/方法论重复
  - B. **工具化封装（本方案）** → ✅ 低投入/可自动复用/单源
  - C. 全自动化无需人工 → ❌ 人类判断不可替代
  - D. 维持现状仅内嵌 → ⚠️ 能力价值未释放
- **理由**：EV-101~104 方法论已完备、缺可执行化；EV-105/106 行业要求复盘自动闭环；EV-107 复用率达标应提升为能力域（工具化）
- **已验证**：check_review_artifacts.py（落盘门禁）、22 台账行动项列、lessons 验证状态列、desensitize.py 脱敏链路均现成
- **不确定**：工具化后真实调用率；`mpv_cli.py` 半自动接口需实测
- **未关闭风险**：过度工具化（反信号收缩）、复盘行动项关闭率
- **反信号**：2 阶段内调用 <3 次 → 收缩回纯子技能；若行动项关闭率 <50% 无上升 → 需人工介入机制
