# 项目群整体规划方案 v2.0（颠覆性重评）

> **版本**：v2.0  
> **日期**：2026-09-01  
> **状态**：评审中  
> **适用范围**：DevProjectTeamSkill 管理的全部项目  
> **核心原则**：最小可行架构 + 渐进增强 + 资源优化

---

## 一、重新评估背景

### 1.1 触发原因
- 原方案创建7个新基础设施项目，可能过度工程化
- Mac mini M2 16GB内存资源紧张，需优化资源使用
- free-api-hub定位与配置存在矛盾
- 行业最佳实践强调最小可行架构

### 1.2 评估方法
- **FULL档位评审**：系统级影响 + 生产变更 + 长期锁定
- **三视角验证**：架构一致性 / 安全合规 / 成本演进性
- **颠覆性思维**：不介意推翻原方案，只要更合理

---

## 二、新架构设计

### 2.1 核心理念：技能驱动而非项目驱动

| 维度 | 原方案（v1.0） | 新方案（v2.0） |
|------|---------------|---------------|
| **架构模式** | 项目分离（14个项目） | 技能集成（1核心+4基础设施） |
| **复杂度** | 高（多项目协调） | 低（单一技能库） |
| **资源消耗** | 高（每个项目独立维护） | 低（共享技能库） |
| **维护成本** | 高（7个新项目） | 低（扩展现有技能） |
| **启动速度** | 慢（需创建多个项目） | 快（直接扩展技能） |

### 2.2 项目群架构（简化版）

```
DevProjectTeamSkill (核心技能库) ← 主要工作区
├── TwinForge (主项目) — 双机 AI 开发工作站
├── dev-git-hub (基础设施) — Git 基建（已移交）
├── dev-task-scheduler (基础设施) — 定时任务调度（已移交）
├── dev-model-router (基础设施) — 模型路由编排（待移交）
└── free-api-hub (基础设施) — 模型清单管理（已清理）
```

**关键变化**：
- ❌ 移除7个新基础设施项目（dev-project-mgmt等）
- ✅ 在DevProjectTeamSkill中通过技能扩展实现相同功能
- ✅ 保持现有4个基础设施项目的薄封装代理调用模式

### 2.3 功能实现策略

| 功能需求 | 实现方式 | 优势 |
|----------|----------|------|
| 项目管理 | 扩展role-project-mgmt技能 | 复用现有项目管理框架 |
| 文档管理 | 扩展role-governance技能 | 复用现有台账和文档管理 |
| 环境管理 | 扩展worktree-isolation技能 | 复用现有环境隔离能力 |
| 测试工具 | 扩展role-testing技能 | 复用现有测试框架 |
| 部署工具 | 扩展role-deployment技能 | 复用现有部署流程 |
| 安全审计 | 扩展role-governance技能 | 复用现有审计框架 |
| 知识库 | 扩展project-memory技能 | 复用现有记忆层 |

## 三、模型策略优化

### 3.1 free-api-hub 功能边界澄清

**职责**（✅ 允许）：
- 维护可用模型清单
- 提供商余额/费用/优惠信息  
- 保证使用最低价最适合的模型

**禁止**（❌ 不允许）：
- 模型路由
- 请求聚合  
- 流量转发

**配置清理**：
- 删除`routing`、`aliases`、`schedule`配置段
- 保留`cost_per_mtok`、`capabilities`、`tags`等清单信息

### 3.2 混合模型策略（优化版）

| 任务类型 | 推荐模型 | 成本 | 实现方式 |
|----------|----------|------|----------|
| S0 简单任务 | 本机 qwen2.5:7b | 免费 | 直接调用Ollama API |
| S1 常规任务 | 本机 qwen2.5-coder:7b | 免费 | 直接调用Ollama API |
| S2 复杂任务 | Qwen-Max | ¥2.5/M input | 直连阿里云百炼 |
| S3 高危任务 | Qwen-Max | ¥2.5/M input | 直连阿里云百炼 |

**关键优化**：
- ❌ 移除free-api-hub中间层（避免额外复杂度）
- ✅ 直连各提供商API（减少依赖，提高稳定性）
- ✅ 利用免费额度（新用户500万Token/90天）

### 3.3 成本控制策略

| 策略 | 实施方式 | 预期节省 |
|------|----------|----------|
| 免费额度最大化 | 立即开通百炼，领取500万免费Token | 100%（前90天） |
| 本地模型优先 | S0/S1任务强制使用本机模型 | 100%（日常任务） |
| 按需付费 | S2/S3任务才使用Qwen-Max | 80%+（相比全云端） |
| Batch调用 | 离线任务使用Batch API（5折） | 50%（批量任务） |
| 上下文缓存 | 重复System Prompt享受折扣 | 30-50%（对话任务） |

## 五、风险评估与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 技能库膨胀 | 维护困难 | 严格遵循技能边界，避免功能重叠 |
| 本地模型能力不足 | 复杂任务质量下降 | 保留Qwen-Max作为后备，按需切换 |
| 直连API稳定性 | 服务中断 | 多提供商配置，自动降级到本地模型 |
| 成本超预算 | 财务压力 | 设置月度消费上限，超限自动告警 |
