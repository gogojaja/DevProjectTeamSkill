## 提案 P-003 — 打断-修正-重规划-沉淀默认闭环

- **问题**：诉求 #7「可随时打断并修正执行方向」成熟度仅 3.5/5，是距 L5 唯一剩余缺口。打断所需零件**全部已存在但未串成默认闭环**：
  - `goal_check.py` 已实现 `amend_goal(goal_id,new_sgd,reason)` + `amendment_history` + CLI `--amend --amend-reason`（目标变更留痕）；
  - SGD 持久化台账 `台账/41_活跃目标.json`（铁律 #13）；
  - `dependency-graph.md` §4 增量更新（`incremental_update` 仅重算受影响子图）+ §6 角色绑定表（P1a）；
  - `deviation-detection.md` §5.1 `FeedbackIngestion`（用户反馈"错了/绕过/太慢"→Deviation）+ §4 偏差台账；
  - `lesson-harvesting.md` §2 复盘卡片 / §4 失败教训库 / §5 经验→技能库反哺注入；
  - `interaction-harvest.md`（P1b 确认清单模板）+ `create_memory` MCP。
- **根因**（5-Why）：§2.4.5 协调官闭环只在"衔接铁律"里一句话提及"用户可随时打断，经 SGD amend 重规划（P2 深化）"，**无结构化的打断入口→修正→重规划→捕获→沉淀默认路径**；各零件分散在 goal_check/dependency-graph/deviation-detection/lesson-harvesting，无统一编排。
- **改进方案**（按引用串联，零新建工具/机制）：编排器 §2.4 新增 **§2.4.6 打断-修正-重规划-沉淀闭环**，定义五步默认路径（① pause 暂停 Executor 冻结在制品 → ② amend `goal_check.py --amend` 写 amendment_history+更新 41_活跃目标.json → ③ replan `dependency-graph` §4 增量重建受影响子图 + §6 绑定表重新指派 → ④ detect `deviation-detection` §5.1 解析 Deviation 登记偏差台账 → ⑤ harvest `lesson-harvesting` §2/§4/§5 + `interaction-harvest` + `create_memory` 沉淀反哺），闭环出口（修正生效回 Executor / 目标不可达升级用户 / 偏差未 resolve 不得交付）。
- **预期收益**：诉求 #7 从 3.5→4.5；整体成熟度 **L4.7→L5.0（收官）**；打断从"人工干预"变"默认闭环且自动沉淀教训"，修正方向可留痕、可重规划、可复用。
- **成本**：低（编排器新增 1 小节 + 版本号；无新角色、无新工具、无新 domain——全部按引用绑定现有机制）。
- **风险**：低。加法式异常路径，不改正常执行流；amend 留痕禁止静默改方向（铁律 #13）；偏差未 resolve 不得交付（衔接 §2.4.5 Verifier 门禁）。
- **评估方式**：① 6 门禁全绿；② 引用的 6 个锚点（goal_check amend / 41_活跃目标.json / dependency-graph §4+§6 / deviation-detection §5.1+§4 / lesson-harvesting §2/§4/§5 / interaction-harvest）逐一核实真实存在；③ tabletop dry-run：打断样例走五步闭环；④ 四目录部署 grep。
- **回退方案**：删除 §2.4.6 小节 + 版本回退，`git revert` 单提交即回。
- **优先级**：P2（收官 L5）。
- **后续**：L5 达成后转入"观察-微调"期，按实际任务运行反馈做 self-improve 小步迭代，不再大改。
