## 一、机器定位与分工

### 1.1 核心原则

> 内存密集型归 Mac，交互密集型归Dell。两台机器各司其职，互补短板。
### 1.2 Mac mini M2 16GB —AI 推理服务器
**定位**：专攻AI 推理，不做办公、不开浏览器、不跑重型IDE，把内存留给模型。
| 资源 | 配置 |
|------|------|
| CPU | 8 核M2 |
| GPU | 10 核|
| 内存 | 16GB 统一内存（100 GB/s 带宽）|
| 存储 | 256GB NVMe |

**核心职责**：
- 本地 LLM 推理（Ollama 运行 7B/14B 模型）
- MCP 服务主部署节点（配置同步源）
- 向量数据库+ Embedding 服务
- 模型实验与性能评测

**不做什么**：
- ❌日常办公（浏览器/文档/通讯）
- ❌重型 IDE 开发（占内存影响模型）
- ❌文件下载/媒体处理

### 1.3 Dell OptiPlex 7010 Micro —开发工作站

**定位**：主力开发环境+ 云端 AI 客户端+ Windows 测试环境。
| 资源 | 配置 |
|------|------|
| CPU | i3-12100T 4 核8 线程 |
| GPU | UHD 730 集显 |
| 内存 | 16GB DDR4 3200 |
| 存储 | 256GB NVMe |

**核心职责**：
- 主力开发（TRAE CN / VSCode / Git 工具链）
- 云端 AI 调用（Claude/GPT/DeepSeek）
- Windows 测试（ps1 脚本、兼容性验证）
- 资源消费端（浏览文档、查资料，不占 Mac 内存）
**不做什么**：
- ❌本地大模型推理（CPU 太慢）
- ❌MCP 服务管理（配置从 Mac 同步）
- ❌长时间高负载计算

## 四、双机协作机制
### 4.1 三种协作模式

**模式一：Dell 开发+ Mac 提供本地模型（最常用）**

```
Dell (TRAE CN)  ──调用 Ollama API──▶ Mac (Ollama + 14B Coder)
     ▲                                   │
     └──── 流式响应 (SSE) ◀────────────────┘
```

开发时在 Dell 的IDE 中直接调用Mac 的本地模型，延迟仅5ms，近似本机体验。
**模式二：Mac 实验 + Dell 分析（模型评测时）**

```
Mac 跑模型评测脚本 → 生成性能数据 → push 到 Git
                                          │
                                          ▼
                                Dell pull 数据 → 分析对比 → 生成报告和图表
```

Mac 负责算力密集的模型测试，Dell 负责数据分析和文档输出。
**模式三：混合推理（本地小模型 + 云端大模型）**

- 简单任务→本地 7B（快速、免费）
- 中等任务 →DeepSeek（低价、高质量）
- 复杂任务 →Claude 3.5（最高质量）

详见第六章 API 策略。
### 4.2 文件同步策略

> 核心原则：Git 同步代码 + SMB 共享工作目录 + 密钥手动分发

**代码项目 →Git 同步**
- 所有代码项目通过 Git + GitHub/Gitee 同步
- 两台机器各自 clone，push/pull 同步
- 适用：技能库、Python/JS 项目、配置文件
**工作目录 →SMB 共享 + rsync**
- Mac 共享 `~/ai-workspace/` 目录
- Dell 挂载为网络驱动器，可直接读写
- 适用：正在开发中的项目、数据集、临时文件
- 解决"切机器就得commit push pull"的痛点
> 使用建议：主力开发在 Dell 上做，需要跑模型时把文件拷到 Mac（或直接用SMB 路径）。
> 完成后 push 到Git。日常频繁切换场景下用SMB 共享目录减少摩擦。
**模型文件 →单边存储**
- 模型文件（GGUF 等）只在 Mac 上存储和管理
- Dell 不需要本地模型副本，通过 API 调用
- 避免大文件同步和重复占用空间

**密钥配置 →手动分发**
- API Key、密码等敏感信息不通过 Git 或SMB 同步
- Mac 用钥匙串，Dell 用凭据管理器
- 新增密钥时手动在两台机器上各加一次
### 4.3 故障转移与降级
| 故障场景 | 影响 | 降级方案 | 恢复操作 |
|---------|------|---------|---------|
| Mac 关机/掉线 | 本地模型不可用| Dell 切换到云端API（免费→付费）| 重启 Mac，Tailscale 自动重连 |
| Mac 内存不足 OOM | 模型推理中断 | 自动降级到更小模型或云端 | 重启 Ollama，清理内存|
| Ollama 服务挂了 | 本地模型不可用| 切换云端 API | 重启 Ollama 服务 |
| Tailscale 断连 | 双机无法通信 | Dell 全用云端 API，Mac 独立运行 | 重启 Tailscale 或重登录 |
| MCP 服务崩溃 | 对应工具不可用| 不影响模型推理，其他 MCP 正常 | 进程管理器自动重启|
| Dell 故障 | 开发中断| 用Mac 自带 VSCode + 向日葵临时开发| 修复 Dell |
| 云端 API 不可用| 大模型能力受影响| 全部切换到本地Ollama 模型 | 等API 恢复或切备用 API |

> **高可用设计**：双机架构天然具备故障隔离——任何一台故障，另一台仍可独立工作。
> 本地模型与云端API 互为备份，确保AI 能力不中断。

## 五、MCP 架构

### 5.1 设计原则（v1.1 修订）
> **每机独立运行，配置集中管理。**
>
> MCP 服务在两台机器上各跑一份，保证各自都能独立工作。
> 配置文件从Mac 为主节点，通过 Git 同步到Dell，避免重复维护。
**为什么不搞SSE 跨机调用（降为备选）**：
- MCP SSE 传输的客户端支持不统一，兼容性有风险
- 跨机调用增加网络依赖和故障点
- MCP 服务本身资源消耗不大（Node.js 进程），两台各跑一份不浪费
- 简单可靠 > 优雅复杂

SSE 跨机调用作为 **Phase 3 可选优化项**，验证可行后再考虑切换。

4. 密钥不入库，各自用系统钥匙串管理

### 5.5 备选方案：SSE 跨机调用（Phase 3 验证）

- Mac 运行 MCP SSE 服务端
- Dell 客户端通过 Tailscale IP + SSE 协议连接
- 减少 Dell 上的 MCP 进程数量
- 前提：客户端支持 SSE 传输 + 性能满足要求

当前阶段**不实施**，Phase 3 做POC 验证后决定是否采纳。

## 六、API 策略

### 6.1 三级 API 架构

> 从免费到付费逐级提升，按任务难度选择合适的模型，既控成本又保质量。
```
任务请求
   ▼
┌──────────────────────────────────┐
│           任务难度评估            │
└──────────────────────────────────┘
   │
   ├─ 简单常规 ────────────▶ L1 本地免费
   │                          Qwen2.5-Coder 7B/14B
   │                          ¥0
   │
   ├─ 中等/专业 ───────────▶ L1.5 免费 API（free-api-hub）
   │                          多个免费模型，零成本
   │                          稳定性一般，作为过渡层
   │
   ├─ 搞不定 / 不稳定 ─────▶ L2 低价付费
   │                          DeepSeek-V3 / 通义千问 72B
   │                          ¥30-50/月，日常主力
   │
   └─ 复杂/创新 ───────────▶ L3 高端付费
                              Claude 3.5 Sonnet / GPT-4o
                              ¥50/月，仅关键任务
```

### 6.2 各级 API 明细

**L1：本地免费模型（Mac Ollama）**

| 模型 | 量化 | 内存占用 | M2 速度 | 适用场景 |
|------|------|---------|---------|---------|
| qwen2.5-coder:7b | Q4_K_M | ~5 GB | ~25 tok/s | 代码补全、简单重构|
| qwen2.5-coder:14b | Q4_K_M | ~8.4 GB | ~8.5 tok/s | 复杂编码、Bug 修复 |
| nomic-embed-text | —| ~270 MB | 快速| Embedding、RAG |

- 优势：零成本、隐私安全、无网络依赖
- 局限：能力上限不如云端大模型
**L1.5：免费 API（free-api-hub）**

- 来源：你已有的free-api-hub 项目
- 成本：¥0
- 定位：本地模型不够用时的第一跳，能省则省
- 风险：稳定性一般、可能限流、数据隐私不确定
- 降级：不稳定时自动切到L2 付费 API

**L2：低价付费 API（日常主力）**

| API | 代表模型 | 输入价格 | 输出价格 | 月预算| 备注 |
|-----|---------|---------|---------|--------|------|
| DeepSeek | DeepSeek-V3 | ¥0.5/百万 token | ¥1/百万 token | ¥20-50 | 编码能力强，性价比极高|
| 通义千问 | Qwen2.5-72B | ¥0.3/百万 token | ¥0.6/百万 token | ¥10-20 | 国内访问快，阿里云|
| 字节豆包 | Doubao-Pro | 免费额度 | 免费额度 | ¥0-10 | 新用户大量免费额度|

月预算：约 ¥30-70（日均20 万输入+ 5 万输出估算）

**L3：高端付费 API（关键任务）**

| API | 模型 | 输入价格 | 输出价格 | 月预算（少量）| 适用场景 |

## 八、Mac 服务分级启动策略

### 8.1 为什么需要分级
Mac 只有 16GB 统一内存，如果所有服务同时跑必 OOM。
| 服务/进程 | 内存占用 |
|-----------|---------|
| macOS  | ~4 GB |
| 14B 模型 (Q4) | ~8.4 GB |
| ChromaDB + Embedding 模型 | ~1-2 GB |
| 2-3 个 MCP 服务 (Node.js) | ~500 MB-1 GB |
| Docker Desktop | ~1-2 GB |
| Open WebUI | ~500 MB |
| **合计** | **~15-16 GB（顶到天花板）** |

**解决方案：分级启动，默认不把内存占满。**

### 8.2 服务分级定义

**Level 1：最小模式（默认）**
- 运行：Ollama + 7B 模型 + 核心 MCP 服务
- 内存占用：~8-9 GB
- 剩余内存：~7 GB
- 适用场景：日常编码、简单补全
- 启动命令：`./scripts/start-minimal.sh`

**Level 2：标准模式**
- 运行：Ollama + 14B 模型 + 核心 MCP 服务
- 内存占用：~12-13 GB
- 剩余内存：~3-4 GB
- 适用场景：复杂编码、Bug 修复
- 启动命令：`./scripts/start-standard.sh`

**Level 3：全功能模式**
- 运行：Ollama + 14B + ChromaDB + 全部 MCP + Open WebUI
- 内存占用：~15-16 GB（接近满载）
- 剩余内存：几乎没有
- 适用场景：RAG 实验、模型评测、重度使用
- 注意：不建议长时间维持，用完切回标准模式
- 启动命令：`./scripts/start-full.sh`

### 8.3 切换策略

```
日常默认 → Level 1（7B，省内存，响应快）
    ├─ 写复杂代码 → Level 2（14B）
    ├─ 做 RAG 实验 → Level 3（全开，用完切回）
    └─ Mac 内存告警 → 自动降级到 Level 1
         ─         └─ Mac 内存告警 →自动降级到Level 1
```

### 8.4 实现方式

- 用shell 脚本管理服务启停
- 配合 launchd / pm2 做进程管理
- 设置内存监控脚本，超过阈值自动告警或降级
- Dell 端通过 SSH 执行切换命令

## 九、安全架构
### 9.1 威胁模型

| 风险 | 等级 | 概率 | 影响 | 缓解措施 |
|------|------|------|------|---------|
| API Key 泄露 | 高| 低| 高| 密钥入钥匙串 + Git 钩子扫描 |
| Ollama 暴露公网 | 高| 低| 高| 仅绑 Tailscale IP + API Key |
| Mac 内存 OOM | 高| 中| 高| 分级启动 + 云端降级 |
| MCP 文件系统越权 | 中| 低| 中| 严格配置 allowed-dirs |
| Tailscale 账号被盗 | 中| 低| 中| 2FA + ACL 限制 |
| 免费 API 不稳定| 低| 高| 低| 多源轮询 + 付费降级 |
| 本地模型越狱 | 低| 低| 低| 权限最小化 + 人工确认 |
| 代码数据泄露到云端| 低| 中| 低| 敏感代码用本地模型|

### 9.2 密钥管理

**Mac：iCloud 钥匙串**
- API Key 存入 macOS 钥匙串
- MCP 服务通过 `security find-generic-password` 读取
- Touch ID 生物识别保护

**Dell：Windows 凭据管理器**
- API Key 存入 Windows Credential Manager
- Python 通过 `keyring` 库读取
- 与 Windows 账户绑定，BitLocker 加密保护

**绝对禁止**：
- ❌在 Git 仓库中提交明文 API Key
- ❌在配置文件中硬编码密钥
- ❌通过聊天软件明文传输密钥
- ❌写入未加密的文本文件

### 9.3 网络安全

| 措施 | 实施方式 | 保护对象 |
|------|---------|---------|
| Tailscale 端到端加密| WireGuard + AES-256 | 双机所有通信 |
| 服务仅绑定内网IP | Ollama/MCP 绑100.x.x.x | 不暴露公网|
| Ollama API Key | OLLAMA_API_KEY 环境变量 | 二次认证 |
| Tailscale ACL | 配置访问控制列表 | 限制横向移动 |
| SSH Key 认证 | ed25519 密钥，禁用密码| 远程管理安全 |
| Tailscale 2FA | 账号双因素认证| 账号安全 |

### 9.4 审计与监控
- **API 用量监控**：每月检查各 API 费用，设置消费告警
- **MCP 操作日志**：开启debug 日志，记录工具调用
- **Git 密钥扫描**：预提交钩子扫描，防止误提交
- **内存监控**：Mac 内存使用率告警，超阈值自动降级
