# 技能独立部署升级方案

> **版本**：v1.0（基线定稿）　**日期**：2026-09-08　**状态**：已评审基线化（CONDITIONAL → 决策锁定 D1/D2/D3）
> **对齐**：PMBOK 6（十大知识领域）· PMBOK 7（八绩效域）· IEEE 828 · PRINCE2 · 单一信源铁律
> **方法论**：plan-creation 8 步生命周期（复杂方案，Step 1-8 全执行）
> **范围**：A 阶段（5 子技能提升顶层独立）+ B 阶段（2 新独立技能，EVM/RAID 内化），共 **8 项 STANDALONE_SKILLS**

## 第 0 章 决策锁定记录（评审定夺）

| # | 决策点 | **锁定结果** | 依据 |
|---|--------|-------------|------|
| D1 | A 阶段 5 子技能形态 | **全部提升为顶层独立技能**（`.trae/skills/{name}/`） | 与 scope-tracking 同构，真正可独立打包 |
| D2 | B 阶段 EVM/RAID 单一信源 | **本地新建权威工具**（`tools/evm_ops.py`/`raid_ops.py`），技能库为新权威，dev-project-mgmt 保留兼容 | 用户内化授权 + 消除现状不一致（4 PMO 已是本地 `*_ops.py`，唯 EVM/RAID 委派） |
| D3 | plan-creation 形态 | **一并提升顶层**（纯文档独立技能，无 bundle_tools） | 统一 STANDALONE_SKILLS 语义 |

> **最终 STANDALONE_SKILLS（8 项）**：`scope-tracking`（既有）+ `portfolio-mgmt` `okr-strategy` `resource-ops` `stakeholder-comms` `plan-creation`（A）+ `schedule-cost` `risk-mgmt`（B）。

## 第 1 章 可行性摘要（Step 1）

- **技术可行性 ✅**：A 阶段 4 PMO 权威工具（`*_ops.py`）已存在；B 阶段内化新建 `evm_ops.py`/`raid_ops.py`（吸收 dev-project-mgmt 逻辑）；scope-tracking 已验证注入模式与 STANDALONE 机制。
- **经济可行性 ✅**：A 以文档重构+目录迁移为主；B 新建 2 工具+2 技能+2 测试，工时可控。
- **操作可行性 ⚠️ 中**：目录迁移改编排器路由（回归风险），以 git stash 隔离 + 三门禁 + 打包部署自包含验证兜底。
- **结论：GO**（决策已锁定，无附条件）。

## 第 2 章 背景与目标

### 2.1 背景（现状证据）
- 范围管理已树标杆：`scope-tracking` v1.2.0 顶层独立可部署，三门禁全绿。
- 4 PMO 子技能集成不完整：无 frontmatter、版本 `> 版本: v1.0`（两段非标）、未注册 SKILL_INDEX、不在 SUB_SKILLS 门禁。
- `plan-creation` 同类缺陷（无 frontmatter、版本两段）。
- 进度/成本/风险无独立技能：内嵌 `role-governance/domain/progress-cost.md`、`risk.md`。
- **架构不一致**：`portfolio_ops/okr_ops/resource_ops/comms_ops` 为本地 `tools/` 脚本（MCP `_run_tool`）；而 `evm_analyze/raid_mgmt/progress_report` 委派 dev-project-mgmt CLI（`_run_mgmt_cli`）。
- 打包/部署不对等：`deploy` copytree 含编排器 `skills/`；`package` 的 `pack_role` 不复制 `skills/`。

### 2.2 目标
1. A：5 子技能提升顶层 + 补 frontmatter/版本/闭环/manifest/注册/门禁 → 可独立部署。
2. B：新建 `schedule-cost`/`risk-mgmt`，EVM/RAID 内化为本地权威工具 → 自包含独立部署。
3. 架构一致：8 项 STANDALONE_SKILLS 统一，消除本地/委派不一致。
4. 零回归：11 角色包 + 9 合规子技能 + scope-tracking 行为不变。

## 第 4 章 方案设计（决策完整）

### 4.1 A 阶段：5 子技能提升顶层独立

**A1 目录迁移**：`dev-project-team-skill/skills/{portfolio-mgmt,okr-strategy,resource-ops,stakeholder-comms,plan-creation}/` → `.trae/skills/{同名}/`（用 `git mv` 保留历史；连带各自 domain/ 若有）。

**A2 SKILL.md 合规化**（每个技能）：
- 顶部补 YAML frontmatter：`name: "{目录名}"` + `description: "{触发语义，中文，含触发词}"`
- 版本重构：`> 版本: v1.0` → 元数据行 `**技能版本**：v1.0.0` + 页脚 `**文档版本**：v1.0.0`
- 补「闭环执行系统」6 章节（任务入口/执行状态/验收门禁/失败处理/产出与交接/审计记录）

**A3 skill.manifest.json**（每个技能）：

| 技能 | bundle_tools | bundle_tests | entrypoint | 说明 |
|------|-------------|-------------|-----------|------|
| portfolio-mgmt | `portfolio_ops.py` | `test_portfolio_ops.py`(新建) | `tools/portfolio_ops.py` | 有权威工具 |
| okr-strategy | `okr_ops.py` | `test_okr_ops.py`(新建) | `tools/okr_ops.py` | 有权威工具 |
| resource-ops | `resource_ops.py` | `test_resource_ops.py`(新建) | `tools/resource_ops.py` | 有权威工具 |
| stakeholder-comms | `comms_ops.py` | `test_comms_ops.py`(新建) | `tools/comms_ops.py` | 有权威工具 |
| plan-creation | `[]` | `[]` | 无（纯文档） | `self_contained:true`，domain 3 文件随包 |

**A4 编排器路由更新**：`dev-project-team-skill/SKILL.md` 第127-128、212-215行路由 `./skills/{name}/` → 顶层 `{name}/`；子技能明细表标注"独立可部署技能"。

**A5 注册与门禁**：SKILL_INDEX 条目 24~28；package/deploy/deploy.sh 的 STANDALONE_SKILLS 扩展；check_version_consistency 新增 STANDALONE_SKILLS 校验遍历。

### 4.2 B 阶段：2 新独立技能 + EVM/RAID 内化

**B1 内化权威工具（D2 核心）**：

- **`tools/evm_ops.py`**（新建，吸收 dev-project-mgmt `evm_calculator.py` 逻辑）：
  - CLI：`calc`（PV/EV/AC/SPI/CPI/SV/CV）/ `status` / `add-milestone`（对齐 MCP `evm_analyze` 的 action）
  - 数据源：台账 `03_进度基准.csv`/`04_成本基准.csv`/`09_进度跟踪台账.csv`/`10_成本消耗台账.csv`
- **`tools/raid_ops.py`**（新建，吸收 dev-project-mgmt `raid_manager.py` + 本地 `risk_scan` 逻辑）：
  - CLI：`list`/`add`/`update`/`close`（RAID 四维，对齐 MCP `raid_mgmt`）+ `scan`（概率×影响，对齐 `risk_scan`）
  - 数据源：台账 `12_风险问题台账.csv`
- **MCP 改本地调用**：`skills_mcp_server.py` 的 `evm_analyze`→`_run_tool("evm_ops.py")`、`raid_mgmt`→`_run_tool("raid_ops.py")`、`risk_scan`→`_run_tool("raid_ops.py","scan")`（与 `portfolio_ops` 模式统一，去除 `_run_mgmt_cli` 委派）。
- **dev-project-mgmt 处理**：保留为兼容/底层库（不强制退役）；技能库 `evm_ops.py`/`raid_ops.py` 为 DevProjectTeamSkill 侧**新权威**；在其 README/交接注明"EVM/RAID 已内化至 DevProjectTeamSkill，本库保留供其他项目/CLI 兼容"。

**B2 新建技能包**：
- `.trae/skills/schedule-cost/`：SKILL.md（frontmatter+版本+闭环）+ domain（baseline/milestone-evm/review）+ references/evm_standard.md + skill.manifest.json（bundle_tools=[evm_ops.py]，bundle_tests=[test_evm_ops.py]）
- `.trae/skills/risk-mgmt/`：SKILL.md + domain（register-init/scan/response/coordination）+ references/raid_standard.md + skill.manifest.json（bundle_tools=[raid_ops.py]，bundle_tests=[test_raid_ops.py]）

**B3 瘦引用委派**：`role-governance/domain/progress-cost.md`、`risk.md` 保留触发壳，逻辑指向 `schedule-cost`/`risk-mgmt`（单一信源）；`references/api_contracts.md` 补委派契约。

**B4 测试**：新建 `tools/tests/test_evm_ops.py`、`test_raid_ops.py`（EVM 指标/RAID 增删改查/scan 分级）。

**B5 注册**：SKILL_INDEX 条目 29~30；STANDALONE_SKILLS 含 schedule-cost/risk-mgmt。

### 4.3 工具层改造

| 工具 | 改造 | 零回归 |

| `deploy_skills.py` | STANDALONE_SKILLS→8 项；inject_bundled 不变（本地 tools 注入） | 空参回退已含 STANDALONE |
