# ADR-2026-08-28-001：交接机制重构——三层文档结构+显式Token预算+三模式Handoff+摘要生成器+预压缩管道

**状态**：Accepted（架构角色 2026-08-29 正式接受）  
**日期**：2026-08-28（接受日 2026-08-29）  
**决策者**：架构角色（role-architecture）  
**关联决策记录**：docs/handoff_optimization_solution.md §决策记录草案  

---

## 背景
DevProjectTeamSkill 技能库在小模型/受限上下文窗口下频繁触发上下文压缩，导致交接信息丢失、跨会话连续性断裂。现有 `交接文档.md` 结构扁平、`token_standard.md` 无显式交接预算、压缩策略单一、无结构化摘要生成、无预压缩管道。

## 决策
实施以下六大支柱：
1. **三层交接文档结构**：L1 必读核心(~800tok必读) / L2 标准上下文(~2.5k按需) / L3 完整归档(全量)
2. **显式 Token 预算分配**：`token_standard.md §7` 新增交接预算——交接必读 10%/工作执行 75%/压缩缓冲 15%，L1 永不压缩
3. **三模式 Handoff 策略**：`handoff-struct`(默认/小模型) / `handoff-full` / `handoff-snap`，按模型能力自动/显式切换
4. **结构化摘要生成器**：`tools/handoff_summarizer.py` 接入 `solidify.sh` 固化流程，辅助模型复用 `qwen2.5-coder:7b`
5. **预压缩优化管道**：工具输出剪枝 → **敏感数据脱敏(强制 `desensitize.py --dictionary`)** → 语义去重(复用 `qwen2.5-coder:7b` mean-pooling embedding，向量仅内存不落盘) → 边界对齐保护
6. **性能基准与回归门禁**：`.performance.yml handoff段` + 基准指标表（摘要生成<500ms、语义去重<200ms、内存≤1.5GB、回归阈值 10%）

## 选项对比
| 选项 | 描述 | 评价 |
|------|------|------|
| A | 仅优化压缩阈值 | 低投入/低收益/不解决根因 |
| **B** | **三层结构+显式预算+三策略+摘要生成器+预压缩管道+性能门禁** | **中投入/高收益/解决根因（本决策）** |
| C | 全技能拆分为微技能+按需加载 | 高投入/高收益/风险大/耦合核心架构（列为 P3 可选） |
| D | 完全依赖大模型/扩大上下文窗口 | 不解决成本/受限环境问题 |

## 理由
- EV-001/002/003 证据链支撑分层预算+多策略+结构化摘要
- EV-007 定位当前痛点（扁平交接文档对小模型不友好）
- P1 独立可交付不依赖 P3
- CR-001~004 已全部在方案中闭环

## 不确定项
- 小模型摘要质量阈值需实测校准（fallback：纯规则摘要+人工断点维护）
- 语义去重 embedding 质量实测（复用 qwen2.5-coder:7b mean-pooling）

## 反信号
- 若实测小模型摘要质量不可用(关键信息丢失>10%) → 回退纯规则摘要+人工断点
- 若语义去重 embedding 内存超 1.5GB → 降级纯规则去重
