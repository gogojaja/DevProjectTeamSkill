# ADR-004：指数退避重试 + 死信队列策略

## 状态

Accepted（已采纳）

## 上下文

任务执行失败是常态——网络波动、依赖服务不可用、临时资源不足等都可能导致任务失败。需要合理的重试策略来自动恢复临时故障，同时避免无限重试造成系统雪崩。

候选重试策略：
- 方案A：固定延迟重试
- 方案B：指数退避重试
- 方案C：指数退避 + 抖动（Jitter）
- 方案D：分层重试（临时错误重试，业务错误不重试）

死信队列策略：
- 有死信队列 vs 无死信队列

## 决策

**采用指数退避 + 抖动 + 最大重试次数 + 死信队列的组合策略。**

同时区分临时错误和业务错误：临时错误进入重试，业务错误直接进入死信。

## 理由

### 为什么是指数退避

1. **避免重试风暴**：如果大量任务同时失败同时重试，会对依赖服务造成更大压力（雪崩效应）
2. **符合故障规律**：大多数临时故障（网络抖动、服务重启）在几秒到几分钟内恢复，指数退避能在早期快速重试，后期逐渐拉长间隔
3. **行业标准**：AWS、Google Cloud、Sidekiq、Celery 等主流系统都采用指数退避

### 为什么要加抖动（Jitter）

1. **避免惊群效应**：如果所有任务都用完全相同的退避时间，它们会在同一时间点重试，造成流量尖峰
2. 加随机抖动后，重试时间均匀分布，平滑流量

### 为什么需要死信队列

1. **隔离不可恢复任务**：有些失败是永久性的（代码 bug、数据错误、权限问题），重试多少次都不会成功
2. **避免资源浪费**：无限重试浪费 CPU、内存、网络资源
3. **便于人工处理**：死信队列集中存放失败任务，便于排查和手动重放
4. **保护系统稳定**：防止失败任务反复重试拖垮整个系统

### 为什么区分临时错误和业务错误

1. **提高效率**：业务错误（参数错误、数据不存在、权限不足）重试没有意义
2. **快速反馈**：业务错误应该立即标记失败，而不是等多次重试后才通知用户

## 重试策略参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_retries | 3 | 最大重试次数 |
| base_delay | 60 秒 | 初始延迟时间 |
| max_delay | 3600 秒 | 最大延迟时间（上限） |
| jitter | 30 秒 | 随机抖动范围 |
| backoff_factor | 2 | 指数因子 |

### 重试延迟计算公式

```
delay = min(base_delay * (backoff_factor ^ retry_count), max_delay) + random(0, jitter)
```

### 重试次数与延迟示例

| 重试次数 | 基础延迟 | 最大延迟（含抖动） |
|---------|---------|------------------|
| 第1次 | 60 秒 | 90 秒 |
| 第2次 | 120 秒 | 150 秒 |
| 第3次 | 240 秒 | 270 秒 |

## 错误分类

### 临时错误（可重试）
- 网络连接失败 / 超时
- 依赖服务 5xx 错误
- 数据库连接失败 / 死锁
- 资源暂时不可用
- 限流 / 429 错误

### 业务错误（不可重试）
- 参数错误 / 400 错误
- 认证失败 / 401 错误
- 权限不足 / 403 错误
- 数据不存在 / 404 错误
- 业务逻辑错误
- 代码 bug

任务可以通过返回 `skip_retry=True` 来标记为业务错误，跳过重试直接进入死信。

## 死信队列处理

1. 任务达到最大重试次数后，状态标记为 `dlq`
2. 触发死信告警（严重级别）
3. 人工排查原因，修复后可手动重试
4. 手动重试成功后，从死信队列移除

## 后果

### 正面
- 自动恢复临时故障，提高任务成功率
- 避免重试风暴，保护系统和依赖服务
- 死信队列隔离不可恢复任务，便于人工处理
- 区分错误类型，提高重试效率

### 负面
- 策略参数需要根据实际情况调优
- 死信队列需要人工处理流程
- 错误分类需要业务代码配合标记

## 替代方案

| 方案 | 拒绝原因 |
|------|---------|
| 固定延迟重试 | 容易造成重试风暴，恢复效率低 |
| 无限重试 | 资源浪费，可能导致系统雪崩 |
| 无死信队列 | 不可恢复任务反复重试，污染主队列 |
| 所有失败都重试 | 业务错误无意义重试，浪费资源 |

## 备注

- 重试策略可按任务单独配置
- 死信队列支持手动重试和批量重试
- 死信任务保留 30 天，过期自动清理
