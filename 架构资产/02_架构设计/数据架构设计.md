# 数据架构设计

> 版本：v1.0.0　日期：2026-08-21　参考：DAMA-DMBOK · ISO/IEC 25010

---

## 1. 数据架构概述

### 1.1 设计原则

1. **分层存储**：热数据（任务状态）SQLite，冷数据（执行历史）CSV
2. **读写分离**：状态数据读写频繁用 SQLite，历史数据追加写入用 CSV
3. **数据可追溯**：所有执行操作留痕，支持审计追溯
4. **数据一致性**：事务保证状态数据一致性，幂等键保证执行不重复
5. **兼容现有格式**：CSV 台账与现有台账格式一致（UTF-8 BOM）

### 1.2 数据分类

| 数据类别 | 存储介质 | 保留周期 | 敏感度 | 说明 |
|---------|---------|---------|--------|------|
| 任务定义数据 | SQLite | 永久 | C 级 | 任务配置、触发器、执行参数 |
| 任务状态数据 | SQLite | 90 天 | C 级 | 运行状态、下次执行时间、锁信息 |
| 执行记录数据 | CSV | 永久 | C 级 | 执行历史、结果、耗时、错误信息 |
| 幂等键数据 | SQLite | 90 天 | C 级 | 幂等去重键值 |
| 调度器状态数据 | SQLite | 永久 | C 级 | 心跳、健康状态 |
| 日志数据 | 日志文件 | 30 天 | B 级 | 结构化日志、可能含路径等敏感信息 |

## 3. 数据字典

### 3.1 jobs 表（任务定义表）

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | - | 任务ID |
| name | VARCHAR(255) | UNIQUE NOT NULL | - | 任务名称（唯一标识） |
| description | TEXT | - | '' | 任务描述 |
| trigger_type | VARCHAR(20) | NOT NULL | 'cron' | 触发器类型：cron/interval/date |
| trigger_config | TEXT | NOT NULL | '{}' | 触发器配置（JSON） |
| func_ref | VARCHAR(512) | NOT NULL | - | 函数引用：module:function |
| max_retries | INTEGER | NOT NULL | 3 | 最大重试次数 |
| timeout | INTEGER | NOT NULL | 300 | 超时时间（秒） |
| idempotency_key_expr | VARCHAR(255) | - | NULL | 幂等键表达式 |
| status | VARCHAR(20) | NOT NULL | 'active' | 状态：active/paused/disabled |
| next_run_time | DATETIME | - | NULL | 下次执行时间 |
| last_run_time | DATETIME | - | NULL | 上次执行时间 |
| created_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL | CURRENT_TIMESTAMP | 更新时间 |

**索引**：
- `idx_jobs_name` (name) UNIQUE
- `idx_jobs_status` (status)

## 5. 存储策略

### 5.1 SQLite 存储

- **路径**：`.secrets/scheduler.db`
- **模式**：WAL（Write-Ahead Logging）提升并发性能
- **备份**：每日备份到 `backups/scheduler/`
- **归档**：执行记录超过 90 天归档到 CSV 后删除

### 5.2 CSV 存储

- **路径**：`台账/31_定时任务执行记录.csv`
- **格式**：UTF-8 with BOM
- **写入方式**：追加写入（append-only）
- **归档策略**：每年归档一次，归档文件移至 `台账/archive/`

### 5.3 日志存储

- **路径**：`logs/scheduler/`
- **格式**：JSON Lines（每行一个 JSON 对象）
- **滚动策略**：按天滚动，保留 30 天
- **脱敏**：日志写入前进行敏感信息脱敏

## 6. 数据生命周期

### 6.1 数据流转

```
任务注册 → jobs 表 → 调度触发 → job_executions 表（running）
                                    ↓
                              执行完成 → 更新状态（success/failed）
                                    ↓
                              成功 → 写入 idempotency_keys 表
                                    ↓
                              异步同步 → CSV 执行记录
                                    ↓
                              90天后 → 归档到 CSV，清理 SQLite
```

### 6.2 保留周期

| 数据类型 | 在线保留 | 归档保留 | 总保留 |
|---------|---------|---------|--------|
| 任务定义 | 永久 | - | 永久 |
| 任务状态 | 90 天 | - | 90 天 |
| 执行记录（SQLite） | 90 天 | - | 90 天 |
| 执行记录（CSV） | 永久 | 每年归档 | 永久 |
| 幂等键 | 90 天 | - | 90 天 |
| 日志 | 30 天 | - | 30 天 |

### 6.3 数据销毁

- SQLite 数据：定期 `DELETE` + `VACUUM`
- CSV 数据：归档后保留，不主动销毁
- 日志文件：自动滚动删除

## 7. 数据一致性

### 7.1 事务边界

- 任务状态变更：单事务内完成状态更新 + 执行记录插入
- 幂等校验：单事务内完成检查 + 插入（利用唯一约束防并发）

### 7.2 最终一致性

- SQLite → CSV 同步：异步批量同步，允许短暂延迟
- 同步校验：每日对账，确保数据一致
