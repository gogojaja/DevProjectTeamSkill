## 1. 调度引擎组件

### 1.1 职责
负责任务调度的核心引擎，基于 APScheduler 封装，提供可靠的任务触发能力。

### 1.2 子组件

| 子组件 | 职责 | 关键实现 |
|--------|------|---------|
| SchedulerManager | 调度器生命周期管理 | 启动/停止/暂停/恢复、配置加载 |
| TriggerFactory | 触发器工厂 | cron/interval/date 三种触发器创建 |
| MisfireHandler | misfire 处理 | 错过触发的任务处理策略 |
| ConcurrencyController | 并发控制 | 最大并发数限制、队列堆积检测 |
| JobLocker | 任务锁 | 防止同一任务重复执行 |

### 1.3 关键配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| timezone | Asia/Shanghai | 调度时区 |
| misfire_grace_time | 3600 | 错过触发宽限时间（秒） |
| max_instances | 1 | 同一任务最大并发实例数 |
| coalesce | True | 多次 misfire 是否合并执行 |
| jobstore | sqlite | 任务持久化存储 |

## 2. 任务注册组件

### 2.1 职责
管理任务的定义、注册、加载和配置。

### 2.2 子组件

| 子组件 | 职责 | 关键实现 |
|--------|------|---------|
| TaskRegistry | 任务注册表 | 任务类的注册与查询 |
| TaskLoader | 任务加载器 | 从 Python 模块 / YAML 配置加载任务 |
| TaskValidator | 任务校验器 | 任务定义合法性校验 |
| ConfigParser | 配置解析器 | YAML / JSON 配置解析 |

### 2.3 注册方式

#### 方式一：装饰器注册
```python
from tools.scheduler import register_task

@register_task(
    name="daily_backup",
    trigger="cron",
    hour=2,
    minute=0,
    idempotency_key="date"
)
def daily_backup_task():
    """每日备份任务"""
    pass
```

#### 方式二：YAML 配置
```yaml
tasks:
  - name: daily_backup
    trigger: cron
    schedule: "0 2 * * *"
    module: tasks.backup
    function: daily_backup_task
    idempotency_key: date
    max_retries: 3
    timeout: 300
```

## 3. 执行框架组件

### 3.1 职责
任务执行的核心框架，提供状态机、重试、超时、死信等通用能力。

### 3.2 子组件

| 子组件 | 职责 | 关键实现 |
|--------|------|---------|
| TaskExecutor | 任务执行器 | 任务加载、执行、结果处理 |
| StateMachine | 状态机 | 任务状态流转控制 |
| RetryPolicy | 重试策略 | 指数退避、最大重试次数 |
| TimeoutController | 超时控制 | 任务执行超时强制终止 |
| DeadLetterQueue | 死信队列 | 失败任务隔离与管理 |

### 3.3 任务状态机

```
PENDING → SCHEDULED → RUNNING → SUCCESS
                          ↓
                        FAILED → RETRYING → RUNNING
                          ↓
                           DLQ
```

| 状态 | 说明 | 转移条件 |
|------|------|---------|
| PENDING | 待调度 | 任务注册后 |
| SCHEDULED | 已调度 | 加入调度队列 |
| RUNNING | 执行中 | 触发执行 |
| SUCCESS | 成功 | 执行成功 |
| FAILED | 失败 | 执行失败 |
| RETRYING | 重试中 | 失败后进入重试 |
| DLQ | 死信 | 重试次数用尽 |

### 3.4 重试策略

- **策略**：指数退避 + 抖动（Jitter）
- **公式**：`delay = base * 2^retry_count + random(0, jitter)`
- **默认配置**：
  - `max_retries`: 3
  - `base_delay`: 60 秒
  - `max_delay`: 3600 秒
  - `jitter`: 30 秒

## 4. 幂等校验组件

### 4.1 职责
确保任务重复执行不产生重复副作用。

### 4.2 子组件

| 子组件 | 职责 | 关键实现 |
|--------|------|---------|
| IdempotencyKeyGenerator | 幂等键生成器 | 根据任务配置生成唯一幂等键 |
| DedupChecker | 去重检查器 | 执行前检查幂等键是否已存在 |
| ExecutionRecorder | 执行记录器 | 执行成功后记录幂等键和结果 |

### 4.3 幂等键规则

| 键类型 | 格式 | 适用场景 |
|--------|------|---------|
| 按日期 | `{task_name}:{date}` | 每日一次的任务 |
| 按业务键 | `{task_name}:{business_key}` | 有业务唯一标识的任务 |
| 按运行ID | `{task_name}:{run_id}` | 每次运行唯一 |
| 自定义 | `{task_name}:{custom_expression}` | 自定义规则 |

### 4.4 校验流程

1. 执行前：检查幂等键是否存在成功记录 → 存在则跳过
2. 执行中：获取幂等锁，防止并发执行
3. 执行后：成功则记录幂等键，失败则不记录（可重试）

## 5. 状态存储组件

### 5.1 职责
基于 SQLite 的任务元数据持久化存储。

### 5.2 数据表

| 表名 | 职责 | 关键字段 |
|------|------|---------|
| jobs | 任务定义表 | id, name, trigger, func, next_run_time, status |
| job_executions | 执行记录表 | id, job_id, run_id, status, start_time, end_time, result |
| idempotency_keys | 幂等键表 | id, job_id, idempotency_key, status, created_at |
| scheduler_state | 调度器状态 | id, state, last_heartbeat |

### 5.3 性能优化

- 使用 WAL 模式提升并发读写性能
- 执行记录定期归档到 CSV
- 索引优化：job_id, status, next_run_time

## 6. 执行记录组件

### 6.1 职责
CSV 格式的执行历史记录，与现有台账格式一致。

### 6.2 记录格式

文件：`台账/31_定时任务执行记录.csv`

| 字段 | 类型 | 说明 |
|------|------|------|
| 执行编号 | string | 自增编号 |
| 任务名称 | string | 任务唯一标识 |
| 运行ID | string | 本次运行唯一ID |
| 触发方式 | string | schedule/manual/retry |
| 计划时间 | datetime | 计划执行时间 |
| 开始时间 | datetime | 实际开始时间 |
| 结束时间 | datetime | 实际结束时间 |
| 耗时(秒) | float | 执行耗时 |
| 状态 | string | success/failed/dlq/skipped |
| 重试次数 | int | 第几次重试 |
| 幂等键 | string | 幂等校验键 |
| 错误信息 | string | 失败时的错误信息 |
| 执行节点 | string | 执行主机标识 |

## 7. 告警通知组件

### 7.1 职责
任务异常和系统健康状态的告警通知。

### 7.2 告警类型

| 告警类型 | 触发条件 | 级别 |
|---------|---------|------|
| 任务失败告警 | 任务执行失败 | 警告 |
| 死信告警 | 任务进入死信队列 | 严重 |
| 堆积告警 | 待执行任务超过阈值 | 警告 |
| 健康告警 | 调度器心跳超时 | 严重 |
| 超时告警 | 任务执行超时 | 警告 |

### 7.3 通知渠道

- 系统通知（macOS Notification Center / Linux notify-send / Windows Toast）
- 日志输出（结构化日志）
- 执行记录标记
- 可选：邮件 / 飞书 / 企业微信（需配置）
