# 容器视图（C4 Level 2）

> 版本：v1.0.0　日期：2026-08-21

---

## 1. 概述

定时任务系统由 7 个核心容器组成，分为触发层、执行层、存储层、观测层四层架构。

## 2. 容器清单

| 容器 | 技术选型 | 职责 | 关键能力 |
|------|---------|------|---------|
| 调度引擎 | APScheduler 3.x | 核心调度 | cron/interval/date 触发器、misfire 处理、并发控制 |
| 任务注册表 | YAML + Python 装饰器 | 任务定义与注册 | 声明式注册、配置驱动、动态加载 |
| 执行框架 | Python 类框架 | 任务执行与控制 | 状态机、重试策略、超时控制、死信队列 |
| 幂等校验 | SQLite + 唯一约束 | 去重与幂等保障 | 幂等键生成、执行前去重、执行后记录 |
| 告警通知 | 系统通知 + 日志 | 异常告警 | 失败告警、堆积告警、健康告警 |
| 状态存储 | SQLite | 任务元数据持久化 | 任务定义、运行状态、锁信息 |
| 执行记录 | CSV (UTF-8 BOM) | 执行历史记录 | 执行明细、统计报表、审计追溯 |

## 3. 分层架构

### 3.1 触发层
- **调度引擎**：基于 APScheduler 的核心调度器，负责按触发器规则触发任务
- **任务注册表**：管理所有任务的定义、配置和注册信息

### 3.2 执行层
- **执行框架**：任务执行的核心框架，提供状态机、重试、超时等通用能力
- **幂等校验**：执行前后的幂等性检查，防止重复执行副作用

### 3.3 存储层
- **状态存储**：SQLite 数据库，存储任务元数据和运行状态
- **执行记录**：CSV 文件，存储执行历史，与现有台账格式一致

### 3.4 观测层
- **告警通知**：任务异常、堆积、健康状态的告警通知

## 4. 容器间交互

### 4.1 正常执行流程
1. 调度引擎从任务注册表加载任务定义
2. 调度引擎按触发器规则触发任务
3. 调度引擎调用执行框架执行任务
4. 执行框架调用幂等校验模块检查幂等键
5. 幂等校验通过后，执行业务逻辑
6. 执行结果更新到状态存储
7. 执行记录写入 CSV 台账
8. 执行失败时触发告警通知

### 4.2 崩溃恢复流程
1. 调度引擎启动时从状态存储加载任务状态
2. 检查 stalled job（运行中但无心跳的任务）
3. 根据配置决定重试或标记失败
4. 恢复正常调度循环

### 4.3 任务注册流程
1. 任务通过装饰器或 YAML 配置声明
2. 任务注册表加载并验证任务定义
3. 注册信息同步到状态存储
4. 调度引擎感知新任务并加入调度队列

## 5. 关键设计决策

### 5.1 调度引擎与执行框架同进程
- **理由**：简化架构，降低进程间通信复杂度
- **代价**：单进程故障影响所有任务
- **缓解**：进程守护 + 健康检查 + 快速恢复

### 5.2 SQLite 与 CSV 分层存储
- **理由**：SQLite 适合频繁更新的状态数据，CSV 适合审计追溯的历史数据
- **优势**：各司其职，性能与可读性兼顾

### 5.3 幂等校验作为框架强制能力
- **理由**：幂等性是可靠性的基础，必须强制保障
- **实现**：框架层自动校验，业务任务只需提供幂等键
