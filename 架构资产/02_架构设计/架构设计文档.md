## 1. 设计概述

### 1.1 设计目标

基于策略分析结论，设计一套轻量、可靠、可观测的定时任务机制，为 DevProjectTeamSkill 技能库提供统一的周期性任务调度能力。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 可靠性优先 | 任务不丢失、不重复、可恢复 |
| 幂等强制 | 框架层校验幂等键，业务任务必须实现幂等 |
| 状态可见 | 全生命周期状态追踪，执行记录完整 |
| 简单易用 | 新任务接入成本低，配置清晰 |
| 跨平台一致 | macOS / Linux / Windows 行为一致 |
| 低资源消耗 | 后台运行，CPU/内存占用可控 |

### 1.3 设计范围

- **包含**：任务注册、调度触发、执行框架、状态管理、幂等校验、重试机制、死信队列、执行记录、告警通知
- **不包含**：分布式多节点调度（当前为单机架构）、复杂 DAG 工作流、实时消息队列

## 2. 4+1 视图总览

### 2.1 逻辑视图

核心模块划分：
- **任务注册模块**：任务定义、触发器配置、幂等键规则
- **调度引擎模块**：APScheduler 封装、触发器管理、 misfire 处理
- **执行框架模块**：任务执行器、状态机、重试策略、超时控制
- **幂等校验模块**：幂等键生成、去重校验、执行记录
- **状态存储模块**：SQLite 任务元数据存储、CSV 执行记录
- **观测告警模块**：日志、统计、告警通知
- **集成适配模块**：TRAE Schedule 适配、技能库任务接入

### 2.2 进程视图

单进程架构：
- **主进程**：scheduler + executor 同进程运行
- **守护进程**：进程监控、自动重启、健康检查
- **任务进程**：独立子进程执行任务（可选，用于隔离）

## 4. 核心设计决策

### 4.1 调度引擎选择

**决策**：使用 APScheduler 作为核心调度引擎

**理由**：
- Python 生态最成熟的任务调度库
- 支持 cron/interval/date 三种触发器
- 支持 misfire 策略、并发控制、任务持久化
- 轻量、跨平台、零外部依赖（除 SQLite）

### 4.2 状态存储选择

**决策**：SQLite 存储任务元数据，CSV 存储执行记录

**理由**：
- SQLite：事务支持、查询能力强、零运维、适合元数据
- CSV：与现有台账格式一致、可读可审计、适合执行记录
- 分层存储：热数据（任务状态）SQLite，冷数据（执行历史）CSV

### 4.3 幂等设计

**决策**：框架层强制幂等键校验

**理由**：
- at-least-once 是分布式系统的常态，幂等是业务正确性的基础保障
- 框架层强制校验可避免业务代码遗漏幂等实现
- 幂等键 = {task_name + business_key + scheduled_time}

### 4.4 重试策略

**决策**：指数退避 + 最大重试次数 + 死信队列

**理由**：
- 指数退避避免重试风暴
- 最大重试次数防止无限重试
- 死信队列隔离不可恢复任务，便于人工处理

### 4.5 与 TRAE Schedule 的关系

**决策**：TRAE Schedule 作为用户入口，APScheduler 作为执行引擎

**理由**：
- TRAE Schedule 提供友好的用户交互和 cron 管理
- APScheduler 提供可靠的调度执行和任务管理
- 双层架构：用户通过 TRAE 管理，实际执行由 APScheduler 保障

## 5. 质量属性实现

### 5.1 可靠性实现

| 机制 | 实现方式 |
|------|---------|
| 任务持久化 | SQLite 存储任务定义和状态 |
| 崩溃恢复 | 启动时从 SQLite 恢复任务，检查 stalled job |
| misfire 处理 | APScheduler 内置 misfire_grace_time 配置 |
| 进程守护 | 外部 supervisor / launchd / Windows 服务 |
| 健康检查 | 心跳文件 + 健康检查接口 |

### 5.2 幂等性实现

| 机制 | 实现方式 |
|------|---------|
| 幂等键生成 | task_id + run_id + 业务键 |
| 执行前去重 | 执行前检查幂等键是否已成功执行 |
| 执行后记录 | 执行成功后记录幂等键和结果 |
| 并发控制 | SQLite 事务 + 唯一约束 |

### 5.3 可观测性实现

| 机制 | 实现方式 |
|------|---------|
| 结构化日志 | JSON 格式日志，包含 task_id/run_id/状态/耗时 |
| 执行记录 | CSV 执行记录台账，每次执行追加 |
| 统计报表 | 每日/每周任务执行统计 |
| 告警通知 | 失败告警、堆积告警、健康告警 |

### 5.4 可维护性实现

| 机制 | 实现方式 |
|------|---------|
| 任务注册 | 装饰器模式，@register_task 一键注册 |
| 配置驱动 | YAML 配置文件定义任务和触发器 |
| 统一接口 | 所有任务遵循统一的 Task 基类接口 |
| CLI 工具 | 命令行管理任务、查看状态、手动触发 |
